## 题目分析

本题要求判断一个给定的字符序列是否具有所谓的 “窗口性质” （$\texttt{Window Property}$）。窗口性质的定义如下：

对于任意正整数 $k$（窗口长度），当我们用长度为 $k$ 的窗口从左到右滑动扫描整个序列时，所得到的不同子串（模式）的个数不超过 $k + 1$。

换句话说，如果存在某个 $k$，使得长度为 $k$ 的不同子串数量大于 $k + 1$，则该序列不具有窗口性质。

### 示例解析

题目给出了几个例子：

- `ABAABABAB` 具有窗口性质。
- `ABCABCABC` 不具有窗口性质（当 $k = 1$ 时，不同字符有 $\texttt{A}$、$\texttt{B}$、$\texttt{C}$ 共 $3$ 个，而 $k + 1 = 2$，$3 > 2$）。
- `011010` 具有窗口性质。
- `0110100101` 不具有窗口性质。

对于 `011010`，题目列出了所有长度 $k = 1$ 到 $6$ 的不同子串，验证了每个 $k$ 下子串数量均不超过 $k + 1$。

### 关键概念：第一个违规符号

如果序列不具有窗口性质，我们需要找到 **第一个违规符号** （$\texttt{first offending symbol}$）。所谓第一个违规符号，是指在该符号加入之前的前缀序列具有窗口性质，而加入该符号后窗口性质被破坏。符号的位置从 $1$ 开始计数。

例如，$\texttt{011010}$ 具有窗口性质，但再添加一个 $\texttt{0}$ 变成 $\texttt{0110100}$ 后，长度为 $2$ 的子串中出现了 $\texttt{00}$，此时长度为 $2$ 的不同子串有：$\texttt{01}$、$\texttt{11}$、$\texttt{10}$、$\texttt{00}$，共 $4$ 个，而 $k + 1 = 3$，$4 > 3$，因此第 $7$ 个符号是第一个违规符号。

## 解题思路

### 朴素方法

最直接的方法是：对于输入序列，逐个字符地构建前缀，每添加一个新字符后，检查所有可能的窗口长度 $k$（从 $1$ 到当前前缀长度），判断是否满足窗口性质。

对于每个 $k$，需要收集当前前缀中所有长度为 $k$ 的子串，并统计不同子串的数量。一旦某个 $k$ 使得不同子串数量超过 $k + 1$，则当前前缀不满足窗口性质，该新添加的字符即为第一个违规符号。

### 算法优化

由于题目保证序列长度不超过 $100$，我们可以采用较为简单的实现方式：

1. 使用一个集合数组 $pattern[k]$ 来存储当前前缀中所有长度为 $k$ 的不同子串。
2. 每添加一个新字符（位置 $i$，从 $0$ 开始计数），对于每个 $k = 1$ 到 $i + 1$：
   - 提取以当前字符结尾的长度为 $k$ 的子串：$line.substr(i - k + 1, k)$。
   - 将该子串插入到 $pattern[k]$ 集合中。
   - 如果插入后 $pattern[k].size() > k + 1$，说明窗口性质被破坏，记录当前位置 $i + 1$（因为位置从 $1$ 开始）并退出。
3. 如果遍历完所有字符都没有违规，则输出 `YES`，否则输出 `NO:位置`。

### 复杂度分析

- 序列长度 $n \leq 100$。
- 对于每个新字符，需要检查最多 $n$ 个窗口长度。
- 每次提取子串和插入集合的操作时间复杂度约为 $O(k)$（子串长度）。
- 总体复杂度 $O(n^3)$，在 $n \leq 100$ 时完全可行（约 $10^6$ 量级操作）。

## 代码实现

```cpp
// The Windows Property
// UVa ID: 261
// Verdict: Accepted
// Submission Date: 2016-05-26
// UVa Run Time: 0.010s
//
// 版权所有（C）2016，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

int main() {
    cin.tie(0); cout.sync_with_stdio(false);
    // 预分配足够大的集合数组，用于存储不同长度的子串模式
    // 序列最长 100，因此窗口长度最大为 100，这里分配 1100 是冗余的
    vector<set<string>> pattern(1100);
    string line;
    while (getline(cin, line)) {
        // 清空所有集合，准备处理新序列
        for (int i = 0; i < pattern.size(); i++) pattern[i].clear();
        bool good = true;      // 标记当前序列是否仍具有窗口性质
        int position = -1;     // 记录第一个违规符号的位置（1-based）
        // 逐字符遍历输入序列
        for (int i = 0; i < line.length(); i++) {
            // 检查所有可能的窗口长度 k，从 1 到当前序列长度（i+1）
            for (int k = 1; k <= (i + 1); k++) {
                // 提取以当前字符结尾的长度为 k 的子串
                // 子串起始位置：i - k + 1，长度为 k
                string p = line.substr(i - k + 1, k);
                // 将子串插入到对应长度的集合中
                pattern[k].insert(p);
                // 如果不同子串的数量超过了 k+1，则窗口性质被破坏
                if (pattern[k].size() > (k + 1)) {
                    good = false;           // 标记为不具有窗口性质
                    position = i + 1;       // 记录违规符号位置（从 1 开始）
                    goto out;               // 跳出双重循环
                }
            }
        }
    out:        
        if (good) cout << "YES" << endl;
        else cout << "NO:" << position << endl;
    }
    return 0;
}
```

## 注意事项

1. **位置计数**：代码中 $i$ 从 $0$ 开始，违规符号位置为 $i + 1$，符合题目要求（从 $1$ 开始计数）。

2. **子串提取**：使用 `string::substr` 方法，第一个参数是起始索引，第二个参数是长度。注意边界条件 $i - k + 1 \geq 0$，由于 $k \leq i + 1$，该条件自动满足。

3. **退出机制**：一旦发现违规，使用 `goto` 直接跳出双重循环，避免不必要的计算。由于循环嵌套较浅且 $n$ 很小，也可以使用标志变量逐层退出。

4. **时间复杂度**：虽然算法在最坏情况下需要处理约 $\sum_{i=1}^{n} \sum_{k=1}^{i} O(k) = O(n^3)$ 次操作，但 $n \leq 100$ 保证了运行效率。
