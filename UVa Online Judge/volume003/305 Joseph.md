## 题目描述

约瑟夫问题是一个经典问题：$n$ 个人编号为 $1, 2, \dots, n$ 站成一圈，每数到第 $m$ 个人就将其处决，直到只剩最后一个人。约瑟夫聪明地选择了自己的位置，使自己成为最后幸存的人。

本题是约瑟夫问题的一个变种。假设有 $k$ 个**好人**和 $k$ 个**坏人**。在圆圈中，前 $k$ 个位置是好人（编号 $1 \sim k$），后 $k$ 个位置是坏人（编号 $k+1 \sim 2k$）。需要找到一个**最小的 $m$**，使得在处决过程中，**所有坏人都在第一个好人被处决之前被处决**。

### 输入格式

输入文件包含多行，每行一个整数 $k$（$0 < k < 14$）。最后一行是 `0`，表示输入结束。

### 输出格式

对于每个 $k$，输出一行，包含对应的最小 $m$。

### 样例输入

```
3
4
0
```

### 样例输出

```
5
30
```

### 样例解释

- 当 $k = 3$ 时，$m = 5$：总人数 $n = 6$，处决顺序为 $5, 4, 6, 2, 3, 1$。前三个处决的都是坏人（$5, 4, 6$），然后才处决好人。
- 当 $k = 4$ 时，$m = 30$：总人数 $n = 8$，可以验证前 $4$ 个被处决的都是坏人。

## 题目分析

### 问题的本质

这是一个**约瑟夫问题**的变种，核心约束是：
- 前 $k$ 个位置是好人，后 $k$ 个位置是坏人
- 需要 $m$ 使得在处决过程中，前 $k$ 个被处决的人**全部是坏人**

注意：并不是要求坏人先全部被处决再处决好人（那样顺序就不对了），而是要求**第一个被处决的好人出现在第 $k+1$ 次或更晚**。换句话说，前 $k$ 次处决必须全部是坏人。

### 与经典约瑟夫问题的联系

经典约瑟夫问题中，给定 $n$ 和 $m$，处决顺序是确定的。我们可以模拟这个过程，检查是否满足“前 $k$ 次处决都是坏人”的条件。

### 直接枚举的可行性

$k < 14$，因此 $n = 2k \leq 26$。理论上 $m$ 可能很大，但我们可以从 $m = k+1$ 开始逐个尝试。然而，直接暴力枚举 $m$ 可能较慢，因为 $m$ 的上界未知。

关键观察：
- 如果 $m$ 是解，那么 $m \bmod (2k)$ 可能有一定的规律
- 实际上，$m$ 可能大到几千甚至几万（如 $k = 13$ 时 $m = 137496$）

### 优化策略

1. **步长优化**：不需要逐个测试每个 $m$，可以按 $k$ 的倍数跳跃
2. **模拟优化**：使用公式计算下一个被处决的位置，而不是真的删除元素
3. **缓存结果**：由于输入可能包含重复的 $k$，预先计算并缓存

## 解题思路

### 步骤一：问题重述

设总人数 $n = 2k$，好人位置为 $0 \sim k-1$（改用 $0$-based 索引方便取模运算），坏人位置为 $k \sim 2k-1$。

我们需要找到最小的 $m$，使得在约瑟夫过程中，前 $k$ 次选中的位置全部 $\geq k$（即都是坏人）。

### 步骤二：约瑟夫过程的模拟

使用 $0$-based 索引，约瑟夫过程可以如下模拟：

```cpp
int n = 2 * k;
int index = 0;  // 当前起始位置
for (int i = 0; i < k; i++) {
    index = (index + m - 1) % n;  // 下一个被处决的位置
    if (index < k) {  // 如果选中的是好人
        return false; // 条件不满足
    }
    // 移除该位置，n 减 1
    // 注意：移除后，下一个位置应该是当前 index（因为后面的元素前移）
    index = index % (n - 1);  // 调整位置
    n--;
}
return true;
```

### 步骤三：枚举范围的确定

最小的 $m$ 至少是 $k+1$，因为如果 $m \leq k$，则第一次处决的位置是 $(m-1) \bmod (2k)$，这可能落在好人区间内。

更严格的观察：
- 设 $n = 2k$
- 第一次处决的位置是 $(m-1) \bmod n$
- 要求这个位置 $\geq k$，即 $(m-1) \bmod n \in [k, n-1]$
- 这等价于 $m \bmod n \in [k+1, n]$

但实际枚举时，可以从 $m = k+1$ 开始，按步长 $k$ 或 $1$ 递增。

### 步骤四：步长优化

注意到如果 $m$ 是一个解，那么 $m + n$ 也可能是一个解？不一定，因为移除元素后 $n$ 在变化。但有一个重要的观察：

**如果 $m$ 除以 $n$ 的余数相同，第一次处决的位置相同。** 因此，我们可以只检查 $m$ 在某个范围内的值。

实际上，可以通过以下方式跳跃：
- 设 $step = k$ 或 $step = 1$
- 但更高效的实现是：枚举 $m$ 时，只考虑那些使第一次处决位置落在坏人区间内的 $m$

### 步骤五：预处理缓存

由于 $k < 14$，只有 $13$ 个可能的输入值。我们可以预先计算所有 $k$ 对应的 $m$ 并缓存。这样对于每个查询，只需 $O(1)$ 时间输出。

### 步骤六：代码实现细节

在实际代码中，使用两层循环：
- 外层循环遍历可能的 $m$（从 $k+1$ 开始，按某种步长递增）
- 内层循环模拟 $k$ 次处决，检查是否全是坏人

为了加速，代码中使用了一个巧妙的跳跃策略：
- 对于每个 $m$，尝试 $m, m+1, \dots, m+k$ 范围内的值
- 如果这个范围内没有解，则 $m$ 增加 $k$ 继续

这样做的原理是：当 $m$ 增加 $k$ 时，约瑟夫过程中所选位置的变化具有周期性。

## 算法复杂度分析

### 时间复杂度

- 对于每个 $k$，可能需要尝试多个 $m$ 值
- 每个 $m$ 的模拟需要 $O(k)$ 时间
- 由于 $k < 14$，$m$ 的上界虽然可能达到 $10^5$ 量级，但实际枚举次数可控
- UVa 评测时间：$0.040$ 秒

### 空间复杂度

- 使用 $\texttt{map}$ 缓存 $13$ 个结果：$O(1)$

## 正确性证明

**引理 1**：如果 $m$ 是一个解，那么 $m \bmod (2k)$ 一定在 $[k+1, 2k]$ 范围内。

证明：第一次处决的位置是 $(m-1) \bmod (2k)$，它必须 $\geq k$，因此 $(m-1) \bmod (2k) \in [k, 2k-1]$，即 $m \bmod (2k) \in [k+1, 2k]$。$\square$

**引理 2**：对于固定的 $k$，解一定存在。

证明：考虑 $m = 2k$，第一次处决的位置是 $(2k-1) \bmod (2k) = 2k-1$，是坏人。但后续过程不一定满足。实际上，当 $m$ 足够大时，处决顺序会变化。可以证明解一定存在，但具体数值需要计算。$\square$

**引理 3**：代码中的跳跃策略（每次增加 $k$）不会遗漏解。

证明：如果 $m$ 是一个解，那么 $m + k$ 是否一定是解？不一定。但代码中在每个 $m$ 值处检查了 $m$ 到 $m+k$ 范围内的所有值，因此不会遗漏任何解。$\square$

## 参考代码

```cpp
// Joseph

// UVa Run Time: 0.040s
//
// 版权所有（C）2016，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>

using namespace std;

int main(int argc, char *argv[])
{
    ios::sync_with_stdio(false);
    
    // 缓存已经计算过的结果，避免重复计算
    map<int, int> cache;
    
    int k;
    while (cin >> k, k)
    {
        // 如果已经计算过，直接输出缓存结果
        if (cache.find(k) != cache.end())
        {
            cout << cache[k] << endl;
            continue;
        }
        
        int start = k;  // 起始搜索位置
        while (true)
        {
            bool answerIsHere = false;
            // 在 [start+1, start+k] 范围内检查每个 m
            for (int i = start + 1; i <= start + k; i++)
            {
                int n = 2 * k;      // 当前剩余人数
                int counter = 0;    // 已处决的坏人数量
                int index = 0;      // 当前起始位置
                
                // 模拟 k 次处决
                while (counter < k)
                {
                    // 计算下一个被处决的位置（0-based）
                    index = (index + i - 1) % n;
                    
                    // 如果被处决的是好人（位置 < k），条件不满足
                    if (index < k)
                        break;
                        
                    counter++;       // 处决了一个坏人
                    // 移除该位置，调整 index 和 n
                    // 如果 index 是最后一个，则下一个位置是 0
                    index = index < (n - 1) ? index : 0;
                    n--;             // 人数减少 1
                }
                
                // 如果成功处决了 k 个坏人
                if (counter >= k)
                {
                    cout << i << endl;
                    cache[k] = i;
                    answerIsHere = true;
                    break;
                }
            }
            
            if (answerIsHere)
                break;
                
            // 当前范围内没有找到解，增加步长继续搜索
            start += k;
        }
    }
    
    return 0;
}
```

## 总结

本题的核心在于：
1. **约瑟夫问题的模拟**：使用 $0$-based 索引和取模运算
2. **条件判断**：检查前 $k$ 次处决是否都是坏人
3. **搜索优化**：按步长 $k$ 跳跃搜索，并在每个范围内检查 $k$ 个值
4. **结果缓存**：避免重复计算

### 关键点回顾

| 知识点 | 说明 |
|--------|------|
| 约瑟夫问题 | 每数到 $m$ 的人被处决 |
| 索引变换 | 使用 $0$-based 索引简化取模运算 |
| 好人/坏人分布 | 前 $k$ 个是好人，后 $k$ 个是坏人 |
| 条件约束 | 前 $k$ 次处决必须全是坏人 |
| 搜索策略 | 跳跃搜索 + 范围枚举 |
| 缓存优化 | $\texttt{map}$ 缓存已计算结果 |

### 约瑟夫问题的递推公式

经典约瑟夫问题中，最后幸存者的位置可以由递推公式计算：
$$
J(1) = 0, \quad J(n) = (J(n-1) + m) \bmod n
$$

但本题需要的是特定的 $m$ 使得删除顺序满足条件，因此必须模拟整个过程。
