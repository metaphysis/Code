## 题目描述

一个 $\texttt{D0L}$（确定性无交互 $\texttt{Lindenmayer}$ 系统）系统由以下部分组成：
- 一个有限的符号集 $\Sigma$（字母表）
- 一个有限的生产规则集 $P$
- 一个起始字符串 $\omega$

生产规则的形式为 $x \rightarrow u$，其中 $x \in \Sigma$，$u \in \Sigma^+$（$u$ 是非空字符串）。每个符号 $x \in \Sigma$ 在 $P$ 中恰好有一个生产规则。直接推导是将字符串 $u_1$ 中的每个符号替换为其生产规则的右端字符串。$\texttt{D0L}$ 系统的语言包含所有可以从起始字符串 $\omega$ 通过有限次直接推导得到的字符串。

假设字母表包含两个符号 $\texttt{a}$ 和 $\texttt{b}$。因此生产规则集包含两条规则：
- $\texttt{a} \rightarrow u$
- $\texttt{b} \rightarrow v$

其中 $u, v \in \{\texttt{a}, \texttt{b}\}^+$，起始字符串 $\omega \in \{\texttt{a}, \texttt{b}\}^+$。

问题：给定字符串 $z$，判断在 $\texttt{D0L}$ 系统的语言中，是否存在一个字符串可以表示为 $xzy$ 的形式（即 $z$ 作为子串出现）。其中 $x$ 和 $y$ 是任意字符串（可以为空）。

### 输入格式

输入文件由多个数据块组成，每个数据块包含四行，块之间没有空行：
- 第一行：符号 $\texttt{a}$ 的生产规则右端字符串 $u$
- 第二行：符号 $\texttt{b}$ 的生产规则右端字符串 $v$
- 第三行：起始字符串 $\omega$
- 第四行：目标字符串 $z$

所有字符串的长度最多为 $15$ 个字符。

### 输出格式

对于每个数据块，输出一行，包含 `YES` 或 `NO`。

### 样例输入

```
aa
bb
ab
aaabb
a
b
ab
ba
```

### 样例输出

```
YES
NO
```

## 题目分析

### 问题的本质

这是一个**形式语言**问题。给定一个 $\texttt{D0L}$ 系统和目标字符串 $z$，判断在系统的语言中是否存在包含 $z$ 作为子串的字符串。

由于字符串长度有限制（$\leq 15$），而派生过程可能会产生非常长的字符串（指数增长），直接模拟所有派生是不现实的。但我们可以利用以下关键观察：

**关键观察**：如果目标字符串 $z$ 出现在某个派生字符串中，那么它一定可以在有限步内出现，并且我们只需要关注那些长度与 $z$ 相关的字符串。

### 派生过程的性质

设 $L$ 为 $z$ 的长度。考虑一个足够长的派生字符串 $s$。如果 $s$ 包含 $z$ 作为子串，那么 $z$ 一定是由 $s$ 中某个长度为 $L$ 的子串通过“反向派生”得到的。

更重要的是：由于生产规则将每个符号替换为固定长度的字符串，派生过程可以用一个**有限自动机**或**图论**模型来描述。

### 有穷状态空间

这是一个典型的**有穷自动机问题**。我们可以将所有长度不超过 $|z|$ 的字符串视为状态。如果一个字符串的长度超过 $|z|$，我们只关心其所有长度为 $|z|$ 的子串。由于字母表只有两个字符 $\texttt{a}$ 和 $\texttt{b}$，长度为 $L$ 的字符串总数为 $2^L \leq 2^{15} = 32768$，这是一个可管理的状态空间。

### 算法思路

我们可以使用 **$\texttt{BFS}$ 或 $\texttt{DFS}$** 从起始字符串 $\omega$ 出发，生成所有可达的“有意义”的字符串，直到无法生成新字符串为止。如果在这个过程中生成了包含 $z$ 的子串，则答案为 `YES`，否则为 `NO`。

## 解题思路

### 步骤一：预处理

首先检查一个简单情况：如果 $z$ 本身是 $u$ 或 $v$ 的子串，那么第一次派生就可能产生 $z$（因为起始字符串 $\omega$ 中的符号会被替换为 $u$ 或 $v$）。但更准确的检查是：如果 $z$ 出现在 $u$ 或 $v$ 中，那么从包含该符号的字符串派生一步就能得到包含 $z$ 的字符串。

实际上，如果 $z$ 是 $u$ 或 $v$ 的子串，则答案是 `YES`。这是因为起始字符串 $\omega$ 至少包含一个符号（长度 $\geq 1$），派生一步后就会产生包含 $u$ 或 $v$ 的字符串。

### 步骤二：$\texttt{DFS}$ 搜索

如果 $z$ 不在 $u$ 或 $v$ 中，我们需要进行搜索。搜索过程如下：

1. 使用一个集合 `produced` 存储已经访问过的字符串
2. 从起始字符串 $\omega$ 开始
3. 对于当前字符串 `current`：
   - 如果 `current` 包含 $z$，则返回 `true`
   - 否则，根据生产规则生成 `next` 字符串
   - 如果 `next` 的长度 $\leq |z|$，则继续搜索 `next`
   - 否则，提取 `next` 的所有长度为 $|z|$ 的子串，并对每个子串继续搜索

### 步骤三：长度控制

为什么要提取长度为 $|z|$ 的子串？因为如果 `next` 的长度超过 $|z|$，那么任何包含 $z$ 的长字符串必然在某个位置包含 $z$ 作为子串。提取所有长度为 $|z|$ 的子串足以捕获所有可能性。

例如，假设 $|z| = 3$，`next = "ababa"`，我们只关心 `"aba"`、`"bab"`、`"aba"` 这三个子串。

### 步骤四：终止条件

由于字符串长度有限，状态空间是有限的，搜索必然终止。当无法生成新的字符串时，搜索结束。

## 算法复杂度分析

### 时间复杂度

- 状态数：最多 $2^L + 1$，其中 $L = |z| \leq 15$，因此状态数 $\leq 32769$
- 每个状态的生成需要 $O(L)$ 时间
- 总复杂度：$O(2^L \cdot L) \approx 5 \times 10^5$，完全可行

### 空间复杂度

- 存储已访问的字符串集合：$O(2^L)$
- 递归深度：最多 $O(2^L)$（最坏情况）

## 正确性证明

**引理 1**：如果 $z$ 出现在 $u$ 或 $v$ 中，则答案一定是 `YES`。

证明：起始字符串 $\omega$ 非空，设其第一个符号为 $c$。派生一步后，该符号被替换为 $u$（若 $c = \texttt{a}$）或 $v$（若 $c = \texttt{b}$），因此派生一步后的字符串包含 $u$ 或 $v$，从而包含 $z$。$\square$

**引理 2**：如果 $z$ 出现在某个派生字符串中，那么它一定出现在某个长度 $\leq |z|$ 的字符串中，或者出现在某个派生字符串的长度为 $|z|$ 的子串中。

证明：考虑包含 $z$ 的最短派生字符串 $s$。如果 $|s| > |z|$，则 $s$ 必然可以通过对其前驱派生一步得到。如果前驱的长度 $\leq |z|$，则 $z$ 出现在某个长度 $\leq |z|$ 的字符串中；如果前驱的长度 $> |z|$，则可以继续回溯，直到找到长度 $\leq |z|$ 的字符串或长度恰好为 $|z|$ 的子串。$\square$

**引理 3**：搜索算法是完备的。

证明：算法从起始字符串开始，通过派生规则生成所有可能的长度 $\leq |z|$ 的字符串及其所有长度为 $|z|$ 的子串。由引理 2，如果存在包含 $z$ 的派生字符串，则它必然被算法捕获。$\square$

## 参考代码

```cpp
// L-system
// UVa ID: 310
// Verdict: Accepted
// Submission Date: 2016-11-22
// UVa Run Time: 0.020s
//
// 版权所有（C）2016，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>

using namespace std;

set<string> produced;   // 记录已经访问过的字符串

string u, v, w, z;      // u: a的生产规则, v: b的生产规则, w: 起始字符串, z: 目标字符串

// 深度优先搜索
// current: 当前考虑的字符串
bool get(string current)
{
    // 如果当前字符串已经访问过，避免重复处理
    if (produced.find(current) != produced.end()) return false;
    
    produced.insert(current);

    string next;
    // 应用生产规则，生成下一级字符串
    for (int i = 0; i < current.length(); i++)
        if (current[i] == 'a') next += u;
        else next += v;

    // 如果 next 的长度不超过 z 的长度，直接继续搜索
    if (next.length() <= z.length()) 
        get(next);
    else
    {
        // 否则，提取所有长度为 |z| 的子串进行搜索
        for (int i = 0; i <= next.length() - z.length(); i++)
            get(next.substr(i, z.length()));
    }
    
    return true;
}

// 检查 produced 中是否有包含 z 的字符串
bool find()
{
    for (auto it = produced.begin(); it != produced.end(); it++)
        if ((*it).find(z) != string::npos)
            return true;
    return false;
}

int main(int argc, char *argv[])
{
    cin.tie(0); cout.tie(0); ios::sync_with_stdio(false);

    while (cin >> u >> v >> w >> z)
    {
        // 特殊情况：如果 z 本身就是 u 或 v 的子串
        if (u.find(z) != string::npos || v.find(z) != string::npos)
            cout << "YES\n";
        else
        {
            produced.clear();
            get(w);
            cout << (find() ? "YES" : "NO") << '\n';
        }
    }
    
    return 0;
}
```

## 总结

本题的核心在于：
1. **状态空间压缩**：只关注长度不超过 $|z|$ 的字符串及其子串
2. **搜索策略**：使用 $\texttt{DFS}$ 遍历所有可能的状态
3. **边界条件**：$z$ 出现在 $u$ 或 $v$ 中时直接判定为 `YES`

### 关键点回顾

| 知识点 | 说明 |
|--------|------|
| $\texttt{D0L}$ 系统 | 确定性 $\texttt{Lindenmayer}$ 系统，每个符号恰好一个产生式 |
| 派生过程 | 同时替换字符串中的所有符号 |
| 状态空间 | 长度为 $L$ 的字符串最多 $2^L$ 个 |
| 子串提取 | 长度超过 $L$ 时只保留长度为 $L$ 的子串 |
| $\texttt{DFS}$ 搜索 | 遍历所有可达状态 |
| 集合去重 | 使用 $\texttt{set}$ 避免重复处理 |

### 算法思想的应用

这种“通过提取定长子串来压缩无限状态空间”的技巧，在处理形式语言和字符串重写系统时非常常见。它本质上是将无限的语言投影到一个有限的状态空间上，从而使得判定问题可解。
