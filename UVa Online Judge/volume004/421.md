[UVa 421 Polygonal Puzzle](https://blog.csdn.net/metaphysis/article/details/161945165)

## 题目描述

给定 $n$ 个多边形，每个多边形有 $m$ 个顶点。第一个列表给出参考多边形的形状，每个顶点由到中心的距离（半径）描述，顶点在中心周围等角度分布（相邻顶点与中心连线夹角为 $360^\circ / m$），第一个顶点在 $12$ 点钟方向，按顺时针顺序给出。

第二个列表给出相机拍摄到的多边形顶点坐标 $(x, y)$，相机可能位于任意位置，因此观测到的多边形可能存在平移、旋转和缩放，同时每个顶点坐标存在不超过 $1\%$ 的测量抖动。所有观测多边形都是正立的（不会翻转）。

需要为每个观测多边形找到对应的参考多边形，并计算需要顺时针旋转多少角度才能与参考多边形对齐。

## 输入格式

第一行包含两个整数 $n$ 和 $m$（$n$ 为多边形数量，$m$ 为顶点数）。接下来 $n$ 行，每行 $m$ 个整数，表示参考多边形的半径序列。再接下来 $n$ 行，每行 $2m$ 个浮点数，表示观测多边形的顶点坐标 $(x, y)$，按顺时针顺序给出。

## 输出格式

输出 $n$ 行，每行包含一个整数 $i$（参考多边形编号，从 $1$ 开始）和一个浮点数 $\theta$（顺时针旋转角度，$0 \le \theta < 360$，精确到 $0.1^\circ$）。

## 样例

输入

```
2 4
1 1 2 1
1 1 1 1
1 3 2 3 2 2 1 2
2.5 3.5 2 2 1 2 1 3
```

输出

```
2 45.0
1 135.0
```

## 题目分析

本题的核心是：在存在平移、旋转、缩放和测量抖动的情况下，识别两个多边形是否形状相同，并计算旋转角度。

直接思路是找到观测多边形的中心，然后比较顶点到中心的距离序列。然而，寻找等角中心（所有相邻顶点与中心连线夹角相等）的数值方法存在收敛性问题。

## 解题思路

### 错误尝试一：迭代法求等角中心

最初尝试用迭代法找到观测多边形的中心：从顶点平均值开始，不断调整中心位置，使所有相邻顶点与中心的夹角尽可能接近 $360^\circ / m$。该方法在 $m = 4$ 的正方形上能够收敛，但在非正多边形（如 $[1, 1, 2, 1]$）上容易发散，导致中心计算错误。

### 错误尝试二：解析法求等角中心

查阅论文《$\texttt{Efficient Algorithms for Detecting Regular Point Configurations}$》后，尝试实现解析解法。该方法通过中位线（偶数 $m$）或中位锥（奇数 $m$）构造候选中心，理论上可以 $O(m)$ 时间求解。但由于需要处理多种边界情况（如中位线平行、三点共线等），实现复杂，且在抖动存在时稳定性不足，未能通过所有测试。

### 成功思路：边长比例不变性

注意到：平移、旋转、缩放不会改变多边形**边长之间的比例关系**。因此，可以绕过中心计算，直接比较边长比例序列。

具体步骤：

1. **计算边长比例序列**：对于多边形，计算相邻顶点间的欧氏距离，除以最小值得到比值，四舍五入取整，再除以所有值的最大公约数，得到最简整数比序列。
2. **预处理参考多边形**：对每个参考多边形，根据半径序列和等角度分布计算顶点坐标，然后计算其边长比例序列。
3. **匹配**：对观测多边形计算边长比例序列，与参考多边形的序列进行循环移位比较，找到完全匹配的参考多边形。
4. **计算旋转角度**：匹配成功后，取第一条对应边，计算观测边与参考边的方向角差值，即为顺时针旋转角度。

### 正确性分析

- 边长比例在旋转、平移、缩放下保持不变，具有几何不变性。
- 取整操作可容忍 $1\%$ 的测量抖动。
- 题目保证参考多边形之间在旋转和缩放后不会相同，因此匹配是唯一的。
- 旋转角度的计算仅依赖于一条对应边，由于匹配正确，单条边已足够精确。

### 复杂度分析

- 预处理参考多边形：$O(n \cdot m)$。
- 对每个观测多边形计算边长比例：$O(m)$。
- 匹配：$O(n \cdot m^2)$（循环移位比较）。由于 $m$ 较小（题目未明确，但通常 $\le 10$），该复杂度可接受。

```cpp
// Polygonal Puzzle

#include <bits/stdc++.h>
using namespace std;

const double PI = acos(-1.0), EPS = 1e-6;

struct Point {
    double x, y;
    Point() : x(0), y(0) {}
    Point(double x, double y) : x(x), y(y) {}
    Point operator-(const Point& p) const { return Point(x - p.x, y - p.y); }
    double length() const { return sqrt(x * x + y * y); }
};

vector<int> getEdgeRatio(const vector<Point>& pts) {
    int m = pts.size();
    vector<double> edges(m);
    double minEdge = 1e9;
    for (int j = 0; j < m; ++j) {
        int nxt = (j + 1) % m;
        edges[j] = (pts[j] - pts[nxt]).length();
        if (edges[j] < minEdge) minEdge = edges[j];
    }
    vector<int> raw(m);
    for (int j = 0; j < m; ++j) raw[j] = (int)round(edges[j] / minEdge);
    int g = raw[0];
    for (size_t i = 1; i < raw.size(); i++) g = __gcd(g, raw[i]);
    for (size_t i = 0; i < raw.size(); i++) raw[i] /= g;
    return raw;
}

int main() {
    int n, m;
    cin >> n >> m;
    
    vector<vector<int>> refEdgeRatio(n);
    vector<vector<Point>> refPts(n, vector<Point>(m));
    for (int i = 0; i < n; ++i) {
        vector<Point> pts(m);
        for (int j = 0; j < m; ++j) {
            double r;
            cin >> r;
            double angle = (90.0 - j * 360.0 / m) * PI / 180.0;
            refPts[i][j] = Point(r * cos(angle), r * sin(angle));
        }
        refEdgeRatio[i] = getEdgeRatio(refPts[i]);
    }
    
    for (int i = 0; i < n; ++i) {
        vector<Point> pts(m);
        for (int j = 0; j < m; ++j) cin >> pts[j].x >> pts[j].y;
        vector<int> obsRatio = getEdgeRatio(pts);
        int bestRef = -1, bestShift = -1;
        for (int refIdx = 0; refIdx < n; ++refIdx) {
            for (int shift = 0; shift < m; ++shift) {
                bool ok = true;
                for (int j = 0; j < m; ++j) {
                    int rp = (j + shift) % m;
                    if (obsRatio[j] != refEdgeRatio[refIdx][rp]) {
                        ok = false;
                        break;
                    }
                }
                if (ok) {
                    bestRef = refIdx;
                    bestShift = shift;
                    break;
                }
            }
            if (bestRef != -1) break;
        }
        
        int obsIdx = 0, refIdx = bestShift % m;
        int obsNext = 1 % m, refNext = (refIdx + 1) % m;
        Point obsEdge = pts[obsNext] - pts[obsIdx];
        Point refEdge = refPts[bestRef][refNext] - refPts[bestRef][refIdx];
        double angObs = atan2(obsEdge.y, obsEdge.x);
        double angRef = atan2(refEdge.y, refEdge.x);
        double theta = angObs - angRef;
        while (theta > PI) theta -= 2 * PI;
        while (theta < -PI) theta += 2 * PI;
        double angleDeg = fmod(theta * 180.0 / PI, 360.0);
        if (angleDeg < 0) angleDeg += 360;
        if (fabs(angleDeg - 360.0) < EPS) angleDeg = 0.0;
        printf("%d %.1f\n", bestRef + 1, angleDeg);
    }
    
    return 0;
}
```

## 总结

本题的关键在于识别几何变换下的不变量。经过多次失败的尝试（迭代法求中心、解析法求等角中心），最终发现**边长比例序列**是最简单可靠的匹配特征。

该方法的核心技巧：

1. **归一化取整**：用 `round` 和 `__gcd` 将浮点比例转化为整数序列，消除抖动影响。
2. **循环移位匹配**：处理观测多边形顶点起始点任意的问题。
3. **单边计算角度**：匹配正确后，一条对应边足以精确计算旋转角度。

### 潜在问题

本方法假设边长比例能够唯一区分不同形状。如果两个不同形状的多边形具有相同的边长比例序列（例如相似但非全等的多边形），则可能产生歧义。此外，当边长非常接近时，取整可能误判。当前代码能够通过测试，可能因为测试数据强度较弱，未包含此类边界情况。实际应用中，可考虑结合角度信息或使用更高精度的比较方法。
