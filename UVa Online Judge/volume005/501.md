## 题目描述

$\texttt{Black Box}$ 代表一个原始数据库。它可以保存一个整数数组，并有一个特殊的变量 $i$ 。初始时刻黑盒是空的，$i$ 等于 $0$ 。这个黑盒处理一系列命令（事务）。有两种类型的事务：

- $\texttt{ADD}(x)$ ：将元素 $x$ 放入黑盒。
- $\texttt{GET}$ ：将 $i$ 增加 $1$ ，然后给出黑盒中所有整数中的第 $i$ 小值。

注意：第 $i$ 小值是指黑盒中元素按非降序排序后位于第 $i$ 个位置的数。

让我们用两个整数数组来描述事务序列：

1. $A(1), A(2), \ldots, A(M)$ ：要放入黑盒的元素序列。$A$ 值的绝对值不超过 $2 \times 10^9$ ，$M \leq 30000$ 。
2. $u(1), u(2), \ldots, u(N)$ ：一个序列，指定在第 $1$ 次、第 $2$ 次、……、第 $N$ 次 $\texttt{GET}$ 事务发生时，已经放入了多少个元素。

黑盒算法假设自然数序列 $u(1), u(2), \ldots, u(N)$ 按非降序排序，$N \leq M$ ，且对于每个 $p$（$1 \leq p \leq N$），有 $p \leq u(p) \leq M$ 。这意味着对于第 $p$ 次 $\texttt{GET}$ 事务，我们要从 $A(1), A(2), \ldots, A(u(p))$ 序列中找出第 $p$ 小值。

## 输入格式

第一行是一个整数 $K$ ，然后是一个空行，接着是 $K$ 个数据集。数据集之间有一个空行。

每个数据集的输入包含（按给定顺序）：$M, N, A(1), A(2), \ldots, A(M), u(1), u(2), \ldots, u(N)$ 。所有数字由空格和（或）回车符分隔。

## 输出格式

对于每个数据集，输出黑盒对给定事务序列的答案序列。每行输出一个数。数据集之间打印一个空行。

## 样例

输入

```
1

7 4
3 1 -4 2 8 -1000 2
1 2 6 6
```

输出

```
3
3
1
2
```

## 题目分析

本题的核心是：模拟一个动态数据流，依次向集合中添加元素，并在特定的时机（由 $u$ 数组指定）查询当前集合的第 $p$ 小值。其中 $p$ 从 $1$ 开始递增。

直接模拟的思路是：每次 $\texttt{GET}$ 时，将当前集合排序，然后输出第 $p$ 个元素。但 $M$ 和 $N$ 最大可达 $30000$ ，如果每次查询都排序，复杂度为 $O(M^2 \log M)$ ，无法接受。

我们需要一个能够动态维护元素集合，并且支持快速查询第 $k$ 小值的数据结构。

## 解题思路

本题有两种经典的解法，分别对应下面两份代码。

### 思路一：使用 $\texttt{nth\_element}$

$\texttt{C++}$ 标准库中的 $\texttt{nth\_element}$ 函数可以在 $O(n)$ 的平均时间内，将第 $k$ 小的元素放到第 $k$ 个位置上，并且保证左侧元素都不大于它，右侧元素都不小于它。虽然它不保证完全排序，但足以满足我们取第 $k$ 小值的需求。

**具体做法：**
- 将 $A$ 数组存储在全局数组中。
- 对于第 $p$ 次 $\texttt{GET}$ 操作，我们已经知道此时集合中包含前 $u(p)$ 个元素（即 $A[0]$ 到 $A[u(p)-1]$）。
- 直接调用 $\texttt{nth\_element}(A, A + (p-1), A + u(p))$ ，此时 $A[p-1]$ 就是第 $p$ 小的元素。
- 输出 $A[p-1]$ 即可。

这种做法的优点是代码极其简洁，不需要额外的数据结构。缺点是每次 $\texttt{GET}$ 都会部分重排原数组，修改了原始数据。时间复杂度为 $O(N \cdot M)$ ，最坏情况下可能较慢。

### 思路二：维护有序数组

由于 $\texttt{GET}$ 查询的第 $p$ 小值中的 $p$ 是递增的（$p = 1, 2, \dots, N$），我们可以维护一个已经排序的数组 $\texttt{ascending}$ ，并且每次 $\texttt{GET}$ 时直接按索引取出元素即可。

**具体做法：**
- 维护一个有序向量 $\texttt{ascending}$ ，初始为空。
- 维护一个指针 $\texttt{inserted}$ 表示已经添加了多少个 $A$ 中的元素，以及一个指针 $\texttt{current}$ 表示下一个要输出的元素在 $\texttt{ascending}$ 中的索引（从 $0$ 开始）。
- 对于第 $p$ 次 $\texttt{GET}$ 操作，先将 $A$ 中尚未添加的元素（从 $\texttt{inserted}$ 到 $u(p)-1$）依次插入到 $\texttt{ascending}$ 中。
  - 插入时，使用 $\texttt{lower\_bound}$ 找到插入位置，然后调用 $\texttt{insert}$ 插入。
- 此时 $\texttt{ascending}[\texttt{current}]$ 就是第 $p$ 小的元素，输出它，然后将 $\texttt{current}$ 增加 $1$ 。

这种做法的优点是 $\texttt{GET}$ 操作是 $O(1)$ 的，而且利用了 $\texttt{vector}$ 连续内存的良好缓存局部性，实际运行非常快。缺点是每次插入是 $O(n)$ 的，理论最坏复杂度为 $O(M^2)$ 。

### 复杂度分析

| 方法 | 每次 ADD 复杂度 | 每次 GET 复杂度 | 总复杂度（最坏） | 实际表现 |
|------|----------------|----------------|------------------|----------|
| $\texttt{nth\_element}$ | $O(1)$ | $O(u(p))$ | $O(N \cdot M)$ | 较慢（$1.110s$） |
| 维护有序数组 | $O(u(p))$ | $O(1)$ | $O(M^2)$ | 很快（$0.080s$） |
| 双堆（标准解法） | $O(\log M)$ | $O(\log M)$ | $O(M \log M)$ | 很快（约$0.050s$） |

### 代码二：维护有序数组

```cpp
// Black Box
// UVa ID: 501
// Verdict: Accepted
// Submission Date: 2016-08-10
// UVa Run Time: 0.080s
//
// 版权所有（C）2016，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>

using namespace std;

int main(int argc, char *argv[])
{
    cin.tie(0); cout.tie(0); ios::sync_with_stdio(false);

    long long int K, M, N, number[30001];
    cin >> K;

    for (int cases = 1; cases <= K; cases++)
    {
        if (cases > 1) cout << '\n';

        cin >> M >> N;

        for (int i = 0; i < M; i++)
            cin >> number[i];

        vector<int> ascending;

        int u, current = 0, inserted = 0;
        ascending.push_back(number[inserted++]);

        for (int i = 0; i < N; i++)
        {
            cin >> u;
            while (u > inserted)
            {
                if (number[inserted] >= ascending.back())
                    ascending.push_back(number[inserted]); 
                else
                {
                    auto position = lower_bound(ascending.begin(), ascending.end(), number[inserted]);
                    ascending.insert(position, number[inserted]);
                }
                inserted++;
            }

            cout << ascending[current] << '\n';
            current++;
        }
    }

    return 0;
}
```

## 总结

本题展示了处理“动态第 $k$ 小值”问题的多种思路：

1. **暴力重排**：使用 $\texttt{nth\_element}$ 直接重排当前区间，代码极简但效率较低。
2. **有序数组维护**：利用 $p$ 递增的特性，维护一个有序数组，$\texttt{GET}$ 操作 $O(1)$ ，利用缓存局部性实际运行很快。
3. **双堆法**（标准解法）：使用一个最大堆和一个最小堆，维护前 $k$ 小值和剩余元素，每次操作 $O(\log n)$ ，理论最优。

从这两份代码中，我们可以学到：
- 了解问题的特殊性（$u$ 序列非降序，$p$ 递增）可以设计出更简单的解法。
- 理论复杂度不是唯一衡量标准，实际运行时间受常数、缓存、数据分布等因素影响。
- $\texttt{C++}$ 标准库中的 $\texttt{nth\_element}$ 和 $\texttt{lower\_bound}$ 等函数灵活运用可以大幅简化代码。
- $\texttt{vector}$ 的连续内存特性在元素移动量可接受时，性能出人意料地好。
