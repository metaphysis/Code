[UVa 566 Adam's Gene](https://blog.csdn.net/metaphysis/article/details/156277540)

## 题目描述

你被全球领先的人类克隆公司 $\texttt{Gemini Labs}$ 聘用，负责编写决策支持软件。在 $\texttt{Gemini}$，所有克隆都源自 $\texttt{ADAM}$ ——一个基因完美的人类。他的 $\texttt{DNA}$ 中的某些特性使他比普通人更容易克隆。然而，并非所有 $\texttt{Adam}$ 的克隆体都是相同的，因为遗传学家会引入隐性基因形式的突变来研究遗传学。

例如，$\texttt{Bob}$ 可能是 $\texttt{Adam}$ 的一个克隆体，添加了秃顶的隐性基因。科学家会研究 $\texttt{Bob}$，以了解该基因可能产生的微妙影响。$\texttt{Bob}$ 的克隆体会携带该隐性基因，这些克隆体的克隆体也会如此，依此类推。只要从 $\texttt{Bob}$ 衍生的克隆体没有被给予第二个隐性秃顶基因，一切都会正常。如果发生这种情况，将产生秃顶克隆体，克隆委员会将关闭 $\texttt{Gemini}$。

你要编写的软件接收研究人员的克隆请求，并评估其一致性和安全性。如果一组请求中包含一个不是 $\texttt{Adam}$ 后代的克隆体，则该请求集合是"不一致的"。如果一个请求集合产生具有两个相同隐性基因的克隆体，则该集合是"不安全的"。

## 输入

你的程序读取一个克隆请求文件，每行一个请求。克隆请求的格式如下：

```
<请求> = clone_<名称>_from_<名称><基因列表>
<基因列表> = NULL|_mutating_<基因><基因序列>
<基因序列> = NULL|_<基因><基因序列>
<基因> = 3个大写字母字符
<名称> = 1到10个大写字母字符
<空格> = 一个空格字符
```

一个典型的克隆请求是：

```
clone BOB from ADAM mutating BLD HEM
```

**注意**：单词之间总是恰好有一个空格；一行的最后一个字符后紧跟 $\texttt{EOLN}$（行结束符）。一个请求可以有 $0$ 到 $10$ 个突变。如果请求中没有突变，则不出现 `mutating` 关键字，例如：

```
clone BOB from ADAM
```

输入保证满足语法格式规范，并且保证每个克隆最多只有一个克隆请求，即 `clone BOB` 作为输入行开头出现不超过一次。此外，你应该按照只有在其之前的定义有效的方式来处理请求。因此，如果输入段如下：

```
clone BOB from ADAM
clone MIKE from TIM
clone TIM from BOB
```

你的输出应包括：

```
clone MIKE from TIM has no connection to ADAM
```

因为当 $\texttt{MIKE}$ 被克隆时，与 $\texttt{ADAM}$ 没有连接。如果一个克隆不一致且不安全，那么所有从该克隆衍生的后续克隆都应报告为与 $\texttt{ADAM}$ 没有连接。

## 输出

你的程序生成一个处理后的请求文件，每行一个，顺序与输入相同。请求根据以下规则修改：

1. 如果一个克隆一致且安全，行格式应为：
   ```
   clone JOE from ADAM is consistent and safe
   ```

2. 如果一个克隆不一致，行格式应为：
   ```
   clone <名称> from <名称> has no connection to ADAM
   ```

3. 如果一个克隆不安全，行格式应为：
   ```
   clone <名称> from <名称> was at least twice mutated with <基因>
   ```
   其中<基因>是克隆突变列表中出现的第一个基因，该基因是来自  $\texttt{Adam}$ 的第二次突变。你只需打印第一个这样的双突变基因。

如果特定的克隆请求不一致，则无需报告是否安全。输出中单词之间应恰好有一个空格，没有前导或尾随空格。
## 题目分析

本题是一个典型的 **基因克隆关系追踪与突变计数** 问题，需要处理一个 **动态构建的克隆家族树** ，并检查两个关键属性：

1. **一致性** ：每个克隆体是否都能追溯到始祖 `ADAM` 。
2. **安全性** ：是否有克隆体携带了 **两个相同** 的隐性基因。

### 核心挑战

1. **顺序处理** ：请求必须按输入顺序处理，每个请求只能使用 **之前已定义的克隆体信息** 。这意味着我们不能预先构建完整的关系图，而必须 **边读入边处理** 。

2. **基因突变的累积性** ：每个克隆体不仅拥有自己新增的突变基因，还 **继承** 了其父克隆体的所有突变基因。因此，基因的计数需要 **从父克隆体继承并累加** 。

3. **安全性检查的优先级** ：当发现克隆体不安全时，它 **立即被视为不一致** ，并且其所有后代都会被标记为不一致。此外，当有多个基因出现两次时，需要按照 **当前克隆体突变列表中出现的顺序** 输出 **第一个** 出现两次的基因。

4. **输入解析** ：输入格式固定但可能有变化（可能没有突变基因），需要准确解析克隆体名称、父克隆体名称和突变基因列表。

### 关键观察

- 始祖 `ADAM` 是所有克隆体的 **根节点** ，其基因计数为空，且始终一致。
- 如果父克隆体 **不存在** 或 **不一致** ，则子克隆体直接标记为不一致，无需检查安全性。
- 只有当父克隆体 **存在且一致** 时，才需要继承其基因计数，添加自身突变，然后检查安全性。
- 安全性检查需要遍历 **所有基因**（包括继承的和新增的），而不仅仅是新增的突变基因。

## 解题思路

### 数据结构设计

我们需要一个结构体 `Clone` 来存储每个克隆体的完整信息：

```cpp
struct Clone {
    string parent;                     // 父克隆体名称
    unordered_set<string> mutations;   // 本克隆体新增的突变基因（集合，用于快速查找）
    vector<string> mutationOrder;      // 保持突变基因的原始顺序（用于按序检查）
    unordered_map<string, int> geneCount; // 从祖先继承的基因计数（包括自身）
    bool consistent;                   // 是否与ADAM相连
};
```

- `parent` ：记录父克隆体名称，用于追溯关系。
- `mutations` ：使用 `unordered_set` 存储本克隆体新增的突变基因，便于快速判断基因是否存在。
- `mutationOrder` ：使用 `vector` 保持突变基因的 **输入顺序** ，因为题目要求按突变列表顺序输出第一个双突变基因。
- `geneCount` ：使用 `unordered_map` 记录每个基因从祖先到当前的 **累积出现次数** 。
- `consistent` ：标记该克隆体是否能追溯到 `ADAM` 。

全局使用 `unordered_map<string, Clone> clones` 来存储所有已处理的克隆体，键为克隆体名称，值为对应的 `Clone` 结构体。

### 算法流程

对于每个输入的克隆请求：

#### 1. 解析输入

- 读取固定格式：`clone <child> from <parent> [mutating <gene1> <gene2> ...]`
- 提取子克隆体名称 `child` 、父克隆体名称 `parent` 和突变基因列表。
- 如果存在突变基因，需要 **同时存储到集合（快速查找）和向量（保持顺序）** 中。

#### 2. 输出请求前缀

- 始终先输出 `clone <child> from <parent>` 部分。

#### 3. 一致性检查

- 如果父克隆体不是 `ADAM` 且 **不在 `clones` 映射中** ，说明父克隆体尚未定义，子克隆体不一致。
- 如果父克隆体存在但 **其 `consistent` 字段为 `false`** ，则子克隆体也不一致。
- 如果以上任一条件成立，输出 `has no connection to ADAM` ，并将该克隆体标记为不一致（`consistent = false`），**无需进行安全性检查**。

#### 4. 继承与突变添加

- 如果父克隆体一致，则 **复制父克隆体的 `geneCount`** 到当前克隆体。
- 将当前克隆体 **新增的突变基因** 加入到 `geneCount` 中，对应计数加 $1$ 。
- 此时，当前克隆体默认是一致的（`consistent = true`）。

#### 5. 安全性检查

- 遍历当前克隆体的 `mutationOrder` （按突变列表顺序）：
  - 对于每个基因，在 `geneCount` 中查找其计数。
  - 如果计数 $\ge 2$ ，说明该基因是 **从 Adam 以来的第二次突变** 。
  - **立即返回该基因**（因为是按顺序遍历，第一个满足条件的基因就是题目要求的第一个双突变基因）。
- 如果找到不安全的基因，输出 `was at least twice mutated with <gene>` ，并将该克隆体 **标记为不一致**（`consistent = false`），因为不安全的克隆体被视为不一致。
- 如果没有找到，则克隆体安全。

#### 6. 最终输出

- 如果克隆体 **一致且安全** ，输出 `is consistent and safe` 。
- 如果克隆体 **不一致** ，输出 `has no connection to ADAM` 。
- 如果克隆体 **不安全** ，输出 `was at least twice mutated with <gene>` 。

### 时间复杂度

- 每个请求需要解析输入、复制父克隆体的基因计数、添加新突变、检查安全性。
- 设 $N$ 为请求数， $M$ 为每个请求的平均突变基因数， $G$ 为总基因种类数。
- 复制父克隆体基因计数的时间复杂度为 $O(G)$ 。
- 检查安全性的时间复杂度为 $O(M)$ （只需遍历当前克隆体的突变列表）。
- 总体时间复杂度约为 $O(N \times (G + M))$ ，在题目限制下（最多 $10$ 个突变基因）完全可行。

### 空间复杂度

- 需要存储所有克隆体的信息，每个克隆体存储其基因计数（映射大小最多为总基因数）。
- 最坏情况下，每个克隆体都有不同的突变基因，空间复杂度为 $O(N \times G)$ 。

## 代码实现

```cpp
// Adam's Gene
// UVa ID: 566
// Verdict: Accepted
// Submission Date: 2025-12-25
// UVa Run Time: 0.000s
//
// 版权所有（C）2025，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

struct Clone {
    string parent;                     // 父克隆体名称
    unordered_set<string> mutations;   // 本克隆体新增的突变基因
    vector<string> mutationOrder;      // 保持突变基因的顺序
    unordered_map<string, int> geneCount; // 从祖先继承的基因计数（包括自身）
    bool consistent;                   // 是否与ADAM相连
};

unordered_map<string, Clone> clones;   // 记录所有已处理的克隆体

// 检查克隆请求是否安全，返回首个出现两次的基因，若安全则返回空字符串
string checkSafety(const Clone& curr) {
    // 按照突变列表中出现的顺序检查每个基因
    for (const string& gene : curr.mutationOrder) {
        auto it = curr.geneCount.find(gene);
        if (it != curr.geneCount.end() && it->second >= 2) 
            return gene;
    }
    return "";
}

// 处理一个克隆请求
void processRequest(const string& line) {
    stringstream ss(line);
    string dummy, child, from, parent;
    ss >> dummy >> child >> from >> parent;

    // 解析突变基因，保持顺序
    vector<string> newMutationOrder;
    unordered_set<string> newMutations;
    string mutating;
    if (ss >> mutating && mutating == "mutating") {
        string gene;
        while (ss >> gene) {
            newMutationOrder.push_back(gene);
            newMutations.insert(gene);
        }
    }

    // 输出原始请求部分
    cout << "clone " << child << " from " << parent;

    // 如果父克隆体不存在或不一致，则子克隆也不一致
    if (parent != "ADAM" && !clones.count(parent)) {
        cout << " has no connection to ADAM\n";
        clones[child] = {parent, newMutations, newMutationOrder, {}, false};
        return;
    }

    Clone& parentClone = clones[parent];
    if (!parentClone.consistent) {
        cout << " has no connection to ADAM\n";
        clones[child] = {parent, newMutations, newMutationOrder, {}, false};
        return;
    }

    // 构建当前克隆体的基因计数
    Clone curr = {parent, newMutations, newMutationOrder, parentClone.geneCount, true};
    for (const string& gene : newMutationOrder) 
        curr.geneCount[gene]++;

    // 检查安全性 - 检查所有基因，不仅仅是新增的
    string unsafeGene = checkSafety(curr);
    if (!unsafeGene.empty()) {
        cout << " was at least twice mutated with " << unsafeGene << "\n";
        clones[child] = {parent, newMutations, newMutationOrder, {}, false}; // 不安全视为不一致
        return;
    }

    // 一致且安全
    cout << " is consistent and safe\n";
    clones[child] = curr;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    // 初始化ADAM
    clones["ADAM"] = {"", {}, {}, {}, true};

    string line;
    while (getline(cin, line)) 
        processRequest(line);

    return 0;
}
```

### 代码要点说明

1. **结构体设计** ：`Clone` 结构体包含了处理问题所需的所有信息，特别是 `mutationOrder` 用于保持基因顺序， `geneCount` 用于累积计数。

2. **输入解析** ：使用 `stringstream` 按空格分割输入，灵活处理有无 `mutating` 关键字的情况。

3. **一致性传播** ：通过检查父克隆体的 `consistent` 字段，实现了不一致性的 **传递性** 。

4. **安全性检查** ：`checkSafety` 函数按突变基因的输入顺序遍历，保证了输出的是 **第一个** 双突变基因。

5. **输出格式** ：严格按照题目要求输出，单词间一个空格，无多余空格。

## 总结

本题考察了 **动态数据结构的构建与维护** 、**状态传递** 和 **顺序敏感的处理逻辑** 。通过合理设计数据结构（使用 `unordered_map` 存储基因计数， `vector` 保持顺序）和分步骤处理（先检查一致性，再继承计数，最后检查安全性），我们能够高效地解决这个问题。关键点在于：

1. **理解一致性传播** ：不一致的克隆体使其所有后代都不一致。
2. **正确处理基因计数** ：需要从父克隆体继承并累加。
3. **按顺序检查安全性** ：输出第一个在突变列表中出现的双突变基因。

这类问题在生物信息学和版本控制系统中也有类似应用，核心思想是 **追踪依赖关系和状态累积** 。
