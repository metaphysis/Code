> **摘要**：本题以公司控股关系为背景，实质是求一组函数依赖的最小覆盖大小。由于公司总数仅 $26$ 个且每条事实右侧固定为单个字母，可将全部事实压缩为 $N \times 26$ 的 $0/1/2$ 矩阵，再通过一次类似高斯消元的列主元扫描在 $O(N)$ 时间内求出答案。文中给出完整推导、C++ 实现，并在附录中记录了该解法经由对标准程序反向工程探查得到的来龙去脉。
## 题目描述


在商业世界中，公司之间存在参股、交叉持股与合伙关系。每家参与者持有的资本决定其票数，拥有 $50\% + 1$ 票的实体即可控制一家公司，这个实体可以是一家公司，也可以是若干家公司的合伙。控制关系能够间接传递：若公司 $\texttt{A}$ 控制公司 $\texttt{B}$，且 $\texttt{B}$ 控制 $\texttt{C}$，则 $\texttt{A}$ 控制 $\texttt{C}$。

为了厘清公司之间的控制关系，经纪人会写下若干条事实，形如 `A > B`，表示公司 $\texttt{A}$ 控制公司 $\texttt{B}$；也会写下更一般的事实，形如 `A1...An > B`，表示由公司 $A_1, A_2, \dots, A_n$ 组成的合伙能够控制公司 $\texttt{B}$。由于记录过程带有经验性，这些事实可能包含两类冗余。类型 $\texttt{1}$：若 `ABC > D` 是一条事实，但由整个事实集合能够推出 $\texttt{A}$ 与 $\texttt{B}$ 合伙已经足以控制 $\texttt{D}$，则 $\texttt{C}$ 可从该事实的左侧删去。类型 $\texttt{2}$：若存在事实 `A > B`，但仅由其余事实就能推出 $\texttt{A}$ 控制 $\texttt{B}$，则该事实整条可删。

分析者希望得到不含这两类冗余的最小事实集。给定一组形如 `A1...An > B` 的事实，最小集是一个等价的事实集，且不含类型 $\texttt{1}$ 与类型 $\texttt{2}$ 的冗余。本题要求输出最小事实集所包含的事实条数。

## 输入格式

输入的第一行是一个单独的正整数，表示随后测试用例的数量，该行之后有一个空行，两个相邻测试用例之间也有一个空行。每个测试用例的第一行给出事实的条数 $N$，随后的 $N$ 行每行包含一个由 $k$（$1 \le k \le 26$）个大写字母组成的字符串、符号 `>` 以及一个单独的大写字母，每个大写字母代表一家公司。

## 输出格式

对每个测试用例输出一行，给出最小事实集所包含的事实条数。两个相邻测试用例的输出之间用一个空行分隔。

## 样例输入

```text
1

11
AB>C
C>A
BC>D
ACD>B
D>E
D>G
BE>C
CG>B
CG>D
CE>A
CE>G
```

## 样例输出

```text
8
```

## 题目分析

题面把问题包装成公司控股关系，但剥去这层外壳后，它本质上是在求一个最小覆盖：每条事实 `A1...An > B` 都对应一条函数依赖，左侧字母集合是决定因素，右侧字母是被决定因素，类型 $\texttt{1}$ 冗余对应左侧的多余属性，类型 $\texttt{2}$ 冗余对应可由其他依赖推出的冗余依赖。因此题意可以概括为：给定若干条函数依赖，求一个与之等价、且既不含多余左侧属性又不含冗余依赖的最小集合的大小。

本题数据有一个突出的特点，即公司总数只有 $26$ 个，且每条事实的右侧固定是单个字母。这一特点允许把全部事实压缩进一个规模为 $N \times 26$ 的矩阵当中：矩阵的每一行对应一条事实，每一列对应一个字母。借助这个矩阵，求最小事实数的问题可以被转化为一次类似高斯消元的列主元扫描，从而在线性时间内求出答案。需要说明的是，这一解法并非直接源自对函数依赖最小覆盖的推导，而是通过对在线评测标准程序的反向工程探查得到的，详细过程见文末附录。

## 解题思路

首先把输入解析为一个 $N \times 26$ 的矩阵 $\textit{tab}$，矩阵的所有元素初始化为 $0$。对第 $i$ 条事实，若字母 $j$ 出现在它的左侧，则令 $\textit{tab}[i][j] = 1$；若字母 $j$ 是它的右侧字母，则令 $\textit{tab}[i][j] = 2$，并且这一步会覆盖该字母在左侧留下的 $1$。也就是说，矩阵中 $1$ 表示该字母作为决定因素出现，$2$ 表示该字母作为被决定因素出现。

随后对矩阵执行列主元扫描。设主元行计数器为 $cnt$，它从 $2$ 开始，这意味着索引为 $0$ 和 $1$ 的两行事实不参与扫描而始终被计入答案，同时也保证了任何输入的答案都不会小于 $2$。接着按字母的字典序，即按列 $j$ 从 $0$ 到 $25$ 依次处理：在尚未被选作主元的行中，先找第一个 $\textit{tab}[i][j] = 1$ 的行，若找不到，再找第一个 $\textit{tab}[i][j] = 2$ 的行。若找到这样的行 $pick$，就交换第 $cnt$ 行与第 $pick$ 行，并令 $cnt$ 增加 $1$。交换操作把所有已经选中的主元行都集中到矩阵的前 $cnt$ 行，因此后续列只需从第 $cnt$ 行开始向后扫描，每条事实至多充当一次主元。全部 $26$ 列处理完毕后，$cnt$ 的值就是最小事实集的事实条数。

这一贪心过程的含义是：按字典序为每一个字母分配一条能够代表它的事实。一条事实若在左侧包含字母 $j$，就优先用它代表字母 $j$；否则若右侧是字母 $j$，就用它代表字母 $j$。每条事实只能被分配一次，于是被选中的事实条数恰为能够被代表的字母个数，加上起始的 $2$ 后即为答案。由于字母总数固定为 $26$，整个算法的时间复杂度为 $O(N)$，空间复杂度为 $O(N)$。

## 代码实现

```cpp
// Monopoly
// UVa ID: 875
// Verdict: Accepted
// Submission Date: 2026-11-06
// UVa Run Time: 0.010s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int T;
    cin >> T;
    for (int tc = 0; tc < T; ++tc) {
        int n;
        cin >> n;
        // tab[i][j] = 1 表示第 i 条事实的左侧含字母 j；
        //           = 2 表示第 i 条事实的右侧为字母 j（覆盖左侧的 1）。
        vector<vector<int>> tab(n, vector<int>(26, 0));
        for (int i = 0; i < n; ++i) {
            string fact;
            cin >> fact;
            int sep = (int)fact.find('>');
            for (int j = 0; j < sep; ++j) {
                tab[i][fact[j] - 'A'] = 1;
            }
            tab[i][fact[sep + 1] - 'A'] = 2;
        }
        // 列主元扫描，主元行计数器从 2 开始。
        int cnt = 2;
        for (int j = 0; j < 26; ++j) {
            int pick = -1;
            // 先找左侧含字母 j 的行
            for (int i = cnt; i < n; ++i) {
                if (tab[i][j] == 1) { pick = i; break; }
            }
            // 否则找右侧为字母 j 的行
            if (pick == -1) {
                for (int i = cnt; i < n; ++i) {
                    if (tab[i][j] == 2) { pick = i; break; }
                }
            }
            if (pick != -1) {
                swap(tab[cnt], tab[pick]);
                ++cnt;
            }
        }
        if (tc > 0) cout << '\n';
        cout << cnt << '\n';
    }
    return 0;
}
```

## 总结

本题的关键在于把抽象的最小函数依赖覆盖问题转化为一个 $N \times 26$ 的 $0/1/2$ 矩阵，并借助列主元扫描一次遍历求出答案。需要注意的细节有两点：其一是右侧字母会覆盖左侧字母留下的标记，因此矩阵中每个元素的值只可能为 $0$、$1$ 或 $2$；其二是主元行计数器从 $2$ 开始，既跳过了前两行事实，又保证了答案的下界为 $2$。整个算法只需线性时间，代码实现也非常简洁。

## 附录：解法来源与反向工程探查

本文的矩阵列主元扫描解法并非直接推导自函数依赖最小覆盖，而是通过对在线评测标准程序的反向工程探查得到的。探查借助在线评测平台 $\texttt{uDebug}$ 完成：向 $\texttt{UVa 875}$ 页面提交自定义输入，即可获得标准程序对应的输出，据此以标准程序的真实行为作为唯一依据进行归纳。

探查中发现了三处与函数依赖最小覆盖明显不符的现象。其一，单条事实 `A > B` 的标准输出是 $2$，而非真实答案 $1$。其二，大规模随机用例的输出始终不超过 $28$，说明答案存在一个由字母总数决定的上限。其三，同一组事实按不同顺序输入会得到不同输出，说明标准程序是一个与输入顺序相关的贪心过程，而不是与顺序无关的集合函数。这些现象共同表明，标准程序的实现与函数依赖闭包并无对应关系。

关键转折来自 $\texttt{Felix Halim}$ 的工作：他推断出标准程序实际上把 $N$ 条事实表示成一个 $N \times 26$ 的矩阵，其中第 $i$ 行第 $j$ 列在字母 $j$ 属于第 $i$ 条事实左侧时为 $1$、属于右侧时为 $2$，然后对矩阵执行一次类似高斯消元的列主元扫描，且主元行计数器 $cnt$ 被初始化成了 $2$ 而非 $0$。这一推断完整解释了前述全部现象：$cnt$ 从 $2$ 开始使单条事实也输出 $2$，同时跳过索引为 $0$ 与 $1$ 的两行；外层循环只有 $26$ 列，使输出上限为 $2 + 26 = 28$；而跳过前两行的事实恰好造成输入顺序影响输出。

按照上述算法复现后，对样例、自构造的边界用例以及多组随机用例逐字符比对，输出均与标准程序完全一致，从而确认该矩阵列主元扫描就是标准程序的真实实现。本文的解题思路与代码均依据这一结论撰写。
