[UVa 1033 Merging Maps](https://blog.csdn.net/metaphysis/article/details/162067121)

## 题目描述

给定若干张矩形地图，每张地图由字符矩阵表示，其中大写字母 `'A'` 到 `'Z'` 表示可识别的主要地物，连字符 `'-'` 表示该位置没有可识别地物。不同的字母代表不同的地物，相同的字母可能出现在多个位置（如同一条道路）。

现在需要将这些地图合并成一张完整的大地图。合并规则如下：

1. 两张地图可以通过重叠来合并，重叠时一张地图中的主要地物可以与另一张地图中的空地 `'-'` 重叠，但不能与不同的字母重叠。
2. 两张地图的匹配得分定义为：在最佳重叠方式下，重合的主要地物（即两张地图在该位置都有相同字母）的数量。
3. 每次选择当前序列中得分最高的地图对进行合并，如果得分相同，选择包含最小序列号地图的配对；如果同一配对有多种偏移方式达到相同得分，选择最小的行偏移，再选择最小的列偏移。
4. 合并后的地图赋予下一个更大的序列号，放回序列中。
5. 重复上述过程，直到只剩一张地图，或所有地图对的得分均为 $0$。

## 输入格式

输入包含多组测试数据，每组数据以一行整数 $N$（$2 \le N \le 10$）开头，表示该组中地图的数量。

接下来是 $N$ 张地图，每张地图以一行两个整数 $R$ 和 $C$（$1 \le R, C \le 10$）开头，分别表示该地图的行数和列数。随后 $R$ 行，每行包含 $C$ 个字符（只含大写字母和 `'-'`），表示地图数据。每行可能包含额外的尾部字符，应被忽略。

输入以一行 `0` 结束。

## 输出格式

对于每组测试数据，输出 `Case X:`（$X$ 从 $1$ 开始编号），然后按序列号升序输出所有最终剩余的地图。每张地图用边框包围，边框由 `+`、`-` 和 `|` 构成。同一测试用例中多张地图之间用一个空行分隔，不同测试用例之间也用一个空行分隔。

## 题目分析

本题的核心是模拟一个地图合并的迭代过程。每张地图可以看作一个二维字符矩阵，合并操作本质上是将两张地图按照某个偏移量重叠，生成一张更大的地图。

### 关键概念

**偏移量** $(r, c)$：表示地图 $b$ 相对于地图 $a$ 的行列偏移。具体而言，地图 $b$ 的左上角 $(0, 0)$ 对应地图 $a$ 的 $(r, c)$ 位置。

**匹配得分**：在给定偏移量下，两张地图重叠区域中，同为字母且相同的位置数量。如果存在同一位置字母不同，则该偏移量无效（冲突）。

**地图合并**：给定偏移量 $(r, c)$，将两张地图合并为一张新地图。新地图的大小为能容纳两张地图的最小矩形，重叠区域的字母以非 `'-'` 优先。

### 约束条件分析

由于 $N \le 10$，$R, C \le 10$，地图数量和尺寸都非常小，因此可以使用较为直接的模拟方法。每次合并时需要遍历所有地图对，计算它们的最佳匹配得分，然后选择得分最高的一对进行合并。

最直接的实现是每次合并时重新计算所有地图对的匹配得分，但由于最多 $10$ 张地图，每张地图最多 $100$ 个格子，计算量完全可接受。因此本题不需要复杂的缓存优化，直接计算即可。

### 匹配计算的关键优化

对于两张地图 $a$ 和 $b$，可能的偏移量数量为 $(R_a + R_b - 1) \times (C_a + C_b - 1)$，在最坏情况下约为 $19 \times 19 = 361$ 个。对于每张地图最多 $100$ 个格子，计算所有偏移量的复杂度约为 $361 \times 100 = 36100$ 次操作，完全可以接受。

但可以进一步优化：只有两张地图存在相同字母时，才可能有正得分。因此，只需枚举两张地图中相同字母的位置对作为候选偏移量。这在大幅减少枚举量的同时，保证了不会遗漏任何可能产生得分的偏移量。

## 解题思路

### 整体框架

1. 读入一组地图数据。
2. 初始化地图序列，每张地图赋予唯一的序列号。
3. 循环执行合并操作，直到只剩一张地图或没有可合并的地图对：
   - 遍历所有地图对，计算每对的最佳匹配得分。
   - 找到得分最高的地图对（得分相同则按序列号最小的地图优先）。
   - 如果最高得分为 $0$，终止合并。
   - 合并选中的两张地图，生成新地图，分配下一个序列号。
   - 从序列中移除被合并的两张地图，加入新地图。
4. 按序列号升序输出最终剩余的地图。

### 匹配得分计算

对于给定的两张地图 $a$ 和 $b$，以及偏移量 $(r, c)$：

- 遍历 $a$ 中所有非 `'-'` 的位置 $(i, j)$。
- 计算其在 $b$ 中的对应位置 $(i - r, j - c)$。
- 如果该位置超出 $b$ 的范围或 $b$ 中为 `'-'`，则忽略。
- 如果 $b$ 中对应位置为不同字母，则返回 $-1$（冲突）。
- 如果字母相同，得分加 $1$。

### 候选偏移量生成

为了只枚举可能产生正得分的偏移量，采用如下策略：

1. 遍历 $a$ 中所有非 `'-'` 的位置 $(i, j)$。
2. 遍历 $b$ 中所有非 `'-'` 的位置 $(x, y)$。
3. 如果两个位置的字母相同，则生成候选偏移量 $(i - x, j - y)$。
4. 检查该偏移量是否在合法范围内（即两张地图至少有一个位置重叠）。
5. 对每个候选偏移量计算匹配得分，选择得分最高的偏移量作为最佳匹配。

这种方法直接利用双重循环比较两个矩阵中的字符，只有相同字符的位置才会生成候选偏移量，避免了盲目枚举所有可能的偏移量。

### 合并操作

给定两张地图 $a$ 和 $b$ 以及偏移量 $(r, c)$：

1. 计算新地图的范围：
   - 行范围：$\min(0, r)$ 到 $\max(a_{rows} - 1, b_{rows} - 1 + r)$
   - 列范围：$\min(0, c)$ 到 $\max(a_{cols} - 1, b_{cols} - 1 + c)$
2. 创建新地图，所有位置初始化为 `'-'`。
3. 将 $a$ 的所有非 `'-'` 字符复制到新地图的对应位置。
4. 将 $b$ 的所有非 `'-'` 字符复制到新地图的对应位置（加上偏移量 $(r, c)$）。

### 数据结构设计

使用两个队列管理地图：

- `maps`：存储所有生成的地图（包括已合并的），索引从 $1$ 开始。
- `q`：存储当前活动地图的序号对 `(地图序列号, maps中的索引)`。

合并时，从 `q` 中移除被合并地图的条目，将新地图追加到 `maps` 末尾，并将新条目加入 `q`。这种方式避免了频繁删除 `vector` 中的元素，操作更高效。

### 复杂度分析

- 每张地图最大 $10 \times 10 = 100$ 个格子。
- 候选偏移量最多为 $100 \times 100 = 10000$ 个，但去重后最多 $19 \times 19 = 361$ 个。
- 每次合并需要遍历所有地图对，最多 $45$ 对。
- 每次匹配计算最多 $361 \times 100 = 36100$ 次操作。
- 总合并次数最多 $N - 1 \le 9$ 次。
- 总时间复杂度：$O(N^2 \cdot R \cdot C \cdot (R + C))$，在给定约束下完全可以接受。
- 空间复杂度：$O(N \cdot R \cdot C)$，用于存储地图数据。

// Merging Maps

// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

struct Map { int id, nr, nc; vector<string> g; };
struct Match { int s, r, c; bool ok; };

int getScore(const Map& a, const Map& b, int r, int c) {
    int s = 0;
    for (int i = 0; i < a.nr; ++i)
        for (int j = 0; j < a.nc; ++j) {
            if (a.g[i][j] == '-') continue;
            int x = i - r, y = j - c;
            if (x < 0 || x >= b.nr || y < 0 || y >= b.nc || b.g[x][y] == '-') continue;
            if (a.g[i][j] != b.g[x][y]) return -1;
            ++s;
        }
    return s;
}

Map merge(const Map& a, const Map& b, int r, int c, int id) {
    int minR = min(0, r), maxR = max(a.nr - 1, b.nr - 1 + r);
    int minC = min(0, c), maxC = max(a.nc - 1, b.nc - 1 + c);
    Map map{id, maxR - minR + 1, maxC - minC + 1,
            vector<string>(maxR - minR + 1, string(maxC - minC + 1, '-'))};
    for (int i = 0; i < a.nr; ++i)
        for (int j = 0; j < a.nc; ++j)
            if (a.g[i][j] != '-') map.g[i - minR][j - minC] = a.g[i][j];
    for (int i = 0; i < b.nr; ++i)
        for (int j = 0; j < b.nc; ++j)
            if (b.g[i][j] != '-') map.g[i + r - minR][j + c - minC] = b.g[i][j];
    return map;
}

Match getBestMatch(const Map& a, const Map& b) {
    Match best{0, 0, 0, false};
    for (int i = 0; i < a.nr; ++i)
        for (int j = 0; j < a.nc; ++j) {
            if (a.g[i][j] == '-') continue;
            for (int x = 0; x < b.nr; ++x)
                for (int y = 0; y < b.nc; ++y) {
                    if (b.g[x][y] == '-' || a.g[i][j] != b.g[x][y]) continue;
                    int r = i - x, c = j - y;
                    if (r >= -(b.nr - 1) && r <= a.nr - 1 && c >= -(b.nc - 1) && c <= a.nc - 1) {
                        int s = getScore(a, b, r, c);
                        if (s > best.s || (s == best.s && (r < best.r || (r == best.r && c < best.c))))
                            best = {s, r, c, true};
                    }
                }
        }
    return best;
}

void print(const Map& m) {
    cout << "    MAP " << m.id << ":\n    +" << string(m.nc, '-') << "+\n";
    for (auto& row : m.g) cout << "    |" << row << "|\n";
    cout << "    +" << string(m.nc, '-') << "+\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, cs = 0;
    while (cin >> n && n) {
        if (cs) cout << '\n';
        vector<Map> maps(1);
        for (int i = 1; i <= n; ++i) {
            Map m{i, 0, 0, {}};
            cin >> m.nr >> m.nc;
            m.g.resize(m.nr);
            cin.ignore(128, '\n');
            for (int r = 0; r < m.nr; ++r) {
                string line;
                getline(cin, line);
                m.g[r] = line.substr(0, m.nc);
            }
            maps.push_back(m);
        }
        vector<pair<int, int>> q;
        for (int i = 1; i <= n; ++i) q.push_back({i, i});
        for (int nxt = n + 1; q.size() > 1; ++nxt) {
            int bs = -1, bi = -1, bj = -1, br = 0, bc = 0;
            for (int i = 0; i < (int)q.size(); ++i)
                for (int j = i + 1; j < (int)q.size(); ++j) {
                    Match m = getBestMatch(maps[q[i].second], maps[q[j].second]);
                    if (!m.ok || m.s == 0) continue;
                    int curMin = min(q[i].first, q[j].first);
                    int bestMin = (bi == -1) ? INT_MAX : min(q[bi].first, q[bj].first);
                    if (m.s > bs || (m.s == bs && (curMin < bestMin ||
                        (curMin == bestMin && max(q[i].first, q[j].first) < max(q[bi].first, q[bj].first))))) {
                        bs = m.s; bi = i; bj = j; br = m.r; bc = m.c;
                    }
                }
            if (bs == -1 || bi == -1) break;
            Map merged = merge(maps[q[bi].second], maps[q[bj].second], br, bc, nxt);
            maps.push_back(merged);
            int newIdx = maps.size() - 1;
            vector<pair<int, int>> ns;
            for (int i = 0; i < (int)q.size(); ++i)
                if (i != bi && i != bj) ns.push_back(q[i]);
            ns.push_back({nxt, newIdx});
            q = ns;
        }
        cout << "Case " << ++cs << '\n';
        for (int i = 0; i < (int)q.size(); ++i) {
            if (i) cout << '\n';
            print(maps[q[i].second]);
        }
    }
    return 0;
}

## 总结

本题是一道典型的模拟题，核心难点在于正确实现地图的匹配、合并和迭代选择逻辑。关键技巧包括：

1. **候选偏移量优化**：只枚举相同字母的位置对作为候选偏移量，避免盲目枚举所有可能的偏移量，大幅提升匹配计算效率。

2. **队列管理**：使用 `q` 存储当前活动地图的序号和索引，合并时只需删除和追加条目，避免了频繁的 `vector` 元素删除操作。

3. **平局处理**：严格按照题目要求处理得分相同、序列号相同等平局情况，确保输出结果与标准答案一致。

4. **输入处理**：注意每行可能包含额外字符，需要使用 `substr(0, m.nc)` 截取前 $C$ 个字符并忽略其余内容。

本题的数据规模较小，使得较为直接的模拟方法足以通过。由于地图数量最多 $10$ 张，每张最多 $10 \times 10$ 个格子，无需复杂的缓存优化即可在限定时间内完成计算。
