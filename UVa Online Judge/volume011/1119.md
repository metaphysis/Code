## 题目描述

项目经理工具（如 $\texttt{UNIX}$ 中的 `make` ）用于维护由许多组件构成的大型软件项目。用户编写一个**项目文件** ，指定哪些组件（称为**任务** ）依赖于其他组件，项目经理可以按照正确的顺序自动更新这些组件。

请编写一个程序，读取项目文件并输出任务应被执行的顺序。

### 输入格式

输入以一个单独的正整数开始，表示接下来的测试用例数量。每个测试用例描述如下。该行之后有一个空行，且两个连续测试用例之间也有一个空行。

为简单起见，每个任务用一个整数 $1, 2, \ldots, N$ 表示（其中 $N$ 是任务总数）。  
输入的第一行给出任务数量 $N$ 和规则数量 $M$ ，满足 $N \leq 100$ ， $M \leq 100$ 。

接下来的 $M$ 行是**规则** ，每行一个，语法如下：  
$T_0 \quad k \quad T_1 \quad T_2 \quad \ldots \quad T_k$  
这个规则表示任务 $T_0$ 依赖于 $k$ 个任务 $T_1, T_2, \ldots, T_k$ （ $T_0$ 称为**目标** ， $T_1 \ldots T_k$ 称为**依赖项** ）。

任务编号之间用单个空格分隔，规则以换行结束。规则可以以任意顺序出现，但每个任务只能作为目标出现一次。

你可以假设规则中**不存在循环依赖** ，即没有任务直接或间接依赖于自身。

### 输出格式

对于每个测试用例，输出必须遵循以下描述。两个连续测试用例的输出之间用一个空行分隔。

输出应为一行，给出任务 $1 \ldots N$ 的一个排列，按照依赖关系排序（即一个任务不能出现在它所依赖的任务之前）。为了避免输出歧义，互相之间没有依赖关系的任务应按编号从小到大排序。

### 样例输入

```
1

5 4
3 2 1 5
2 2 5 3
4 1 3
5 1 1
```

### 样例输出

```
1 5 3 2 4
```

## 题目分析

### 问题本质

这是一个典型的**拓扑排序** 问题：
- 每个任务对应图中的一个节点。
- 依赖关系 “任务 $T_0$ 依赖于任务 $T_1$ ” 可以表示为一条从 $T_1$ 指向 $T_0$ 的有向边。
- 要求输出的任务顺序就是该有向无环图的一个拓扑排序。
- 当存在多个合法的拓扑排序时，题目要求按任务编号的升序输出，这相当于在所有可能的拓扑序中，取**字典序最小**的一个。

### 为什么是拓扑排序？

拓扑排序适用于**有向无环图** （ $\texttt{DAG}$ ），它给出一个节点的线性序列，使得对于图中的每一条有向边 $u \to v$ ，节点 $u$ 都出现在节点 $v$ 之前。这与本题的要求完全一致：如果一个任务依赖于另一个任务（即存在依赖关系 $T_1 \to T_0$ ），那么 $T_1$ 必须在 $T_0$ 之前执行。题目明确保证没有循环依赖，因此图一定是 $\texttt{DAG}$ 。

### 算法选择

常见的拓扑排序算法有两种：
1. **$\texttt{Kahn}$ 算法（基于入度）** ：不断移除入度为 $0$ 的节点，并更新其邻接节点的入度。
2. **基于 $\texttt{DFS}$ 的算法** ：通过深度优先遍历进行后序遍历，再反转得到拓扑序。

本题要求当多个节点可选时按编号升序输出，这提示我们使用 **$\texttt{Kahn}$ 算法配合最小堆** ：
- 使用一个最小优先队列（ $\texttt{min-heap}$ ）来存储当前所有入度为 $0$ 的节点。
- 每次从堆中取出编号最小的节点加入结果序列。
- 然后将其所有邻接节点的入度减 $1$ ，如果某个邻接节点的入度变为 $0$ ，则将其加入堆中。
- 重复上述过程直到堆为空。

这种方法的正确性在于：每次选择当前可执行任务中编号最小的那个，从而保证了最终拓扑序的字典序最小性。
### 复杂度分析

- 时间复杂素： $O((N+M)\log N)$ ，其中 $N$ 为节点数，$M$ 为边数。每个节点和边被处理一次，堆操作为 $O(\log N)$ 。
- 空间复杂度： $O(N+M)$ ，用于存储图和辅助数据结构。

```cpp
// Project File Dependencies

#include <bits/stdc++.h>
using namespace std;

int main() {
    int caseCount;
    cin >> caseCount; // 读取测试用例数量
    for (int caseIndex = 0; caseIndex < caseCount; ++caseIndex) {
        if (caseIndex > 0) cout << endl; // 测试用例之间输出空行
        int n, m;
        cin >> n >> m; // 读取任务数量和规则数量
        vector<vector<int>> graph(n + 1); // 邻接表，graph[i] 存储任务 i 依赖的所有任务
        vector<int> indegree(n + 1, 0);   // 入度数组
        // 读取每条规则
        for (int i = 0; i < m; ++i) {
            int target, k;
            cin >> target >> k;
            for (int j = 0; j < k; ++j) {
                int dep;
                cin >> dep;
                graph[dep].push_back(target); // 依赖指向目标：dep -> target
                indegree[target]++;
            }
        }
        // 最小堆，用于保证编号小的任务优先输出
        priority_queue<int, vector<int>, greater<int>> pq;
        // 将所有入度为 0 的任务加入堆
        for (int i = 1; i <= n; ++i)
            if (indegree[i] == 0) pq.push(i);
        vector<int> result;
        // 拓扑排序
        while (!pq.empty()) {
            int cur = pq.top();
            pq.pop();
            result.push_back(cur);
            // 遍历当前任务指向的所有目标任务
            for (int neighbor : graph[cur]) {
                indegree[neighbor]--;
                if (indegree[neighbor] == 0) pq.push(neighbor);
            }
        }
        // 输出结果
        for (size_t i = 0; i < result.size(); ++i) {
            if (i) cout << ' ';
            cout << result[i];
        }
        cout << '\n';
    }
    return 0;
}
```

### 代码说明

1. **图的存储** ：使用邻接表 `graph` ， `graph[dep]` 存储所有依赖于 `dep` 的任务（即从 `dep` 出发能到达的节点）。
2. **入度数组** ： `indegree[i]` 表示有多少个任务必须在任务i之前执行。
3. **最小堆** ：使用 `priority_queue` 配合 `greater<int>` 比较器实现最小堆，确保每次取出的都是当前可执行任务中编号最小的。
4. **拓扑排序过程** ：标准的 $\texttt{Kahn}$ 算法，但使用最小堆来选择下一个要处理的任务。
5. **输出格式处理** ：注意测试用例之间的空行，以及输出序列中数字之间的空格。

### 关键点

- 边的方向：从依赖项指向目标。
- 使用最小堆保证在多个可执行任务中选择编号最小的。
- 题目保证无环，所以最终结果一定包含所有 $N$ 个任务。
