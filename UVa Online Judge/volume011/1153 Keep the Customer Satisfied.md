
> **摘要**：本文讨论钢铁公司订单调度问题：每份订单有生产时间 $q$ 与交货期限 $d$，需在满足交货期限的前提下最大化接受订单数量。文章先通过交换论证证明按交货期限排序生产即可，再给出基于大根堆的贪心策略——超时时删除已接受订单中生产时间最长的一份，并附交换论证的正确性证明与复杂度分析，最终以 $O(n \log n)$ 时间、$O(n)$ 空间解决 $n \le 800000$ 的大规模数据。

 # 题目描述

一家钢铁公司需要安排下一个生产周期的订单。每份订单包含钢材需求量 $q$ 和交货期限 $d$，生产 $q$ 吨钢材恰好需要 $q$ 秒。生产从时刻 $0$ 开始，生产线同一时刻只能处理一份订单，接受的订单必须在各自的交货期限之前或恰好在交货期限时完成。

公司能够拒绝部分订单，并自行决定接受订单的生产顺序。要求在满足所有接受订单的交货期限的前提下，使接受的订单数量最多。只需输出最多接受的订单数量，无需输出具体生产安排。

# 输入格式

第一行包含一个正整数 $T$，表示测试用例数量。此后给出 $T$ 组测试数据，测试用例数量之后以及相邻测试用例之间存在空行。

每组测试数据的第一行包含一个整数 $n$，表示订单数量，其中 $n \le 800000$。接下来的 $n$ 行，每行包含两个整数 $q$ 和 $d$，分别表示该订单需要生产的钢材数量和交货期限，其中 $q < 1000$，$d < 2 \times 10^6$。

# 输出格式

对于每组测试数据，输出一行，包含一个整数，表示最多能够接受的订单数量。相邻测试用例的输出之间保留一个空行。

# 样例输入

```text
1

6
7 15
8 20
6 8
4 9
3 21
5 22
```

# 样例输出

```text
4
```

# 题目分析

每份订单的生产时间等于其钢材需求量，因此本题转化为单条生产线上的带截止时间任务选择问题：从所有任务中选择尽量多的任务，使它们都能够按时完成。所有订单从时刻 $0$ 起均可安排生产，空闲时间只会推迟后续订单的完成时间，因此安排接受的订单时无需保留空闲时间。

首先确定生产顺序。对于相邻的两份订单，设它们的生产时间分别为 $q_a$、$q_b$，交货期限满足 $d_a > d_b$，但订单 $a$ 被安排在订单 $b$ 之前。设这两份订单开始前已经生产了 $t$ 秒，原安排可行意味着 $t + q_a + q_b \le d_b$。交换它们后，订单 $b$ 的完成时间为 $t + q_b \le d_b$，订单 $a$ 的完成时间为 $t + q_b + q_a \le d_b < d_a$，后续订单的完成时间保持不变。因此，交换这类相邻逆序订单不会破坏可行性，反复交换后便得到按照交货期限非递减排列的可行安排。由此可知，只需在按照交货期限排序的订单序列中选择订单。

设排序后的订单为 $(q_i,d_i)$，当前已经接受的订单总生产时间为 $s$。处理订单 $i$ 时，若 $s + q_i \le d_i$，直接接受它即可；否则，当前接受的订单与订单 $i$ 无法全部保留。由于目标是最大化订单数量，每份订单对答案的贡献相同，此时应当从这些订单中删除生产时间最长的一份，使保留订单占用的总时间最少，为后续订单留下更多生产时间。使用大根堆维护已接受订单的生产时间，就能快速找到需要比较和删除的最长订单。

样例中，按交货期限排序后的订单依次为 $(6,8)$、$(4,9)$、$(7,15)$、$(8,20)$、$(3,21)$、$(5,22)$。首先接受生产时间为 $6$ 的订单，随后加入生产时间为 $4$ 的订单会超过期限 $9$，因此用后者替换前者，总生产时间降为 $4$。继续接受生产时间为 $7$、$8$ 的订单后，总生产时间为 $19$；加入生产时间为 $3$ 的订单会超过期限 $21$，因此删除生产时间为 $8$ 的订单，总生产时间降为 $14$。最后接受生产时间为 $5$ 的订单，总生产时间为 $19$，最终接受 $4$ 份订单。

# 解题思路

先按照交货期限从小到大排序；交货期限相同时，按照生产时间从小到大排序。使用大根堆保存当前接受的订单生产时间，并用 $s$ 维护这些订单的总生产时间。初始时堆为空，$s = 0$。

依次处理每份订单。若 $s + q_i \le d_i$，则将其生产时间加入大根堆，并令 $s \leftarrow s + q_i$。若直接接受会超时，且堆非空，记堆顶的生产时间为 $L$；当 $q_i < L$ 且 $s - L + q_i \le d_i$ 时，删除堆顶并加入当前订单，同时令 $s \leftarrow s - L + q_i$。其余情况直接拒绝当前订单。遍历结束后，堆中的订单数量就是答案。

这一过程等价于“先加入当前订单，若超时则删除最长订单”。当前订单比堆顶订单更短时，删除堆顶；当前订单不比堆顶订单短时，直接删除刚加入的当前订单。超时时只需删除一份订单：加入当前订单之前有 $s \le d_i$，而待删除的最长订单满足 $L \ge q_i$，因此删除后有
$$
s + q_i - L \le s \le d_i.
$$
对于替换操作，加入当前订单前的 $s$ 不超过此前处理订单的交货期限，而交货期限已经非递减排序，因此同样有 $s \le d_i$。当 $q_i < L$ 时，替换后的总生产时间小于原来的 $s$，自然满足当前交货期限。给出的代码保留了这一可行性检查。

下面证明删除最长订单能够保持最优答案。将已经被贪心删除的订单排除后，考虑剩余订单按交货期限排列的序列。当扫描首次遇到不可行前缀时，记该前缀的订单集合为 $P$，末尾订单为 $i$，其中生产时间最长的订单为 $m$。此前的所有前缀均可行，而 $P$ 中全部订单的总生产时间超过 $d_i$，所以任何可行方案都必须拒绝 $P$ 中至少一份订单。删除 $m$ 后，如果 $m$ 就是订单 $i$，剩余前缀恢复为此前的可行前缀；如果 $m$ 位于订单 $i$ 之前，删除它不会增加任何较早订单的完成时间，而且由于 $q_m \ge q_i$，订单 $i$ 的完成时间也不超过加入它之前的总生产时间。因此，$P$ 删除 $m$ 后整体可行。

考虑一个不包含此前已删除订单的最优方案。如果该方案已经拒绝 $m$，则本次删除与这个最优方案一致；否则，该方案必定拒绝了 $P$ 中另一份订单 $x$。将方案中的 $m$ 替换为 $x$，接受的订单数量不变。替换后，在前缀 $P$ 中接受的订单构成 $P$ 删除 $m$ 后的一个子集，因此仍然可行；在 $P$ 之后，由于 $q_x \le q_m$，累计生产时间不会增加，因此后续订单仍然按时完成。于是，始终存在一个最优方案同时拒绝此前删除的订单和本次删除的最长订单。反复应用这一交换论证，最终贪心保留的订单集合可行，并且其数量达到最优。

排序需要 $O(n \log n)$ 时间，每份订单至多执行常数次堆操作，所有堆操作合计需要 $O(n \log n)$ 时间，因此每组测试数据的时间复杂度为 $O(n \log n)$。订单数组与大根堆均需要 $O(n)$ 存储空间，因此空间复杂度为 $O(n)$。

# 代码实现

```cpp
// Keep the Customer Satisfied

#include <bits/stdc++.h>

using namespace std;

const int MAXN = 800010;

struct order { int q, d; } o[MAXN];

bool cmp(order a, order b)
{
    if (a.d != b.d) return a.d < b.d;
    return a.q < b.q;
}

int main(int argc, char *argv[])
{
    cin.tie(0), cout.tie(0), ios::sync_with_stdio(false);
    int cases; cin >> cases;
    while (cases--)
    {
        int n; cin >> n;
        for (int i = 0; i < n; i++) cin >> o[i].q >> o[i].d;
        sort(o, o + n, cmp);
        int tons = 0;
        priority_queue<int> pq;
        for (int i = 0; i < n; i++)
        {
            if (tons + o[i].q <= o[i].d)
            {
                tons += o[i].q;
                pq.push(o[i].q);
            }
            else
            {
                if (!pq.empty())
                {
                    if (o[i].q < pq.top() && tons - pq.top() + o[i].q <= o[i].d)
                    {
                        tons = tons - pq.top() + o[i].q;
                        pq.pop(); pq.push(o[i].q);
                    }
                }
            }
        }
        cout << pq.size() << '\n';
        if (cases) cout << '\n';
    }
    return 0;
}
```

# 总结

本题的关键是先通过交换论证确定按照交货期限安排生产，再在出现超时时删除当前候选订单中生产时间最长的一份。交货期限排序保证了逐个检查的有效性，大根堆则支持快速调整已接受的订单集合。对于每份订单价值相同、生产时间不同且具有交货期限的任务选择问题，这种允许替换先前选择的贪心策略能够最大化按时完成的任务数量，并将时间复杂度控制在 $O(n \log n)$。
