### 问题描述

立方体工厂有限公司销售一种时髦的商品，名为 **$\texttt{hcubes}$** 。老板 $\texttt{Tesseract}$ 先生购买了一个大仓库来存放它们。然而，他有独特的堆放癖好：只允许两种堆放方式：
1.  **立方体堆** ：堆放成一个大的立方体，其包含的 $\texttt{hcubes}$ 数量为 $i^3$ ，其中 $i$ 是正整数。
2.  **平方金字塔堆** ：堆放成一个金字塔，其每一层是一个正方形，从顶层到底层，第 $k$ 层包含 $k^2$ 个 $\texttt{hcubes}$。因此，一个高度为 $i$ 的金字塔包含 $1^2 + 2^2 + ... + i^2$ 个 $\texttt{hcubes}$。

给定 $N$ 个 $\texttt{hcubes}$，目标是找到按照上述规则堆放它们所需的 **最少堆数** 。每种类型的堆可以创建任意多个。

**输入** ：多行，每行一个整数 $N$ （ $0 \le N \le 400000$ ），以 `-1` 表示输入结束。

**输出** ：对于每个 $N$ ，输出对应的最少堆数。

### 样例分析

**样例输入**：
```
38
60
12
39101
-1
```

**样例输出**：
```
2
2
4
4
```

以 $N = 38$ 为例，最少需要 $2$ 堆。一种可行的方案是：一堆高度为 $4$ 的金字塔（包含 $1^2+2^2+3^2+4^2 = 30$ 个）和一堆高度为 $2$ 的立方体（包含 $2^3 = 8$ 个），总共 $30+8=38$ 个。

### 题目分析与解题思路

#### 1. 问题本质

这是一个 **组合优化问题** 。我们需要用两种特定类型的“物品”（立方体堆和金字塔堆）来恰好“装满”一个容量为 $N$ 的“背包”，并且要求使用的“物品”数量最少。

关键点在于：
*   **物品类型** ：不是固定的，而是所有可能的立方数（ $i^3$ ）和所有可能的金字塔数（ $\sum_{k=1}^{i} k^2$ ）。
*   **物品数量** ：每种类型的堆可以无限次使用（因为只要 $N$ 足够大，你可以建多个同样大小的立方体或金字塔）。
*   **目标** ：最小化物品（堆）的数量。

这完美契合了 **完全背包问题（$\texttt{Unbounded Knapsack Problem}$）** 的模型，其中“价值”是堆的数量（我们想最小化它，通常设为 $1$ ），“重量”是堆所包含的 $\texttt{hcubes}$ 数量。

#### 2. 解题步骤

**第一步：预处理所有可能的“物品”**

我们需要生成所有可能被用到的堆的容量（即 $\texttt{hcubes}$ 数量）。

*   **立方体堆容量** ：遍历 $i$ 从 $1$ 开始，计算 $i^3$ ，直到其值超过 $N$ 的最大值 $400000$ 。
    *   计算： `cube = i * i * i` 。
*   **金字塔堆容量** ：遍历 $i$ 从 $1$ 开始，利用平方和公式计算 $1^2+2^2+...+i^2 = \frac{i(i+1)(2i+1)}{6}$ ，直到其值超过 $400000$ 。
    *   计算： `pyramid = i * (i + 1) * (2 * i + 1) / 6` 。

将这些容量值分别存入两个列表（例如 `cubes` 和 `pyramids` ）中。

**第二步：动态规划求解**

定义状态 $dp[x]$ ：表示 **恰好** 堆放 $x$ 个 $\texttt{hcubes}$ 所需的最少堆数。我们的目标是 $dp[N]$ 。

*   **初始状态** ： $dp[0] = 0$ （堆放 $0$ 个当然需要 $0$ 堆）。对于 $x > 0$ ， $dp[x] = \infty$ （初始化为一个极大值，表示暂时无法达到）。
*   **状态转移方程** ：对于每一种可能的堆容量 `num` （来自 `cubes` 或 `pyramids` 列表），我们考虑用它来更新所有更大的容量。
    *   对于容量 `j` 从 `num` 到 $MAX_N$ （ $400000$ ）：
    *   如果 $dp[j - num] \ne \infty$ （即 $j-num$ 这个状态是可达的），那么我们可以通过先在 $j-num$ 的基础上再加一堆容量为 `num` 的堆，来达到状态 $j$ 。
    *   因此，状态转移为： $dp[j] = \min(dp[j], dp[j - num] + 1)$ 。这里的 $+1$ 表示增加了一堆。
*   **遍历顺序** ：由于每种堆可以无限使用，这正是一个完全背包问题。在代码实现时，对于每个 `num` ，我们正序遍历 `j` 从 `num` 到 $MAX_N$ ，这样 `num` 就可以被重复使用。
*   **执行顺序** ：我们可以先遍历所有立方体堆，再遍历所有金字塔堆（或者反过来，或者合并遍历），因为动态规划的过程会综合考虑所有可能性。

**第三步：查询与输出**

在预处理阶段，我们已经一次性计算出了 $dp[0]$ 到 $dp[400000]$ 的所有结果。对于每个输入的 $N$ ，只需直接输出 $dp[N]$ 即可，查询时间复杂度为 $O(1)$ ，非常高效。

#### 3. 复杂度分析

*   **时间复杂度** ：
    *   预处理生成物品列表： $O(\sqrt[3]{MAX_N}) + O(\sqrt{MAX_N})$ ，非常小。
    *   动态规划：外层循环遍历物品（物品总数 $M$ 大约几百个），内层循环遍历容量（ $MAX_N+1$ 次）。总时间复杂度为 $O(M \cdot MAX_N)$ 。在本题 $MAX_N = 400000$ 的条件下， $M$ 较小，可以在合理时间内完成（通常 $1$ 秒内）。
    *   查询： $O(1)$ 每项。
*   **空间复杂度** ： $O(MAX_N)$ ，用于存储 $dp$ 数组。

```cpp
// Cubes Squared
// UVa ID: 1158

// UVa Run Time: 0.030s

// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

const int MAX_N = 400000;
const int INF = 1e9;

vector<int> cubes;       // 所有立方数（i³）
vector<int> pyramids;    // 所有平方金字塔数（1²+2²+...+i²）
int dp[MAX_N + 1];       // dp[x] 表示堆放 x 个 hcube 所需的最少堆数

// 预处理所有可能的立方数和平方金字塔数
void preprocess() {
    // 立方数：i³ ≤ MAX_N
    for (int i = 1; i * i * i <= MAX_N; i++) cubes.push_back(i * i * i);
    // 平方金字塔数：1²+2²+...+i² ≤ MAX_N
    for (int i = 1; i * i <= MAX_N; i++) {
        int sum = i * (i + 1) * (2 * i + 1) / 6;  // 平方和公式
        if (sum > MAX_N) break;
        pyramids.push_back(sum);
    }
    // 初始化 dp 数组为无穷大
    fill(dp, dp + MAX_N + 1, INF);
    dp[0] = 0;  // 堆放 0 个 hcube 需要 0 堆
    // 完全背包动态规划
    for (int num : cubes)
        for (int j = num; j <= MAX_N; j++)
            if (dp[j - num] != INF) dp[j] = min(dp[j], dp[j - num] + 1);
    for (int num : pyramids)
        for (int j = num; j <= MAX_N; j++)
            if (dp[j - num] != INF) dp[j] = min(dp[j], dp[j - num] + 1);
}

int main() {
    preprocess();  // 预处理所有结果
    int n;
    while (cin >> n and n != -1) cout << dp[n] << endl;
    return 0;
}
```
