
> **摘要**：本题将每种化合物视为顶点、每个结合对视为无向边，把“爆炸组合”等价转化为图中存在环。由于已接收的边必须始终构成森林，判断新结合对是否拒绝只需检查两端点是否已连通。文章给出并查集（路径压缩 + 按大小合并）的建模与实现，时间复杂度 $O(U + m\alpha(U))$。

 # 题目描述

若干种简单化合物能够组成不同的结合对，每个结合对恰好包含两种不同的简单化合物。当 $N > 2$ 时，将包含 $N$ 种简单化合物的 $N$ 个不同结合对混合，就会产生爆炸。

现在需要按照接收顺序，将结合对依次装入货船。每次收到一个结合对时，若它与已经接收的某些结合对能够组成爆炸组合，就必须拒绝接收；否则必须接收。被拒绝的结合对不会进入货船，也不会影响后续判断。

给定结合对的接收顺序，求被拒绝的结合对总数。

# 输入格式

输入包含多组测试数据，相邻测试数据之间以一个空行分隔。

每组数据包含若干行，每行给出两个整数 $a$ 和 $b$，表示由这两种简单化合物组成的一个结合对，其中 $0 \le a,b \le 10^5$，且 $a \ne b$。

每组数据以单独一行的 $-1$ 结束。输入中不存在重复的结合对，全部输入以文件结束标志结束。

# 输出格式

对于每组测试数据，输出一行，表示被拒绝的结合对总数。

# 样例输入

```text
1 2
3 4
3 5
3 1
2 3
4 1
2 6
6 5
-1
```

# 样例输出

```text
3
```

# 题目分析

将每一种简单化合物看作一个顶点，将每一个结合对看作连接对应两个顶点的一条无向边。由于结合对中的两种化合物不同，且输入中不存在重复的结合对，因此得到的是没有自环和重边的无向图。题目中的爆炸组合对应于选出 $N$ 条边，并且这些边的端点恰好包含 $N$ 个不同顶点，其中 $N > 2$。

这一条件与图中存在环等价。首先，一个长度为 $k$ 的简单环恰好包含 $k$ 个顶点和 $k$ 条边，而无自环、无重边保证 $k \ge 3$，因此环上的结合对构成爆炸组合。反过来，若选出的 $N$ 条边涉及 $N$ 个顶点，但这些边不包含环，那么它们组成森林。设该森林包含 $c$ 个连通分量，则边数应为 $N-c$，其中 $c \ge 1$，所以边数严格小于 $N$，与选出了 $N$ 条边矛盾。因此，只要出现符合题意的爆炸组合，图中就一定存在环。

于是，整个接收过程必须保证已经接收的边始终组成森林。对于新收到的结合对，设其两个端点为 $a$ 和 $b$。若它们位于不同的连通分量中，加入这条边只是将两棵树连接成一棵树，不会形成环，必须接收；若它们已经位于同一个连通分量中，原来的树中存在连接它们的唯一路径，加入新边后便形成一个环，必须拒绝。问题由此转化为动态维护连通性，并统计两个端点已经连通的结合对数量。

# 解题思路

使用并查集维护已经接收的结合对所形成的连通分量。数组 $parent$ 记录并查集中的父节点，调用 $\texttt{findSet}$ 函数得到某个顶点所在集合的根。代码还在每个集合的根处维护顶点数量 $ranks$ 和已经接收的边数 $pairs$。这里的 $ranks$ 表示集合大小，合并时将较小的集合连接到较大的集合，从而实现按大小合并；$\texttt{findSet}$ 函数同时使用路径压缩，提高后续查询效率。

每组数据开始时，将每个顶点初始化为独立集合，顶点数量为 $1$，边数为 $0$，拒绝次数为 $0$。对于一个结合对，先查出两个端点所属集合的根 $x$ 和 $y$。当 $x \ne y$ 时，接收这条边并合并两个集合；合并后的顶点数量等于原来两个集合的顶点数量之和，边数等于原来两个集合的边数之和再加 $1$。当 $x=y$ 时，两个端点已经连通，拒绝这条边并将拒绝次数增加 $1$，集合信息保持不变。

通过代码使用顶点数量与边数之间的关系进行判断。对于当前任意一个根为 $r$ 的连通分量，始终满足树的性质：
$$
pairs[r]=ranks[r]-1.
$$
因此，当两个端点属于同一个集合时，代码中的条件 $ranks[x]=pairs[x]+1$ 始终成立，对应的处理就是拒绝当前结合对。当两个端点属于不同集合时，有：
$$
pairs[x]+pairs[y]+1=ranks[x]+ranks[y]-1.
$$
这说明连接两个不同集合后，边数仍然比顶点数量少 $1$，合并结果仍是一棵树。代码在这个分支中检查顶点总数是否等于加入新边后的边数；根据上述等式，该条件始终不成立，因此会执行合并。代码中同一集合内增加边数的分支也不会在合法接收过程中执行。这些额外分支不影响结果，保留原有实现即可。

算法的正确性由森林这一性质在整个过程中始终成立得到保证。初始状态没有边，所有连通分量都是树。若新边连接不同连通分量，接收后仍然是森林，不存在爆炸组合；若新边连接同一连通分量内的两个顶点，加入后必然形成环，拒绝恰好符合题意。每次处理都准确执行接收规则，因此最终统计的拒绝次数正确。

在样例中，前 $4$ 个结合对被接收后，顶点 $1$、$2$、$3$、$4$、$5$ 已经连通。因此，结合对 $(2,3)$ 和 $(4,1)$ 都会形成环，需要拒绝。随后接收 $(2,6)$，顶点 $6$ 也进入该连通分量，最后的 $(6,5)$ 同样需要拒绝，答案为 $3$。

设每组数据包含 $m$ 个结合对，初始化的编号空间大小为 $U$。初始化需要 $O(U)$ 时间，每个结合对执行常数次并查集操作，结合路径压缩与按大小合并后，均摊时间为 $O(\alpha(U))$，其中 $\alpha$ 为反阿克曼函数。因此，每组数据的总时间复杂度为 $O(U+m\alpha(U))$，空间复杂度为 $O(U)$。

# 代码实现

```cpp
// X-Plosives

#include <bits/stdc++.h>

using namespace std;

const int MAXV = 100010;

int parent[MAXV], ranks[MAXV], pairs[MAXV];

void makeSet()
{
    for (int i = 0; i < MAXV; i++) parent[i] = i, ranks[i] = 1, pairs[i] = 0;
}

int findSet(int x)
{
    return (parent[x] == x ? x : parent[x] = findSet(parent[x]));
}

int main(int argc, char *argv[])
{
    cin.tie(0), cout.tie(0), ios::sync_with_stdio(false);
    int a, b, refusals;
    makeSet();
    refusals = 0;
    while (cin >> a)
    {
        if (a >= 0)
        {
            cin >> b;
            int x = findSet(a), y = findSet(b);
            if (x != y)
            {
                if (ranks[x] + ranks[y] == pairs[x] + pairs[y] + 1) refusals++;
                else
                {
                    if (ranks[x] > ranks[y])
                    {
                        parent[y] = x, ranks[x] += ranks[y], pairs[x] += pairs[y] + 1;
                    }
                    else
                    {
                        parent[x] = y, ranks[y] += ranks[x], pairs[y] += pairs[x] + 1;
                    }
                }
            }
            else
            {
                if (ranks[x] == pairs[x] + 1) refusals++;
                else
                {
                    pairs[x]++;
                }
            }
        }
        else
        {
            cout << refusals << '\n';
            makeSet();
            refusals = 0;
        }
    }
    return 0;
}
```

# 总结

本题的关键是将化合物与结合对分别建模为顶点和无向边，并证明“相同数量的结合对与化合物构成爆炸组合”等价于图中存在环。由于已经接收的边始终组成森林，判断新结合对是否需要拒绝，只需判断两个端点是否已经连通。并查集通过路径压缩和按大小合并高效维护连通性，而树中边数比顶点数量少 $1$ 的性质，则解释了给定代码中顶点计数与边计数的判断依据。
