
> **摘要**：本题给定一张有向无环图，要求用最少的伞兵访问全部路口，且每个路口只能被访问一次，本质是求有向无环图的最小顶点不相交路径覆盖。文章通过拆点把问题转化为二分图最大匹配，证明答案为 $n-M$（$M$ 为最大匹配数），并给出基于匈牙利算法的 $O(n^3)$ 实现与完整证明。

 # 题目描述

一座城镇有 $n$ 个路口和 $m$ 条单向街道，每条街道连接两个路口。所有街道构成一张有向无环图，即从任意路口出发，沿街道行走都无法再次回到该路口。

现在安排若干名伞兵降落到城镇中。每名伞兵可以选择任意路口作为降落点，随后沿单向街道访问其他路口，也可以只访问降落点。要求所有路口都被访问，并且每个路口只能由一名伞兵访问。

求完成任务所需的最少伞兵人数。

# 输入格式

输入第一行包含一个整数 $T$，表示数据组数。每组数据的格式如下：

- 第一行包含一个正整数 $n$，表示路口数量，满足 $1 \le n \le 120$。
- 第二行包含一个正整数 $m$，表示单向街道数量。
- 接下来 $m$ 行，每行包含两个整数 $u$ 和 $v$，表示存在一条从路口 $u$ 通向路口 $v$ 的单向街道，满足 $1 \le u,v \le n$。

路口编号为 $1$ 到 $n$，街道的输入顺序任意。相邻数据组之间没有空行，输入保证合法，且街道构成的有向图不存在环。

# 输出格式

对于每组数据，输出一行一个整数，表示访问所有路口所需的最少伞兵人数。

# 样例输入

```text
2
4
3
3 4
1 3
2 3
3
3
1 3
1 2
2 3
```

# 样例输出

```text
2
1
```

# 题目分析

每名伞兵的访问路线都是原图中的一条有向路径。由于原图没有环，沿街道行走不会重复经过同一个路口；由于不同伞兵不能访问同一个路口，各条路径之间必须没有公共顶点。因此，本题等价于求有向无环图的最小顶点不相交路径覆盖：选择尽量少的有向路径，使每个顶点恰好属于其中一条路径。只包含一个顶点的路径同样合法，对应一名伞兵降落后不再移动。

设某个合法方案包含 $k$ 条路径，第 $i$ 条路径包含 $s_i$ 个顶点，那么这条路径恰好使用 $s_i-1$ 条边。所有路径覆盖全部 $n$ 个顶点，因此路径使用的边数之和为
$$
\sum_{i=1}^{k}(s_i-1)=\sum_{i=1}^{k}s_i-k=n-k.
$$
这说明，最小化路径数量等价于最大化路径中使用的连接边数量。每增加一条合法连接，就把两段路径连接起来，使所需路径数量减少 $1$。

这些连接边必须满足明确的限制：每个顶点最多有一个后继，也最多有一个前驱。前者保证访问路线不会分叉，后者保证两条路线不会汇合到同一个顶点。一个顶点同时拥有一个前驱和一个后继完全合法，此时它位于某条路径的中间。将每个顶点分别作为“提供后继的起点”和“接受前驱的终点”处理，就能把这两个限制转化为二分图匹配中的端点互斥限制。

样例的第一组数据中，路口 $1$ 和路口 $2$ 都只能沿街道前往路口 $3$，它们无法由同一条路径覆盖。选择路径 $1 \to 3 \to 4$，再让另一名伞兵访问路口 $2$，共需 $2$ 名伞兵。第二组数据存在路径 $1 \to 2 \to 3$，因此只需 $1$ 名伞兵。

# 解题思路

将原图中的每个顶点 $u$ 拆成左部顶点 $u_L$ 和右部顶点 $u_R$，分别表示它作为一条连接边起点和终点的身份。对于原图中的每条有向边 $u \to v$，在二分图中加入边 $u_L \to v_R$。选中这条二分图边，就表示让同一名伞兵从路口 $u$ 直接走到路口 $v$。匹配要求每个左部顶点最多关联一条匹配边，因此每个原图顶点最多有一个后继；每个右部顶点最多关联一条匹配边，因此每个原图顶点最多有一个前驱。左右两份顶点相互独立，所以同一个原图顶点能够同时拥有前驱和后继。

设二分图的最大匹配大小为 $M$，则最少伞兵人数为
$$
n-M
$$
下面从两个方向证明这一结论。对于任意包含 $k$ 条路径的合法覆盖，路径中的 $n-k$ 条边在拆点后的二分图中构成一个匹配，因为每个顶点在路径中最多有一个后继和一个前驱。因此 $n-k \le M$，整理得到 $k \ge n-M$，说明任何方案都至少需要 $n-M$ 名伞兵。

反过来，将一个大小为 $M$ 的最大匹配映射回原图，保留其对应的 $M$ 条有向边。此时每个顶点的入度和出度都不超过 $1$，所以这些边只能组成若干条有向路径或有向环。原图是有向无环图，保留下来的边也不可能构成环，因此所得结构必然由若干条互不相交的有向路径以及孤立顶点组成。把孤立顶点视为只包含一个顶点的路径，就得到覆盖全部顶点的合法方案。该方案包含 $n$ 个顶点和 $M$ 条路径连接边，因此路径数量恰好为 $n-M$。结合前面的下界，答案得到证明。

实现时，代码使用基于增广路的匈牙利算法求二分图最大匹配。开始时所有顶点均未匹配，随后依次为尚未匹配的左部顶点寻找增广路。搜索过程中，若遇到尚未匹配的右部顶点，就能直接完成一次增广；若右部顶点已经匹配，就继续尝试为它原来对应的左部顶点寻找其他匹配位置。成功找到增广路后，沿途重新安排匹配关系，匹配数量增加 $1$。每轮搜索都重新清空右部顶点的访问标记，保证本轮搜索不会重复访问同一个右部顶点，同时允许不同轮次重新调整已有匹配。

代码中的 $\texttt{g}$ 保存二分图邻接矩阵，$\texttt{cx}$ 和 $\texttt{cy}$ 分别记录左右两侧的匹配对象，$\texttt{visited}$ 记录一轮增广搜索中访问过的右部顶点。调用 $\texttt{dfs}$ 函数寻找增广路，调用 $\texttt{hungarian}$ 函数得到最大匹配大小，最后输出 $n-M$。输入中的路口编号从 $1$ 开始，代码将其减去 $1$，转换为从 $0$ 开始的数组下标。

建图时只添加原图中实际存在的街道，不计算传递闭包。每条匹配边表示一次沿街道直接进行的移动，路径中的中间路口也必须被纳入同一条访问路线。只按可达关系连边会隐藏中间路口的占用情况，无法保证不同路径没有公共顶点。

对于本代码采用的邻接矩阵实现，每轮增广搜索最多访问 $n$ 个右部顶点，并对递归涉及的左部顶点扫描至多 $n$ 个候选邻接位置，单轮时间复杂度为 $O(n^2)$。最多进行 $n$ 轮增广搜索，因此每组数据的时间复杂度为 $O(n^3)$；邻接矩阵占用 $O(n^2)$ 空间，匹配数组和访问数组占用 $O(n)$ 空间，总空间复杂度为 $O(n^2)$。代码使用固定容量数组预留存储空间。

# 代码实现

```cpp

#include <bits/stdc++.h>

using namespace std;

const int MAXV = 256;
int g[MAXV][MAXV], visited[MAXV], cx[MAXV], cy[MAXV], tx, ty;

int dfs(int u) {
    for (int v = 0; v < ty; v++)
        if (g[u][v] && !visited[v]) {
            visited[v] = 1;
            if (cy[v] == -1 || dfs(cy[v])) {
                cx[u] = v, cy[v] = u;
                return 1;
            }
        }
    return 0;
}

int hungarian() {
    int matches = 0;
    memset(cx, -1, sizeof(cx));
    memset(cy, -1, sizeof(cy));
    for (int i = 0; i < tx; i++)
        if (cx[i] == -1) {
            memset(visited, 0, sizeof(visited));
            matches += dfs(i);
        }
    return matches;
}

int main(int argc, char *argv[]) {
    cin.tie(0), cout.tie(0), ios::sync_with_stdio(false);
    int cases;
    cin >> cases;
    for (int c = 1; c <= cases; c++) {
        int n, m, u, v;
        cin >> n >> m;
        memset(g, 0, sizeof(g));
        for (int i = 0; i < m; i++) {
            cin >> u >> v;
            u--, v--;
            g[u][v] = 1;
        }
        tx = ty = n;
        cout << n - hungarian() << '\n';
    }
    return 0;
}
```

# 总结

本题的关键是把伞兵访问路线转化为有向无环图上的最小顶点不相交路径覆盖，再通过拆点，将每个顶点最多拥有一个前驱和一个后继的限制转化为二分图匹配限制。路径数量等于顶点数量减去路径中的连接边数量，因此最大匹配大小为 $M$ 时，答案就是 $n-M$。原图无环保证匹配边还原后只能形成路径，构成这一结论成立的关键条件；直接使用原图街道建边，则保证了每次连接都对应真实且不遗漏中间路口的移动。
