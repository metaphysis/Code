
> **摘要**：本题给出若干条已按出发时间排序的出租车预约行程，每条行程包含出发时间与起终点坐标，出租车在网格中按曼哈顿距离行驶。要求安排尽可能少的出租车完成全部行程，其中同一辆车衔接两条行程时，必须能在后一条行程出发前至少一分钟到达其起点。文章将问题转化为有向无环图上的最少路径覆盖，进而用二分图最大匹配求解，答案为行程总数减去最大匹配数，并给出基于增广路算法的实现与复杂度分析。

# 题目描述

城市被建模为一个矩形网格，每个地址由街道编号和大街编号表示。出租车从地址 $(a,b)$ 行驶到地址 $(c,d)$ 所需的时间为曼哈顿距离：

$$
|a-c|+|b-d|
$$

给定第二天已经预约的所有行程，要求安排尽可能少的出租车完成全部行程。

一辆出租车可以执行一条行程，条件如下：

- 该行程是这辆出租车当天执行的第一条行程。
- 或者出租车完成上一条行程后，能够在新行程出发前至少一分钟到达新行程的出发地点。

部分行程可能在午夜之后结束。所有预约按照出发时间递增排列。

# 输入格式

第一行包含一个整数 $N$，表示测试场景数量。

每个测试场景首先包含一个整数 $M$，表示预约行程数量，满足 $0<M<500$。

接下来 $M$ 行，每行描述一条行程，格式如下：

```text
hh:mm a b c d
```

其中，$\texttt{hh:mm}$ 是出发时间，范围为 $\texttt{00:00}$ 到 $\texttt{23:59}$；$(a,b)$ 是出发地址，$(c,d)$ 是目的地址。所有坐标均为不小于 $0$ 且小于 $200$ 的整数。

同一测试场景中的行程已经按照出发时间递增排列。

# 输出格式

对于每个测试场景，输出一行，表示完成全部预约行程所需的最少出租车数量。

# 样例输入

```text
2
2
08:00 10 11 9 16
08:07 9 16 10 11
2
08:00 10 11 9 16
08:06 9 16 10 11
```

# 样例输出

```text
1
2
```

# 题目分析

每条预约行程都必须由某一辆出租车执行。若一辆出租车先执行行程 $i$，再执行行程 $j$，则必须满足以下条件：

$$
\text{行程 }i\text{ 的结束时间}+\text{从行程 }i\text{ 终点到行程 }j\text{ 起点的行驶时间}<\text{行程 }j\text{ 的出发时间}
$$

其中，严格小于表示出租车至少提前一分钟到达。行程 $i$ 的结束时间为：

$$
t_i+|a_i-c_i|+|b_i-d_i|
$$

出租车从行程 $i$ 的终点前往行程 $j$ 的起点所需时间为：

$$
|c_i-a_j|+|d_i-b_j|
$$

因此，若行程 $i$ 能够直接衔接到行程 $j$，就可以建立一条有向关系 $i\to j$。

由于所有行程已经按照出发时间排序，若行程 $i$ 能衔接到行程 $j$，则通常有 $i<j$。每辆出租车执行的行程序列可以看成这些行程组成的若干条链，每条链对应一辆出租车。问题转化为：将全部行程划分为尽可能少的合法链。

为了求出最少链数，将每条行程复制成左部顶点和右部顶点。左部顶点表示某条行程作为前一条行程，右部顶点表示某条行程作为后一条行程。如果行程 $i$ 能够衔接到行程 $j$，就在左部顶点 $i$ 与右部顶点 $j$ 之间连边。

在二分图中选择一条匹配边，表示将行程 $j$ 接在行程 $i$ 之后。由于匹配的性质，每条行程至多拥有一个前继和一个后继，因此匹配边集合恰好能够组成若干条互不冲突的行程链。

设行程总数为 $M$，最大匹配数为 $K$。每条链如果包含 $r$ 条行程，就需要 $r-1$ 条衔接边。所有链中的衔接边总数为：

$$
M-\text{链数}
$$

最大匹配能够尽可能多地连接行程，因此最少出租车数量为：

$$
M-K
$$

本题使用增广路方法实现二分图最大匹配。每次从一个尚未匹配的左部顶点出发，尝试寻找一条增广路。若右部顶点尚未匹配，则直接建立匹配；若右部顶点已经匹配，则递归尝试为原先匹配的左部顶点寻找新的位置。每找到一条增广路，匹配数增加一。

# 解题思路

首先读取每条行程的出发时间和四个坐标。将出发时间 $\texttt{hh:mm}$ 转换为从当天零点开始计算的分钟数：

$$
60\times \text{小时}+\text{分钟}
$$

对于行程 $i$，先计算出租车完成该行程后的时间：

$$
finish_i=t_i+|a_i-c_i|+|b_i-d_i|
$$

随后枚举所有行程对 $(i,j)$，计算出租车完成行程 $i$ 后前往行程 $j$ 出发地点的时间：

$$
finish_i+|c_i-a_j|+|d_i-b_j|
$$

如果该值严格小于 $t_j$，则在二分图中添加边 $i\to j$。这条边表示同一辆出租车可以连续执行行程 $i$ 和行程 $j$。

建立图后，调用 $\texttt{hungarian}$ 函数计算最大匹配。函数使用数组 $\textit{cx}$ 记录每个左部顶点匹配的右部顶点，使用数组 $\textit{cy}$ 记录每个右部顶点匹配的左部顶点。每次处理一个左部顶点时，清空 $\textit{visited}$ 数组，保证本次增广搜索中每个右部顶点最多被访问一次。

$\texttt{dfs}$ 函数遍历当前左部顶点的所有邻接右部顶点。若某个右部顶点尚未访问，则标记该顶点。若该右部顶点尚未匹配，或者其当前匹配的左部顶点能够通过递归搜索转移到其他右部顶点，就更新匹配关系，并返回匹配成功。所有左部顶点处理完成后，得到最大匹配数。

最后输出 $M-K$。样例中的第一个测试场景中，第一条行程结束后能够在第二条行程出发前到达其起点，因此两条行程可以由同一辆出租车完成，最大匹配数为 $1$，答案为 $2-1=1$。第二个测试场景中，第一条行程结束后无法在第二条行程出发前至少一分钟到达，因此不存在衔接边，最大匹配数为 $0$，答案为 $2$。

设单个测试场景包含 $M$ 条行程。建立图需要枚举所有行程对，时间复杂度为 $O(M^2)$。增广路匹配最多进行 $M$ 次，每次搜索最多遍历 $O(M^2)$ 条边，因此匹配部分的时间复杂度为 $O(M^3)$。总时间复杂度为 $O(M^3)$。邻接矩阵占用 $O(M^2)$ 的空间，匹配数组和访问数组占用 $O(M)$ 的空间，因此总空间复杂度为 $O(M^2)$。

# 代码实现

代码使用二分图最大匹配求解最少出租车数量。函数 $\texttt{dfs}$ 用于寻找增广路，函数 $\texttt{hungarian}$ 用于计算最大匹配。代码中的结构体 $\texttt{taxi}$ 保存每条预约行程的出发时间、出发地址和目的地址。

```cpp
// Taxi Cab Scheme
// UVa ID: 1201

// 版权所有（C）2018，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>

using namespace std;

const int MAXV = 1024;

int g[MAXV][MAXV], visited[MAXV], cx[MAXV], cy[MAXV], tx, ty;

int dfs(int u)
{
    for (int v = 0; v < ty; v++)
        if (g[u][v] && !visited[v])
        {
            visited[v] = 1;
            if (cy[v] == -1 || dfs(cy[v]))
            {
                cx[u] = v, cy[v] = u;
                return 1;
            }
        }
    return 0;
}

int hungarian()
{
    int matches = 0;
    memset(cx, -1, sizeof(cx)); memset(cy, -1, sizeof(cy));
    for (int i = 0; i < tx; i++)
        if (cx[i] == -1)
        {
            memset(visited, 0, sizeof(visited));
            matches += dfs(i);
        }
    return matches;
}

struct taxi
{
    int minutes, a, b, c, d;
} books[512];

int main(int argc, char *argv[])
{
    cin.tie(0), cout.tie(0), ios::sync_with_stdio(false);

    int cases;
    cin >> cases;
    for (int c = 1; c <= cases; c++)
    {
        int M;
        cin >> M;
        for (int i = 0; i < M; i++)
        {
            string time;
            int a, b, c, d;
            cin >> time;
            cin >> books[i].a >> books[i].b >> books[i].c >> books[i].d;
            books[i].minutes = stoi(time.substr(0, 2)) * 60 + stoi(time.substr(3));
        }
        
        tx = ty =  M;
        for (int i = 0; i < M; i++)
            for (int j = 0; j < M; j++)
                g[i][j] = 0;
        for (int i = 0; i < M; i++)
            for (int j = 0; j < M; j++)
            {
                int endtime = books[i].minutes + abs(books[i].a - books[i].c) + abs(books[i].b - books[i].d);
                endtime += abs(books[i].c - books[j].a) + abs(books[i].d - books[j].b);
                if (endtime < books[j].minutes)
                    g[i][j] = 1;
            }        
                
        cout << M - hungarian() << '\n';
    }

    return 0;
}
```

# 总结

本题的关键是将出租车调度问题转化为最少路径覆盖问题，再利用二分图最大匹配求解。

核心结论如下：

- 若行程 $i$ 完成后能够在行程 $j$ 出发前至少一分钟到达其起点，就在二分图中建立边 $i\to j$。
- 最大匹配中的每条边表示两条行程由同一辆出租车连续完成。
- 最大匹配数越大，能够合并的行程链越多。
- 最少出租车数量等于行程总数减去最大匹配数：
  
$$
\text{答案}=M-\text{最大匹配数}
$$

实现时必须使用严格不等式判断衔接条件，并将时间统一转换为分钟。通过增广路算法求出最大匹配后，即可在线性之外的多项式时间内完成整个调度计算。
