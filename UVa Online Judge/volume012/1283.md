## 题目描述

$\texttt{ACM}$（$\texttt{Association of Chaos and Mischief}$）的指挥结构由若干个单元（$\texttt{cell}$）组成。对于任意两个不同的单元 $A$ 和 $B$，要么 $A$ 控制 $B$，要么 $B$ 控制 $A$，且不会同时互相控制。这种关系可能是循环的，例如 $A$ 控制 $B$、$B$ 控制 $C$、$C$ 控制 $A$。

我们可以派遣特工渗透进任意一个单元。渗透一个单元 $x$ 后，我们会获得对该单元以及所有被 $x$ 直接控制的单元的控制权，但不能获得其他单元的控制权。例如，在 $A \to B \to C \to A$ 的循环中，渗透 $A$ 只能控制 $A$ 和 $B$，不能控制 $C$。

为了成功渗透整个 $\texttt{ACM}$，我们必须获得所有单元的控制权。请计算最少需要渗透多少个单元，并输出任意一组最优解。

## 输入格式

每个测试用例第一行包含一个整数 $n$（$1 \le n \le 75$），表示单元的数量。接下来 $n$ 行，每行是一个长度为 $n$ 的二进制字符串。第 $j$ 行的第 $i$ 个字符为 $\texttt{1}$ 表示单元 $j$ 控制单元 $i$，为 $\texttt{0}$ 表示不控制。第 $i$ 行的第 $i$ 个字符为 $\texttt{0}$，且对于 $i \ne j$，要么第 $j$ 行的第 $i$ 个字符为 $\texttt{1}$，要么第 $i$ 行的第 $j$ 个字符为 $\texttt{1}$，但不会同时为 $\texttt{1}$。

输入可能包含多个测试用例，每个测试用例的格式相同，直到文件结束。

## 输出格式

对于每个测试用例，输出一行，格式为 `Case X: m c1 c2 ... cm`，其中 $X$ 是测试用例编号（从 $1$ 开始），$m$ 是最少需要渗透的单元数量，$c_1, c_2, \dots, c_m$ 是任意一组最优解中需要渗透的单元编号（编号从 $1$ 到 $n$，顺序任意）。

## 题目分析

本题描述的是一个**竞赛图**（$\texttt{tournament graph}$）：$n$ 个顶点，每对不同顶点之间恰好有一条有向边。边 $j \to i$ 表示单元 $j$ 控制单元 $i$。

选择渗透一个顶点 $v$，可以获得顶点 $v$ 及其所有出邻点的控制权。我们需要选择一个最小的顶点集合 $S$，使得每个顶点要么在 $S$ 中，要么是某个 $s \in S$ 的出邻点。这正是**有向图的最小支配集**问题。

对于一般图，最小支配集是 $\texttt{NP-hard}$ 的。虽然竞赛图具有很好的结构性质，但最小支配集问题在竞赛图上仍然是 $\texttt{NP-hard}$ 的。题目给出的 $n \le 75$ 也暗示了需要采用指数级算法。

## 解题思路

### 问题的转化

设 $\textit{cover}[v]$ 为选择顶点 $v$ 后能获得控制权的顶点集合（包含 $v$ 本身及其所有出邻点）。我们需要选择最少的顶点，使得这些 $\textit{cover}$ 集合的并集等于全体顶点集合 $\{0, 1, \dots, n-1\}$。

这是一个**集合覆盖**问题，但具有特殊的图论结构。

### 算法选择

由于 $n \le 75$，直接枚举所有子集（$2^{75}$）是不可能的。我们采用**迭代加深搜索**（$\texttt{IDA*}$）配合强剪枝。

迭代加深的基本思想：
- 从小到大枚举深度限制 $\textit{limit}$（从 $1$ 开始递增）。
- 对于每个 $\textit{limit}$，执行深度受限的深度优先搜索。
- 当搜索到一组解时，该解就是最优解（因为 $\textit{limit}$ 是从小到大的）。

### 基础版本

最直接的实现思路是：
1. 预处理每个顶点的覆盖集合 $\textit{cover}[v]$。
2. 在深度受限的 $\texttt{DFS}$ 中，每次选择第一个未覆盖的顶点 $u$，然后枚举所有能覆盖 $u$ 的顶点作为候选。
3. 递归搜索，直到找到一组解。

这个基础版本虽然可以得到正确结果，但由于没有任何剪枝，搜索空间巨大。对于 $n = 75$ 的极限数据，运行时间达到 $9$ 秒以上。

基础版本的代码如下：

```cpp
#include <bits/stdc++.h>
using namespace std;

int n, limit;
vector<bitset<75>> cover;
bitset<75> allCovered;
vector<int> ans, cur;

bool dfs(bitset<75> covered, int depth) {
    if (covered == allCovered) {
        ans = cur;
        return true;
    }
    if (depth >= limit) return false;
    
    int u = -1;
    for (int i = 0; i < n; ++i) if (!covered[i]) { u = i; break; }
    if (u == -1) return false;
    
    vector<int> cand;
    for (int i = 0; i < n; ++i) if (cover[i][u]) cand.push_back(i);
    
    for (int v : cand) {
        cur.push_back(v + 1);
        if (dfs(covered | cover[v], depth + 1)) return true;
        cur.pop_back();
    }
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int caseNum = 0;
    while (cin >> n) {
        ++caseNum;
        cover.assign(n, bitset<75>());
        for (int i = 0; i < n; ++i) {
            string s;
            cin >> s;
            cover[i].set(i);
            for (int j = 0; j < n; ++j) if (s[j] == '1') cover[i].set(j);
        }
        allCovered.reset();
        for (int i = 0; i < n; ++i) allCovered.set(i);
        
        for (limit = 1; limit <= n; ++limit) {
            cur.clear();
            if (dfs(bitset<75>(), 0)) break;
        }
        
        cout << "Case " << caseNum << ": " << ans.size();
        for (int x : ans) cout << " " << x;
        cout << "\n";
    }
    return 0;
}
```

### 关键优化

1. **预处理入邻点列表**

   为了快速找到能够覆盖某个顶点的所有候选顶点，我们预处理每个顶点的**入邻点列表** $\textit{inNeighbors}[i]$，即所有能覆盖 $i$ 的顶点（包括 $i$ 自身）。这避免了每次搜索时重新扫描全图。

2. **启发式剪枝**

   定义启发函数 $\textit{heuristic}(\textit{covered})$ 为：从当前覆盖状态到完全覆盖，至少还需要选择的顶点数的一个下界。我们采用以下估计：

   $$
   \textit{heuristic}(\textit{covered}) = \left\lceil \frac{\textit{remain}}{\max\textit{Cover}} \right\rceil
   $$

   其中 $\textit{remain}$ 是当前未覆盖的顶点数，$\max\textit{Cover}$ 是当前任意一个未选顶点能覆盖的最大未覆盖顶点数。

   在搜索过程中，如果当前深度 $\textit{depth}$ 满足：

   $$
   \textit{depth} + \textit{heuristic}(\textit{covered}) > \textit{limit}
   $$

   则说明即使使用最乐观的估计也无法在剩余深度内完成覆盖，可以立即剪枝。

3. **选择最难覆盖的顶点**

   在每一层递归中，我们选择**候选点最少**的未覆盖顶点作为分支点。候选点越少，分支因子越小，搜索树越窄。这类似于 $\texttt{MRV}$（$\texttt{most constrained variable}$）启发式。

4. **候选点排序**

   对于选定的顶点 $u$，其候选点（能覆盖 $u$ 的所有顶点）按覆盖能力降序排序：覆盖能力越强的顶点越优先尝试，这样能更快地找到解，从而提高剪枝效率。

5. **贪心求上界**

   在开始迭代加深之前，先用贪心算法求一个上界 $\textit{upper}$：每次选择能覆盖最多未覆盖顶点的顶点，直到全覆盖。这样迭代加深的 $\textit{limit}$ 只需要从 $1$ 枚举到 $\textit{upper}$ 即可，无需枚举到 $n$。

6. **允许重复选择已覆盖的顶点**

   这是一个关键点。在搜索过程中，一个顶点即使已经被覆盖，仍然可以被选择渗透。因为被覆盖的顶点可能控制其他尚未被覆盖的顶点，而仅被控制并不能让我们获得它的控制能力。因此，**不能跳过已被覆盖的候选点**。基础版本中由于没有跳过已覆盖点，实际上是允许重复选择的，这一点是正确的。

7. **使用位集（$\texttt{bitset}$）加速**

   由于 $n \le 75$，可以用 `std::bitset<75>` 表示覆盖状态，集合的并、交、差运算都非常高效。

### 复杂度分析

- 最坏情况下的搜索树大小是指数级的，但由于竞赛图的性质和强剪枝，实际运行效率很高。
- 对于 $n = 75$ 的极限数据，优化后的代码可以在 $1$ 秒内完成（实测约 $660$ 毫秒）。
- 空间复杂度：$O(n^2)$，用于存储覆盖矩阵和入邻点列表。

## 代码实现

### 优化版本

```cpp
// Infiltration
// UVa ID: 1283
// Verdict: Accepted
// Submission Date: 2026-06-13
// UVa Run Time: 0.660s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net


#include <bits/stdc++.h>
using namespace std;

int n, limit;
vector<bitset<75>> cover;
vector<vector<int>> inNeighbors;  // 预处理入邻点
bitset<75> allCovered;
vector<int> ans, cur;

int heuristic(bitset<75>& covered) {
    int remain = n - covered.count();
    if (remain == 0) return 0;
    int maxCover = 1;
    for (int i = 0; i < n; ++i) {
        int cnt = (cover[i] & ~covered).count();
        if (cnt > maxCover) maxCover = cnt;
    }
    return (remain + maxCover - 1) / maxCover;
}

bool dfs(bitset<75> covered, int depth) {
    if (covered == allCovered) {
        ans = cur;
        return true;
    }
    if (depth >= limit) return false;
    if (depth + heuristic(covered) > limit) return false;
    
    // 找最难覆盖的点（候选点最少）
    int u = -1, minCand = n + 1;
    for (int i = 0; i < n; ++i) if (!covered[i]) {
        int cnt = 0;
        for (int v : inNeighbors[i]) if (!covered[v]) ++cnt;
        if (cnt < minCand) minCand = cnt, u = i;
    }
    if (u == -1) return false;
    
    // 候选点按覆盖能力降序
    vector<int> cand = inNeighbors[u];
    sort(cand.begin(), cand.end(), [&](int a, int b) {
        return (cover[a] & ~covered).count() > (cover[b] & ~covered).count();
    });
    
    for (int v : cand) {
        cur.push_back(v + 1);
        if (dfs(covered | cover[v], depth + 1)) return true;
        cur.pop_back();
    }
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int caseNum = 0;
    while (cin >> n) {
        ++caseNum;
        cover.assign(n, bitset<75>());
        inNeighbors.assign(n, vector<int>());
        for (int i = 0; i < n; ++i) {
            string s;
            cin >> s;
            cover[i].set(i);
            inNeighbors[i].push_back(i);
            for (int j = 0; j < n; ++j) if (s[j] == '1') {
                cover[i].set(j);
                inNeighbors[j].push_back(i);
            }
        }
        allCovered.reset();
        for (int i = 0; i < n; ++i) allCovered.set(i);
        
        // 贪心上界
        bitset<75> greedyCovered;
        int upper = 0;
        while (greedyCovered != allCovered) {
            int best = -1, bestCnt = -1;
            for (int i = 0; i < n; ++i) if (!greedyCovered[i]) {
                int cnt = (cover[i] & ~greedyCovered).count();
                if (cnt > bestCnt) bestCnt = cnt, best = i;
            }
            if (best == -1) break;
            ++upper;
            greedyCovered |= cover[best];
        }
        
        for (limit = 1; limit <= upper; ++limit) {
            cur.clear();
            if (dfs(bitset<75>(), 0)) break;
        }
        
        cout << "Case " << caseNum << ": " << ans.size();
        for (int x : ans) cout << " " << x;
        cout << "\n";
    }
    return 0;
}
```

## 总结

本题的核心是求解竞赛图的最小支配集，这是一个 $\texttt{NP-hard}$ 问题。通过迭代加深搜索配合以下关键优化，可以在 $n \le 75$ 的范围内高效求解：

1. **预处理入邻点列表**：避免重复扫描。
2. **启发式剪枝**：用乐观估计下界剪去不可能的分支。
3. **选择最难覆盖的顶点**：减小分支因子。
4. **候选点排序**：优先尝试覆盖能力强的顶点。
5. **贪心上界**：减少迭代加深的层数。
6. **位集（$\texttt{bitset}$）加速**：利用 `std::bitset` 进行高效的集合运算。
7. **允许重复选择已覆盖的顶点**：这是容易忽略的关键点，因为被覆盖的顶点仍然可能贡献其出边。

从基础版本（$9$ 秒）到优化版本（$660$ 毫秒），性能提升了约 $14$ 倍。这充分体现了剪枝策略和数据结构优化在指数级算法中的重要性。在实际竞赛中，当遇到 $\texttt{NP-hard}$ 问题且数据规模较小时，迭代加深搜索配合强剪枝往往是最实用的解决方案。
