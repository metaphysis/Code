## 题目描述
怀特先生迷上了跳舞机游戏 $\texttt{Dance Dance Revolution}$。游戏中有 $5$ 个位置：中心点 $0$，以及上、左、下、右四个方向点，分别标记为 $1$、$2$、$3$、$4$。游戏开始时，双脚都在中心点 $0$。

游戏按照给定的方向序列进行，每次必须有一只脚（且只能一只）移动到序列指定的方向点上。规则如下：
1. 不能将双脚移动到同一个点上（除非其中一只脚已在该点，此时应原地踩踏）。
2. 移动消耗的体力取决于移动类型：
   - 从中心点 $0$ 移动到任意边点：$2$ 单位体力
   - 从一个边点移动到相邻边点（如 $1\rightarrow 2$）：$3$ 单位体力
   - 从一个边点移动到相对边点（如 $1\rightarrow 3$）：$4$ 单位体力
   - 停留在原地再次踩踏：$1$ 单位体力

给定一个方向序列（由 $1$、$2$、$3$、$4$ 组成，以 $0$ 结束序列，单独 $0$ 表示输入结束），要求计算完成整个序列所需的最少体力消耗。

## 输入输出格式
**输入**：多组测试数据，每组包含一系列整数，以 $0$ 结束一组数据。单独一行 $0$ 表示输入结束。
**输出**：对每组数据，输出一个整数表示最少体力消耗。

**样例输入**：
```
1 2 2 4 0
1 2 3 4 1 2 3 3 4 2 0
0
```
**样例输出**：
```
8
22
```

## 题目分析

### 问题本质
这是一个**状态空间搜索**问题，我们需要在满足游戏规则的前提下，为每一步选择移动左脚还是右脚，使得总体力消耗最小。

**关键约束**：
- 每个时刻，双脚位置不能相同（除非是通过“原地踩”实现的）。
- 每个指令必须有一只脚落在目标点上。
- 体力消耗取决于移动距离（相邻、相对、中心到边等）。

### 状态定义
我们可以将问题建模为**动态规划（$\texttt{DP}$）**：
- 设 $dp[i][l][r]$ 表示处理完前 $i$ 个指令后，**左脚在位置 $l$**，**右脚在位置 $r$** 时的最小体力消耗。
- 这里 $l, r \in \{0,1,2,3,4\}$，共 $5\times5=25$ 种脚位组合。

### 状态转移
对于第 $i$ 个指令 $target$：
1. **如果左脚移动到 $target$**：
   - 条件：右脚不在 $target$ 上（否则违反“双脚不能同点”规则）。
   - 消耗：$dp[i-1][l'][r] + cost(l', target)$，其中 $l'$ 是移动前左脚位置。
2. **如果右脚移动到 $target$**：
   - 条件：左脚不在 $target$ 上。
   - 消耗：$dp[i-1][l][r'] + cost(r', target)$，其中 $r'$ 是移动前右脚位置。
3. **如果某只脚已在 $target$**：
   - 只能选择原地踩踏，消耗 $1$ 单位体力，这已包含在 $cost(target, target)=1$ 中。

**注意**：移动时，只能移动一只脚，另一只脚保持不动。

### 体力消耗表
根据题目描述，我们可以预先计算 $cost[a][b]$：
- $cost[0][1]=cost[0][2]=cost[0][3]=cost[0][4]=2$
- $cost[1][2]=cost[2][1]=cost[2][3]=cost[3][2]=cost[3][4]=cost[4][3]=cost[4][1]=cost[1][4]=3$
- $cost[1][3]=cost[3][1]=cost[2][4]=cost[4][2]=4$
- $cost[x][x]=1$（原地踩踏）
- 其余未说明的情况（如 $1\rightarrow 0$）与对称情况相同。

### 优化空间
由于 $dp[i][*][*]$ 只依赖于 $dp[i-1][*][*]$，我们可以使用**滚动数组**，只保留当前状态和上一个状态，空间复杂度为 $O(5^2)=O(25)$。

### 初始状态与答案
- 初始状态：$dp[0][0][0] = 0$（双脚都在中心点）。
- 最终答案：完成所有指令后，所有 $dp[l][r]$ 中的最小值。

## 算法步骤
1. 读入指令序列，遇到 $0$ 处理一组数据。
2. 初始化 $dp$ 数组为无穷大，设置 $dp[0][0]=0$。
3. 对于每个指令 $target$：
   - 创建新数组 $ndp$，初始化为无穷大。
   - 遍历所有脚位状态 $(l, r)$：
     - 如果左脚可以移动到 $target$（即 $r \neq target$），则更新 $ndp[target][r] = \min(ndp[target][r], dp[l][r] + cost[l][target])$。
     - 如果右脚可以移动到 $target$（即 $l \neq target$），则更新 $ndp[l][target] = \min(ndp[l][target], dp[l][r] + cost[r][target])$。
   - 将 $ndp$ 设为新的 $dp$。
4. 遍历所有最终状态 $(l, r)$，取最小值输出。

## 复杂度分析
- 时间复杂度：$O(N \times 5^2 \times 2) = O(N)$，其中 $N$ 是指令总数，每个状态最多进行两次转移。
- 空间复杂度：$O(5^2) = O(25)$，使用滚动数组。

```cpp
// Dance Dance Revolution

#include <bits/stdc++.h>
using namespace std;

const int INF = 0x3f3f3f3f;
int cost[5][5]; // 预计算体力消耗表

// 初始化体力消耗表
void initCost() {
    // 初始化全部为0
    for (int i = 0; i < 5; i++) 
        for (int j = 0; j < 5; j++) 
            cost[i][j] = 0;
    
    // 中心点到边点：2
    for (int i = 1; i <= 4; i++) 
        cost[0][i] = cost[i][0] = 2;
    
    // 相邻边点：3
    cost[1][2] = cost[2][1] = 3;
    cost[2][3] = cost[3][2] = 3;
    cost[3][4] = cost[4][3] = 3;
    cost[4][1] = cost[1][4] = 3;
    
    // 相对边点：4
    cost[1][3] = cost[3][1] = 4;
    cost[2][4] = cost[4][2] = 4;
    
    // 原地踩踏：1
    for (int i = 0; i < 5; i++) 
        cost[i][i] = 1;
}

int main() {
    initCost(); // 初始化体力消耗表
    vector<int> steps; // 存储当前指令序列
    int step;
    
    while (cin >> step) {
        if (step == 0) {
            // 遇到0表示一组数据结束
            if (steps.empty()) 
                break; // 单独0表示输入结束
            
            // dp[l][r]表示当前左脚在l、右脚在r的最小体力
            vector<vector<int>> dp(5, vector<int>(5, INF));
            dp[0][0] = 0; // 初始状态：双脚在中心点
            
            // 处理每个指令
            for (int s : steps) {
                vector<vector<int>> ndp(5, vector<int>(5, INF));
                for (int l = 0; l < 5; l++) {
                    for (int r = 0; r < 5; r++) {
                        if (dp[l][r] != INF) {
                            // 尝试移动左脚到s
                            if (r != s) // 右脚不能在目标点上
                                ndp[s][r] = min(ndp[s][r], dp[l][r] + cost[l][s]);
                            // 尝试移动右脚到s
                            if (l != s) // 左脚不能在目标点上
                                ndp[l][s] = min(ndp[l][s], dp[l][r] + cost[r][s]);
                        }
                    }
                }
                dp = move(ndp); // 滚动更新
            }
            
            // 寻找最小消耗
            int ans = INF;
            for (int l = 0; l < 5; l++) 
                for (int r = 0; r < 5; r++) 
                    ans = min(ans, dp[l][r]);
            
            cout << ans << endl;
            steps.clear(); // 清空，准备下一组数据
        } else {
            steps.push_back(step); // 添加指令到序列
        }
    }
    
    return 0;
}
```

## 总结
本题是一个典型的**动态规划**问题，通过合理定义状态（双脚位置）和状态转移（移动左脚或右脚），可以高效求解最小体力消耗。关键点在于：
1. 正确处理游戏规则，特别是“双脚不能同点”的限制。
2. 精确计算各种移动方式的体力消耗。
3. 使用滚动数组优化空间。

该算法在时间和空间上都是高效的，能够处理较长的指令序列。
