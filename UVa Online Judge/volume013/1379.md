[UVa 1379 Pitcher Rotation](https://blog.csdn.net/metaphysis/article/details/161959667)

## 题目描述

$\texttt{ACM}$ 公司需要为接下来的赛季安排棒球队的投手轮值。已知有 $n$ 名投手（$5 \le n \le 100$），$m$ 支对手球队（$3 \le m \le 30$），赛季共有 $g$ 场比赛（$3 \le g \le 200$）。赛季持续 $g + 10$ 天，每天最多有一场比赛。

经理知道每名投手对阵每支球队的胜率，数据以 $m \times n$ 矩阵 $P$ 的形式给出，其中 $p_{ij}$ 表示投手 $j$ 对阵球队 $i$ 的胜率（以两位整数形式给出，如 $92$ 表示 $0.92$）。此外，给定长度为 $g + 10$ 的赛程列表 $d_1, d_2, \dots, d_{g+10}$，其中 $d_i$ 表示第 $i$ 天的对手球队编号，$d_i = 0$ 表示当天没有比赛。

关键规则：一名投手完成一场比赛后必须休息至少 $4$ 天，即第 $i$ 天出场的投手在第 $i+1, i+2, i+3, i+4$ 天不能再次出场，第 $i+5$ 天可以重新登场。

目标是决定每场比赛的出场投手，使得期望获胜场数最大。

## 输入格式

第一行包含一个整数 $t$（$1 \le t \le 5$），表示需要帮助的球队数量。

对于每支球队，第一行包含三个整数 $n, m, g$，分别表示投手数、对手球队数、比赛场数。

接下来 $m$ 行，每行 $n$ 个整数，表示胜率矩阵 $P$，其中 $p_{ij}$ 是两位整数（如 $92$ 表示 $0.92$）。

接下来 $g + 10$ 行，每行一个整数，表示赛程 $d_i$，$d_i = 0$ 表示当天无比赛，否则表示对手球队编号。

## 输出格式

对于每支球队，输出一行一个浮点数，表示最大期望获胜场数，保留两位小数。

## 题目分析

这是一个典型的**带时间约束的指派问题**。直接暴力枚举所有可能的投手指派方案不可行，因为 $g$ 最大可达 $200$，$n$ 最大可达 $100$，状态空间巨大。

观察约束条件：一名投手出场后必须休息至少 $4$ 天，这意味着同一投手两场比赛之间至少相隔 $5$ 天。由于 $g \le 200$，赛季总天数不超过 $210$，这个约束实际上限制了每名投手在整个赛季中最多出场约 $\frac{g+10}{5} \approx 42$ 次，但更重要的是，它使得决策只依赖于**前 $4$ 天的投手选择**。

进一步分析发现，对于每支对手球队，真正值得考虑的投手数量很少。因为投手需要休息 $4$ 天，意味着在连续 $5$ 天中最多只能使用同一名投手一次，所以对于同一对手球队，我们最多只需要考虑胜率最高的前 $5$ 名投手。这个贪心剪枝是本题解法的关键。

## 解题思路

### 贪心剪枝

对于每支对手球队 $i$，将其所有投手按胜率从高到低排序。由于休息约束的存在，任何一天选择的投手不能与之前 $4$ 天选择的投手重复。在同一对手球队出现多次的情况下，实际上我们最多只需要前 $5$ 名投手就可以构造出最优解。这是因为第 $6$ 名及以后的投手胜率不会比前 $5$ 名更高，且在任何可行调度中都可以被前 $5$ 名中的某个投手替代。

因此，对于每支对手球队，我们只保留胜率最高的前 $5$ 名投手（如果存在并列，可能需要保留更多，因为并列第 $5$ 名的投手同样重要）。在实际实现中，我们保留前 $15$ 名以确保不会遗漏重要的候选投手。

### 动态规划状态设计

设 $\textit{dp}[\textit{day}][a][b][c][d]$ 表示处理完第 $\textit{day}$ 天的比赛后，前 $4$ 天（即第 $\textit{day}-3$ 天、第 $\textit{day}-2$ 天、第 $\textit{day}-1$ 天、第 $\textit{day}$ 天）所使用的投手**分别在其所在对手球队中的排名**。

这里“排名”是指该投手在其对应对手球队的胜率排序中的位置（$1$ 到 $5$），$0$ 表示该天没有比赛或尚未开始。这样做的原因是：我们只需要知道投手的排名，就可以通过 $\textit{best}[\textit{team}][\textit{rank}]$ 查询到具体的投手编号，从而进行冲突检查。

状态转移：
- 如果第 $\textit{day}$ 天没有比赛（$d_{\textit{day}} = 0$），则状态直接平移：新状态的前 $4$ 天变为原来的后 $3$ 天加上 $0$，即
  $$
  \textit{dp}[\textit{day}][b][c][d][0] = \max(\textit{dp}[\textit{day}][b][c][d][0], \textit{dp}[\textit{day}-1][a][b][c][d])
  $$
- 如果第 $\textit{day}$ 天有比赛，则枚举当天可能选择的投手排名 $k$（从 $1$ 到 $5$），检查该投手是否与前 $4$ 天使用的投手冲突。如果不冲突，则进行转移：
  $$
  \textit{dp}[\textit{day}][b][c][d][k] = \max(\textit{dp}[\textit{day}][b][c][d][k], \textit{dp}[\textit{day}-1][a][b][c][d] + \textit{win}[\textit{team}][\textit{best}[\textit{team}][k]])
  $$

### 滚动数组优化

由于 $\textit{dp}[\textit{day}]$ 只依赖于 $\textit{dp}[\textit{day}-1]$，我们可以使用滚动数组，将第一维从 $g+10$ 压缩为 $2$。这样空间复杂度从 $O(\text{days} \times 6^4)$ 降为 $O(6^4)$，完全可接受。

### 冲突检查

对于当天选择的投手 $\textit{pitcher}$，需要检查它是否在前 $4$ 天中出现过。具体地：
- 第 $\textit{day}-4$ 天使用的投手排名为 $a$，其实际投手编号为 $\textit{best}[d_{\textit{day}-4}][a]$
- 第 $\textit{day}-3$ 天使用的投手排名为 $b$，其实际投手编号为 $\textit{best}[d_{\textit{day}-3}][b]$
- 第 $\textit{day}-2$ 天使用的投手排名为 $c$，其实际投手编号为 $\textit{best}[d_{\textit{day}-2}][c]$
- 第 $\textit{day}-1$ 天使用的投手排名为 $d$，其实际投手编号为 $\textit{best}[d_{\textit{day}-1}][d]$

如果 $\textit{pitcher}$ 与其中任何一个相同，则发生冲突，不能选择该投手。

### 答案计算

遍历所有 $\textit{dp}$ 状态，取最大值即为最大期望胜率（整数形式，需要除以 $100$ 转换为小数）。

## 复杂度分析

- 预处理每支球队的胜率排序：$O(m \cdot n \log n)$，$m \le 30$，$n \le 100$，可忽略。
- 动态规划：天数 $O(g+10)$，状态数 $O(6^4) = 1296$，每状态转移 $O(5)$，总复杂度 $O((g+10) \times 6^4 \times 5) \approx 200 \times 1296 \times 5 \approx 1.3 \times 10^6$，非常快。
- 空间复杂度：$O(6^4)$，使用滚动数组后为常数。

## 代码实现

```cpp
// Pitcher Rotation
// UVa ID: 1379
// Verdict: Accepted
// Submission Date: 2026-06-13
// UVa Run Time: 0.630s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 110;
const int MAXG = 250;
const int MAXK = 15;  // 候选投手最大数量，实际上由于在线测试数据较弱，设置为 6 也可以通过，运行时间更短

int n, m, g, days;
int win[MAXN][MAXN];
int schedule[MAXG];
int best[MAXN][MAXK];
int dp[2][MAXK][MAXK][MAXK][MAXK];

int main() {
    int T;
    scanf("%d", &T);
    while (T--) {
        scanf("%d%d%d", &n, &m, &g);
        days = g + 10;

        for (int i = 1; i <= m; i++)
            for (int j = 1; j <= n; j++)
                scanf("%d", &win[i][j]);

        for (int i = 1; i <= days; i++)
            scanf("%d", &schedule[i]);

        // 预处理每个对手的前 MAXK-1 名投手
        for (int i = 1; i <= m; i++) {
            pair<int, int> pitchers[MAXN];
            for (int j = 1; j <= n; j++)
                pitchers[j] = make_pair(win[i][j], j);
            sort(pitchers + 1, pitchers + n + 1,
                 [](const pair<int, int>& a, const pair<int, int>& b) {
                     return a.first > b.first;
                 });
            int cnt = 0;
            for (int k = 1; k <= n && cnt < MAXK - 1; k++)
                best[i][++cnt] = pitchers[k].second;
            for (int k = cnt + 1; k < MAXK; k++)
                best[i][k] = 0;
        }

        memset(dp, -1, sizeof(dp));
        dp[0][0][0][0][0] = 0;

        int cur = 0, pre = 1;
        int ans = 0;

        for (int day = 1; day <= days; day++) {
            cur ^= 1;
            pre ^= 1;
            memset(dp[cur], -1, sizeof(dp[cur]));

            int team = schedule[day];

            for (int a = 0; a < MAXK; a++) {
                for (int b = 0; b < MAXK; b++) {
                    for (int c = 0; c < MAXK; c++) {
                        for (int d = 0; d < MAXK; d++) {
                            int last_val = dp[pre][a][b][c][d];
                            if (last_val == -1) continue;

                            if (team == 0) {
                                // 没有比赛，状态平移
                                int& target = dp[cur][b][c][d][0];
                                if (last_val > target) target = last_val;
                                if (last_val > ans) ans = last_val;
                            } else {
                                // 有比赛，尝试所有候选投手
                                for (int k = 1; k < MAXK; k++) {
                                    int pitcher = best[team][k];
                                    if (pitcher == 0) continue;

                                    bool conflict = false;
                                    if (day - 4 >= 1 && schedule[day - 4] != 0 && best[schedule[day - 4]][a] == pitcher) conflict = true;
                                    if (!conflict && day - 3 >= 1 && schedule[day - 3] != 0 && best[schedule[day - 3]][b] == pitcher) conflict = true;
                                    if (!conflict && day - 2 >= 1 && schedule[day - 2] != 0 && best[schedule[day - 2]][c] == pitcher) conflict = true;
                                    if (!conflict && day - 1 >= 1 && schedule[day - 1] != 0 && best[schedule[day - 1]][d] == pitcher) conflict = true;

                                    if (conflict) continue;

                                    int val = last_val + win[team][pitcher];
                                    int& target = dp[cur][b][c][d][k];
                                    if (val > target) target = val;
                                    if (val > ans) ans = val;
                                }
                            }
                        }
                    }
                }
            }
        }

        printf("%d.%02d\n", ans / 100, ans % 100);
    }
    return 0;
}
```

## 总结

本题的核心技巧是**贪心剪枝**与**基于排名编码的 $\texttt{DP}$**：

1. **贪心剪枝**：由于休息约束，每支球队只需要考虑胜率最高的前若干名投手（通常为 $5$ 名）。这大幅缩小了候选集，使得 $\texttt{DP}$ 状态可控。

2. **排名编码**：$\texttt{DP}$ 状态存储的是投手在其对应对手球队中的排名，而非投手编号。这样既压缩了状态空间，又能在冲突检查时通过 $\textit{best}$ 数组快速还原投手编号。

3. **滚动数组**：由于天数较多，使用滚动数组优化空间，避免存储所有天的状态。

4. **注意并列情况**：当第 $5$ 名存在并列时，需要适当扩大候选池（如取前 $15$ 名），否则可能遗漏最优解，不过在线测试数据较弱，用 $5$ 即可通过。

本题是动态规划与贪心结合的良好范例，展示了如何利用问题特性进行剪枝，将指数级问题转化为多项式时间可解的问题。
