## 题目描述

有一家比萨店位于一条笔直的道路上，道路上有许多房屋作为比萨店的顾客。 为了吸引更多订单，店主宣布将对延迟配送收取罚金：订单下达后经过某个指定时间后开始计罚，每单位时间罚金 $1$ 韩元。 今天路上所有房屋在同一时间订了比萨，且配送刚开始时罚金开始计算。 在忙碌的日子，如果某顾客的延迟罚金超过卖比萨的收入，店主可以选择不给他配送。 请编写程序帮助店主决定应该给哪些顾客配送、跳过哪些顾客，以使总利润最大。

配送利润 $=$ 收入 $-$ 延迟罚金。 假设配送员移动速度为每单位时间走 $1$ 单位距离，递交比萨时间不计。

**输入格式**  
第一行包含一个整数 $T$ ，表示测试用例的数量。  
每个测试用例包含三行：  
- 第一行：一个整数 $n$ $(1 \le n \le 100)$ ，表示顾客数量。  
- 第二行： $n$ 个整数 $p_1, p_2, \dots, p_n$ $(p_1 < p_2 < \dots < p_n$ 且 $p_i \ne 0$ ， $i = 1, \dots, n)$ ，表示第 $i$ 个顾客相对于比萨店的位置。  
- 第三行： $n$ 个整数 $e_1, e_2, \dots, e_n$ $(e_i > 0$ ， $i = 1, \dots, n)$ ，表示给第 $i$ 个顾客送比萨可获得的收入。

**输出格式**  
对每个测试用例输出一行，包含一个整数，表示最大利润。

## 题目分析

### 问题核心

本题的关键在于：  
1. **顾客可选择配送或不配送** ：当配送某顾客的利润为负时，选择不配送可获得更高的总利润。  
2. **罚金随时间累积** ：每过 $1$ 单位时间，所有 **已决定要配送但尚未送达** 的顾客都会产生 $1$ 韩元的罚金。  
3. **配送顺序影响利润** ：不同的配送顺序会导致不同的累计罚金，从而影响总利润。

### 关键观察

设我们决定配送 $k$ 个顾客，这些顾客按某种顺序排列。 当配送员从一个位置移动到另一个位置时，所花费的时间会对所有 **尚未送达** 的顾客产生罚金。 如果还有 $cnt$ 个顾客尚未送达（包括即将送达的那一位），那么移动 $d$ 单位距离就会产生 $cnt \times d$ 的罚金。

### 动态规划状态设计

为了处理“选择配送哪些顾客”以及“以什么顺序配送”这两个问题，我们采用记忆化搜索（ $\texttt{DFS}$ + 记忆化）的方法，状态设计如下：

- 定义 $dp[s][e][cnt][pos]$ 表示：  
  - 已经考虑了区间 $[s, e]$ 内的顾客（这些顾客 **决定不配送** ）。  
  - 还需要配送 $cnt$ 个顾客。  
  - 配送员当前位置在 $s$ （当 $pos = 0$ ）或在 $e$ （当 $pos = 1$ ）。

**为什么这样设计？**  
1. 区间 $[s, e]$ 表示已经考虑过且决定不配送的顾客，这样可以保证在状态转移时不会重复考虑这些顾客。  
2. $cnt$ 表示 **还需要配送的顾客数量** ，这个参数至关重要，因为它决定了罚金的计算系数。  
3. $pos$ 记录了配送员的当前位置，以便计算移动距离。

### 状态转移

设当前状态为 $(s, e, cnt, pos)$ ，当前位置为 $currentPos$ （若 $pos = 0$ 则 $currentPos = p[s]$ ，否则 $currentPos = p[e]$ ）。 我们需要选择下一个配送的顾客 $i$ ，它必须不在区间 $[s, e]$ 内（即尚未考虑过）。

- 若 $i$ 在区间左侧（ $i < s$ ）：配送员从 $currentPos$ 移动到 $p[i]$ ，距离为 $|p[i] - currentPos|$ 。 由于还有 $cnt$ 个顾客（包括 $i$ ）尚未送达，移动这段距离产生的罚金为 $cnt \times |p[i] - currentPos|$ 。 配送顾客 $i$ 获得的利润为 $e[i] - cnt \times |p[i] - currentPos|$ 。 之后状态更新为 $(i, e, cnt-1, 0)$ （配送员停在 $i$ 处）。
- 若 $i$ 在区间右侧（ $i > e$ ）：同理，利润为 $e[i] - cnt \times |p[i] - currentPos|$ ，之后状态更新为 $(s, i, cnt-1, 1)$ 。

转移时取所有可能选择的最大值。

### 初始化与答案计算

我们不知道最优解中会配送多少个顾客，因此需要枚举 $k = 1, 2, \dots, n$ ，尝试配送 $k$ 个顾客的情况。

对于每个 $k$ ，枚举第一个配送的顾客 $i$ ：  
- 从比萨店（位置 $0$ ）出发到顾客 $i$ ，距离为 $|p[i]|$ 。  
- 此时还有 $k$ 个顾客（包括 $i$ ）需要配送，因此产生的罚金为 $k \times |p[i]|$ 。  
- 初始利润为 $e[i] - k \times |p[i]|$ 。  
- 之后递归计算剩下的 $k-1$ 个顾客：状态为 $(i, i, k-1, 0)$ 。

最终答案为所有 $k$ 和所有起始顾客 $i$ 对应的利润最大值。

### 复杂度分析

- 状态总数： $O(n^3)$ （ $s, e, cnt$ 各 $O(n)$ ， $pos$ 为常数 $2$ ）。  
- 每个状态转移需要枚举下一个顾客，最坏 $O(n)$ 。  
- 外层枚举 $k$ 和起始顾客 $i$ ： $O(n^2)$ 。  
- 总时间复杂度： $O(n^4) \approx 100^4 = 10^8$ ，在题目限制下（ $n \le 100$ ）可以接受，因为实际运行时有大量状态不会访问到，且常数较小。  
- 空间复杂度： $O(n^3)$ ，用于存储记忆化搜索的结果。

### 样例验证

以题目中的第一个样例为例：

```
5
-6 -3 -1 2 5
27 10 2 5 20
```

最优解配送 $4$ 个顾客： $c_3, c_2, c_1, c_5$ （对应位置 $-1, -3, -6, 5$ ，收入 $2, 10, 27, 20$ ）。

计算过程：  
1. 从 $0$ 到 $-1$ ：距离 $1$ ，罚金 $4 \times 1 = 4$ ，利润 $2 - 4 = -2$ 。  
2. 从 $-1$ 到 $-3$ ：距离 $2$ ，还有 $3$ 个顾客未送达，罚金 $3 \times 2 = 6$ ，利润 $10 - 6 = 4$ ，累计 $2$ 。  
3. 从 $-3$ 到 $-6$ ：距离 $3$ ，还有 $2$ 个顾客未送达，罚金 $2 \times 3 = 6$ ，利润 $27 - 6 = 21$ ，累计 $23$ 。  
4. 从 $-6$ 到 $5$ ：距离 $11$ ，还有 $1$ 个顾客未送达，罚金 $1 \times 11 = 11$ ，利润 $20 - 11 = 9$ ，累计 $32$ 。

最终总利润为 $32$ ，与样例输出一致。

## 代码实现

```cpp
// Pizza Delivery
// UVa ID: 1628
// Verdict: Accepted
// Submission Date: 2025-12-30
// UVa Run Time: 0.000s
//
// 版权所有（C）2025，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 105;

int cases;
int n;
int pos[MAXN], earn[MAXN];
int dp[MAXN][MAXN][MAXN][2];
bool visited[MAXN][MAXN][MAXN][2];

// s,e: 已经考虑了区间[s,e]（这些顾客不送）
// cnt: 还需要送的顾客数量
// position: 0=在s位置，1=在e位置
int dfs(int s, int e, int cnt, int position) {
    if (cnt == 0) return 0;
    if (visited[s][e][cnt][position]) return dp[s][e][cnt][position];
    visited[s][e][cnt][position] = true;
    int &answer = dp[s][e][cnt][position];
    answer = 0;
    int currentPos = (position == 0) ? pos[s] : pos[e];
    // 考虑下一个要送的顾客
    if (position == 0) {  // 当前在s位置
        // 选择左边还没考虑的顾客（0 ~ s-1）
        for (int i = 0; i < s; i++) {
            int distance = abs(pos[i] - currentPos);
            int profit = earn[i] - cnt * distance;
            answer = max(answer, profit + dfs(i, e, cnt - 1, 0));
        }
        // 选择右边还没考虑的顾客（e+1 ~ n-1）
        for (int i = e + 1; i < n; i++) {
            int distance = abs(pos[i] - currentPos);
            int profit = earn[i] - cnt * distance;
            answer = max(answer, profit + dfs(s, i, cnt - 1, 1));
        }
    } else {  // 当前在e位置
        // 选择左边还没考虑的顾客（0 ~ s-1）
        for (int i = 0; i < s; i++) {
            int distance = abs(pos[i] - currentPos);
            int profit = earn[i] - cnt * distance;
            answer = max(answer, profit + dfs(i, e, cnt - 1, 0));
        }
        // 选择右边还没考虑的顾客（e+1 ~ n-1）
        for (int i = e + 1; i < n; i++) {
            int distance = abs(pos[i] - currentPos);
            int profit = earn[i] - cnt * distance;
            answer = max(answer, profit + dfs(s, i, cnt - 1, 1));
        }
    }
    return answer;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int T; cin >> T;
    for (cases = 1; cases <= T; cases++) {
        cin >> n;
        for (int i = 0; i < n; i++) cin >> pos[i];
        for (int i = 0; i < n; i++) cin >> earn[i];
        // 初始化visited数组
        memset(visited, 0, sizeof(visited));
        int answer = 0;
        // 枚举总共要送的人数k
        for (int k = 1; k <= n; k++) {
            // 枚举第一个送的顾客
            for (int i = 0; i < n; i++) {
                // 从0点出发到顾客i，花费时间abs(pos[i])，产生罚金k * abs(pos[i])
                int profit = earn[i] - k * abs(pos[i]);
                answer = max(answer, profit + dfs(i, i, k - 1, 0));
            }
        }
        cout << answer << "\n";
    }
    return 0;
}
```

## 总结

本题是一道经典的动态规划问题，难点在于如何设计状态以同时处理“选择顾客”和“确定顺序”两个子问题。 通过将“还需要配送的顾客数量” $cnt$ 作为状态参数，我们可以正确计算移动产生的罚金。 采用记忆化搜索实现，代码简洁且效率足够。 理解状态设计的含义是解决此题的关键。
