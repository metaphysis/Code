[UVa 10418 Hyper Toy Soldiers](https://blog.csdn.net/metaphysis/article/details/156570887)

## 题目描述

$\texttt{Alan}$ 的父亲给他买了一盒玩具士兵，包含 $k$ 个红色士兵、$k$ 个绿色士兵和 $1$ 个金色士兵。有一个 $m \times n$ 的棋盘，每个格子有一个高度 $h_{i,j}$ 。初始时，每个士兵被放置在一个格子上（不一定各不相同），并且选定了 $t$ 个目标格子，每个目标格子有一个“重要值” $r_i$ 。目标是通过移动士兵，使得第 $i$ 个目标格子上恰好有 $r_i$ 个士兵。每个士兵必须位于这 $t$ 个目标格子之一，因此保证所有 $r_i$ 的总和等于 $2k + 1$ 。

每次移动时，一个士兵可以移动到相邻（上、下、左、右）的格子，但不能移出棋盘。红色士兵只能向上爬，因此只有当目标格子的高度不低于当前格子时才能移动；绿色士兵只能向下跳，因此只有当目标格子的高度不高于当前格子时才能移动；金色士兵可以在棋盘上自由移动。

由于可能无法达成目标，$\texttt{Alan}$ 被允许使用一种魔法。每次使用魔法时，他可以对所有士兵进行任意多次交换（即可以进行任意排列，但不能移动任何士兵）。

请帮助 $\texttt{Alan}$ 使用尽可能少的魔法次数来达成目标。

## 题目分析

### 核心难点

1. **移动限制**：红色士兵只能向上（非下降）移动，绿色士兵只能向下（非上升）移动，金色士兵无限制。
2. **魔法机制**：一次魔法可以进行任意多次交换，相当于可以重新排列所有士兵的身份（类型和位置的绑定关系）。
3. **目标约束**：每个目标格子有特定的容量要求，需要精确分配士兵。

### 关键观察

1. **魔法的本质**：一次魔法可以交换任意两个士兵的身份（类型）。这意味着如果士兵 $A$ 无法到达目标 $X$ ，但可以到达目标 $Y$ ，而士兵 $B$ 无法到达目标 $Y$ ，但可以到达目标 $X$ ，那么通过一次魔法交换 $A$ 和 $B$ 的身份，两个士兵都能到达目标。
2. **状态扩展**：由于魔法可以改变士兵类型，一个士兵从起点到目标的过程可以描述为：
   - 从起点以初始类型移动若干步
   - 使用魔法改变类型（可能需要多次）
   - 以新类型继续移动
   - 重复上述过程
3. **最小魔法次数**：问题转化为寻找最小的整数 $M$ ，使得存在一种分配方案，每个士兵到其目标所需的魔法次数不超过 $M$ 。

### 算法思路

#### 1. 计算最小魔法次数

对于每个士兵和目标格子，我们需要计算从士兵起点到目标格子的**最小所需魔法次数**。这可以通过一个**扩展的 $\texttt{BFS}$** 来实现。

**状态定义**： $(x, y, type, casted)$ ，其中：
- $(x, y)$：当前坐标
- $type$：当前士兵类型（$0$ 表示红色，$1$ 表示绿色）
- $casted$：已使用的魔法次数

**状态转移**：
- **移动**：如果从 $(x, y)$ 到 $(nx, ny)$ 的移动符合当前类型的规则（红色不能下降，绿色不能上升），则转移到 $(nx, ny, type, casted)$ ，魔法次数不变。
- **交换**：在任何位置，可以使用一次魔法改变士兵类型，即转移到 $(x, y, 1-type, casted+1)$ 。

通过 $\texttt{BFS}$ 计算从起点 $(sx, sy,$初始类型$, 0)$ 到目标格子 $(gx, gy)$ 的最小 $casted$ 值，即为该士兵到达该目标所需的最小魔法次数。

#### 2. 二分答案 + 最大流检查

由于直接求解最小魔法次数较困难，我们采用**二分答案**的方法：

1. **二分范围**：魔法次数 $M$ 的范围是 $[0, 2k+1]$ （最多交换所有士兵）。
2. **检查可行性**：对于给定的 $M$ ，检查是否存在分配方案，使得每个士兵到其目标的魔法次数不超过 $M$ 。

**检查方法**：构建一个二分图，使用**最大流**算法判断是否存在满足条件的分配。

- **左侧节点**： $2k$ 个红绿士兵（金色士兵单独处理）
- **右侧节点**： $t$ 个目标格子，每个节点的容量为 $r_i$ （目标格子的需求数量）
- **边**：如果士兵 $i$ 到目标 $j$ 的最小魔法次数 $\leq M$ ，则添加一条容量为 $1$ 的边
- **源点** → 士兵：容量 $1$
- **目标** → 汇点：容量 $r_i$

计算最大流 $F$ ，如果满足 $F + M \geq 2k$ ，则说明在最多使用 $M$ 次魔法的情况下，可以分配所有红绿士兵。

**解释**： $F$ 表示可以直接匹配（无需额外魔法）的士兵数量， $2k - F$ 表示需要通过魔法重新分配的士兵数量。由于一次魔法可以进行任意多次交换， $M$ 次魔法可以解决至少 $M$ 个士兵的分配问题。因此，条件 $F + M \geq 2k$ 确保所有士兵都能被分配。

**金色士兵的处理**：金色士兵可以自由移动，因此不需要魔法即可到达任何目标。在算法中，我们只需要确保红绿士兵分配后，剩余的位置由金色士兵填补即可。

## 算法步骤

1. **读入数据**：包括棋盘大小、士兵位置、目标格子、高度信息。
2. **预处理**：对每个红绿士兵，使用扩展 $\texttt{BFS}$ 计算到每个目标格子的最小魔法次数。
3. **二分答案**：在范围 $[0, 2k+1]$ 内二分查找最小的魔法次数 $M$ 。
4. **检查可行性**：对每个 $M$ ，构建网络流图并计算最大流，检查是否满足 $F + M \geq 2k$ 。
5. **输出结果**：最小的满足条件的 $M$ 。

## 时间复杂度分析

- **预处理 $\texttt{BFS}$**：每个士兵执行一次 $\texttt{BFS}$ ，状态数为 $O(m \times n \times 2)$ ，每个状态扩展 $4$ 个方向，总复杂度 $O(2k \times m \times n \times 4) = O(k \cdot m \cdot n)$ 。
- **二分答案**： $O(\log k)$ 次检查。
- **每次检查的最大流**：节点数 $O(2k + t)$ ，边数 $O(2k \cdot t)$ ，使用 Dinic 算法复杂度 $O(E \sqrt{V}) = O((2k \cdot t) \sqrt{2k + t})$ 。
- **总复杂度**： $O(k \cdot m \cdot n + \log k \cdot (k \cdot t) \sqrt{k + t})$ ，在题目数据范围内可接受。

```cpp
// Hyper Toy Soldiers

#include <bits/stdc++.h>
using namespace std;

// 士兵类型常量
#define RED 0    // 红色士兵
#define BLUE 1   // 绿色士兵（代码中使用 BLUE 表示绿色）

const int INF = 0x3f3f3f3f;        // 无穷大
const int MAXN = 105;              // 最大棋盘大小
const int MAXV = 305;              // 最大节点数
const int MAXE = 40010;            // 最大边数
const int dx[4] = {1, -1, 0, 0};   // 四个移动方向
const int dy[4] = {0, 0, 1, -1};

// 输入数据
int m, n, k, t;                    // 棋盘大小，红/绿士兵数，目标格子数
int height[MAXN][MAXN];            // 棋盘高度
int goalX[MAXN], goalY[MAXN];      // 目标格子坐标
int goalR[MAXN];                   // 目标格子需求数量
int startX[MAXN], startY[MAXN];    // 士兵起始坐标

// 链式前向星最大流数据结构
struct Arc { 
    int to;         // 目标节点
    int capacity;   // 边容量
    int next;       // 下一条边索引
} arcs[MAXE * 2];   // 正反两条边

int head[MAXV];     // 每个节点的第一条边
int idx;            // 当前边索引
int source, sink;   // 源点和汇点
int level[MAXV];    // 分层图层级
int current[MAXV];  // 当前弧优化

// 添加边
void addEdge(int from, int to, int capacity) {
    arcs[idx] = {to, capacity, head[from]};
    head[from] = idx++;
    arcs[idx] = {from, 0, head[to]};
    head[to] = idx++;
}

// BFS 构建分层图
bool bfs() {
    memset(level, -1, sizeof level);
    queue<int> q;
    level[source] = 0;
    q.push(source);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int i = head[u]; ~i; i = arcs[i].next) {
            int v = arcs[i].to;
            if (arcs[i].capacity > 0 && level[v] == -1) {
                level[v] = level[u] + 1;
                q.push(v);
                if (v == sink) return true;
            }
        }
    }
    return level[sink] != -1;
}

// DFS 寻找增广路
int dfs(int u, int flow) {
    if (u == sink) return flow;
    int volume = 0;
    for (int& i = current[u]; ~i; i = arcs[i].next) {
        int v = arcs[i].to, r = arcs[i].capacity;
        if (level[v] == level[u] + 1 && r > 0) {
            int volume = dfs(v, min(r, flow));
            if (volume > 0) {
                arcs[i].capacity -= volume;
                arcs[i ^ 1].capacity += volume;
                return volume;
            }
        }
    }
    return 0;
}

// Dinic 最大流算法
int maxFlow() {
    int flow = 0;
    while (bfs()) {
        for (int i = 0; i < MAXV; i++) current[i] = head[i];
        while (int delta = dfs(source, INF))
            flow += delta;
    }
    return flow;
}

// 扩展 BFS：计算从起点到所有位置的最小魔法次数
int dist[MAXN][MAXN];  // 到达每个位置的最小魔法次数
void initialize(int sx, int sy, int type) {
    // 初始化距离为无穷大
    memset(dist, INF, sizeof dist);
    
    // 队列元素：(x, y, 当前类型, 已使用魔法次数)
    queue<tuple<int, int, int, int>> q;
    dist[sx][sy] = 0;
    q.push({sx, sy, type, 0});
    
    while (!q.empty()) {
        auto [x, y, type, casted] = q.front(); q.pop();
        
        // 尝试四个方向的移动
        for (int d = 0; d < 4; d++) {
            int nx = x + dx[d], ny = y + dy[d];
            if (nx < 1 || nx > m || ny < 1 || ny > n) continue;
            
            // 如果已经有更优解，跳过
            if (dist[nx][ny] <= casted) continue;
            
            // 检查当前类型是否可以移动到这个位置
            bool continuing = false;
            if (type == RED) 
                continuing = height[nx][ny] >= height[x][y];  // 红色不能下降
            else 
                continuing = height[nx][ny] <= height[x][y];  // 绿色不能上升
            
            if (continuing) {
                // 可以不使用魔法直接移动
                dist[nx][ny] = casted;
                q.push({nx, ny, type, casted});
            } else {
                // 需要使用魔法改变类型后才能移动
                if (dist[nx][ny] > casted + 1) {
                    dist[nx][ny] = casted + 1;
                    q.push({nx, ny, 1 - type, casted + 1});
                }
            }
        }
    }
}

// magicNeeded[i][j]: 士兵 i 到达目标 j 所需的最小魔法次数
int magicNeeded[MAXN][MAXN];

// 检查是否可以在 magicUsed 次魔法内完成分配
bool check(int magicUsed) {
    int soldierCount = 2 * k;  // 红绿士兵总数
    int goalCount = t;         // 目标格子数
    
    // 初始化图
    idx = 0;
    memset(head, -1, sizeof head);
    source = 0;
    sink = soldierCount + goalCount + 1;
    
    // 源点连接到所有士兵
    for (int i = 1; i <= soldierCount; i++) 
        addEdge(source, i, 1);
    
    // 目标格子连接到汇点，容量为目标需求数
    for (int i = 0; i < goalCount; i++) 
        addEdge(soldierCount + i + 1, sink, goalR[i]);
    
    // 添加士兵到目标格子的边（如果所需魔法次数不超过限制）
    for (int i = 0; i < 2 * k; i++)
        for (int j = 0; j < goalCount; j++)
            if (magicNeeded[i][j] <= magicUsed)
                addEdge(i + 1, soldierCount + j + 1, 1);
    
    // 计算最大流
    int flow = maxFlow();
    
    // 检查条件：已匹配的士兵数 + 可用魔法次数 >= 总士兵数
    return flow + magicUsed >= 2 * k;
}

int main() {
    // 加速输入输出
    cin.tie(0); cout.tie(0); ios::sync_with_stdio(false);
    
    int T;
    cin >> T;
    
    while (T--) {
        // 读入数据
        cin >> m >> n >> k >> t;
        
        // 读入士兵位置：前 k 个红，中间 k 个绿，最后 1 个金
        for (int i = 0; i < 2 * k + 1; i++) 
            cin >> startX[i] >> startY[i];
        
        // 读入目标格子
        for (int i = 0; i < t; i++) 
            cin >> goalX[i] >> goalY[i] >> goalR[i];
        
        // 读入棋盘高度
        for (int i = 1; i <= m; i++)
            for (int j = 1; j <= n; j++)
                cin >> height[i][j];
        
        // 预处理：计算每个红绿士兵到每个目标的最小魔法次数
        for (int i = 0; i < 2 * k; i++) {
            // 前 k 个是红色士兵，后 k 个是绿色士兵
            initialize(startX[i], startY[i], (i < k) ? RED : BLUE);
            
            // 记录到每个目标的魔法次数
            for (int j = 0; j < t; j++)
                magicNeeded[i][j] = dist[goalX[j]][goalY[j]];
        }
        
        // 二分答案：寻找最小魔法次数
        int left = 0, right = 2 * k + 1, answer = -1;
        while (left <= right) {
            int middle = (left + right) / 2;
            if (check(middle)) {
                answer = middle;
                right = middle - 1;
            } else {
                left = middle + 1;
            }
        }
        
        cout << answer << '\n';
    }
    
    return 0;
}
```

## 总结

本题是一道综合性较强的图论问题，涉及状态搜索、二分答案和网络流等多个知识点。关键解题思路包括：

1. **理解魔法机制**：一次魔法可以进行任意交换，这简化了问题，使我们可以独立计算每个士兵的最小魔法需求。
2. **状态扩展 $\texttt{BFS}$**：通过维护（位置, 类型, 魔法次数）状态，计算从起点到目标的最小魔法次数。
3. **二分答案 + 最大流**：将可行性检查转化为二分图匹配问题，利用最大流算法高效判断。

算法的时间复杂度在题目限制范围内，能够正确处理最大规模的数据。代码实现中需要注意网络流的建图和 $\texttt{BFS}$ 状态转移的正确性。
