## 题目描述

给定一个整数 $K$ ($1 < K < 16$)，要求构造一棵树和一个顶点顺序，使得贪心染色算法需要至少 $K$ 种颜色来给这棵树进行正常着色。

**约束条件**：
- 任何顶点的最大度数不超过 $K-1$
- 顶点数不超过 $2^{(K-1)}$
- 顶点编号从 $1$ 到 $N$

## 题目分析

这是一个图论构造问题，核心在于理解贪心染色算法的局限性。虽然树是二分图，理论上只需要 $2$ 种颜色就能正常着色，但贪心算法的性能严重依赖于顶点着色顺序。

**贪心染色算法**：给定顶点的一个排列，按顺序对每个顶点使用最小的可用颜色（不与已着色的邻居顶点颜色冲突）。

**关键洞察**：通过精心构造树结构和顶点顺序，可以迫使贪心算法使用尽可能多的颜色。具体来说，我们需要构造一个结构，使得某个顶点在着色时，它的所有邻居已经使用了 $K-1$ 种不同的颜色，从而迫使该顶点使用第 $K$ 种颜色。

## 解题思路

### 核心构造方法

使用 **"颜色强迫树"** 的构造方法，通过 $\texttt{BFS}$ 方式递归构建：

1. **根节点**：创建一个颜色为 $K$ 的根节点
2. **子节点生成**：对于每个颜色为 $c$ 的节点，为其创建 $c-1$ 个子节点，颜色分别为 $1, 2, \ldots, c-1$
3. **递归构建**：如果子节点的颜色大于 $1$，则继续为其生成子节点
4. **顶点顺序**：按照颜色从低到高的顺序排列所有顶点

### 算法正确性证明

这种构造方法能保证贪心算法需要恰好 $K$ 种颜色：

- **颜色 $1$ 的顶点**：都是叶子节点，可以安全使用颜色 $1$
- **颜色 $c$ 的顶点**：其父节点颜色为 $c+1$，且连接了颜色为 $1, 2, \ldots, c-1$ 的子节点
- **根节点**（颜色 $K$）：连接了颜色为 $1, 2, \ldots, K-1$ 的子节点，必须使用颜色 $K$

### 约束条件验证

- **最大度数**：根节点度数为 $K-1$，其他节点度数不超过 $K-2$
- **顶点数限制**：构造的树规模适中，满足 $N \leq 2^{(K-1)}$
- **树结构**：连通无环，满足树的定义

## 复杂度分析

- **时间复杂度**：$O(2^K)$，与构造的树规模相关
- **空间复杂度**：$O(2^K)$，存储树结构和顶点信息

```cpp
#include <bits/stdc++.h>

using namespace std;

void generateTestCase(int k) {
    vector<pair<int, int>> edges;
    vector<int> vertexColor; // 顶点编号 -> 颜色
    vector<vector<int>> colorVertices(k + 1); // 颜色 -> 顶点列表
    
    int nextVertexId = 1;
    
    // 使用BFS构造树
    queue<pair<int, int>> q; // (顶点编号, 颜色)
    
    // 从根节点开始，颜色为k
    int root = nextVertexId++;
    vertexColor.push_back(0); // 0-index填充
    vertexColor.push_back(k);
    colorVertices[k].push_back(root);
    q.push({root, k});
    
    while (!q.empty()) {
        auto [currentId, currentColor] = q.front();
        q.pop();
        
        // 如果当前颜色为1，不需要生成子节点
        if (currentColor == 1) continue;
        
        // 为当前节点生成子节点，颜色分别为1, 2, ..., currentColor-1
        for (int childColor = 1; childColor < currentColor; childColor++) {
            int childId = nextVertexId++;
            vertexColor.push_back(childColor);
            colorVertices[childColor].push_back(childId);
            
            // 添加边
            edges.push_back({currentId, childId});
            
            // 如果子节点颜色大于1，继续处理
            if (childColor > 1)
                q.push({childId, childColor});
        }
    }
    
    int n = nextVertexId - 1;
    int m = edges.size();
    
    // 构建顶点顺序：按颜色从低到高排列
    vector<int> order;
    for (int color = 1; color <= k; color++)
        for (int vertexId : colorVertices[color])
            order.push_back(vertexId);
    
    // 输出结果
    cout << n << " " << m << "\n";
    for (auto& e : edges)
        cout << e.first << " " << e.second << "\n";
    
    for (size_t i = 0; i < order.size(); i++) {
        if (i > 0) cout << " ";
        cout << order[i];
    }
    cout << "\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int k;
    while (cin >> k)
        generateTestCase(k);
    
    return 0;
}
```

## 示例分析

对于 $K = 3$ 的情况：

**构造的树**：
```
    1(color3)
   / \
2(color1) 3(color2)
          |
        4(color1)
```

**顶点顺序**：$2, 4, 3, 1$

**贪心染色过程**：
1. 顶点 $2$：颜色 $1$
2. 顶点 $4$：颜色 $1$（与 $2$ 不相邻）
3. 顶点 $3$：颜色 $2$（与 $4$ 相邻，颜色 $1$ 不可用）
4. 顶点 $1$：颜色 $3$（与 $2$-颜色 $1$、$3$-颜色 $2$ 相邻）

正好需要 $3$ 种颜色，符合要求。

## 总结

本题展示了贪心算法的局限性，通过精心构造可以使其性能达到最坏情况。这种"颜色强迫树"的构造方法具有通用性，可以应用于其他类似的算法分析问题。关键在于理解算法的执行过程，然后反向构造使其性能最差的输入实例。
