[UVa 11238 Innumerous Bowling Games](https://blog.csdn.net/metaphysis/article/details/157330759)

## 题目描述

霍默·杰·辛普森是一位狂热的保龄球玩家。最近他和朋友打球时总是得到相同的分数，但每局比赛至少有一帧是不同的。卡尔想知道霍默有多少种不同的方式可以打出特定的分数。

### 保龄球规则概述

一局保龄球由 $10$ 帧组成，每帧最多有两次投掷机会：

1.  **普通帧** ： 两次投击倒的瓶数之和为 $0$ 到 $9$ 分
2.  **补中（$\texttt{Spare}$）** ： 第二次投掷击倒所有剩余瓶，得 $10$ 分，并获得 **下一次投掷** 的瓶数作为奖励分
3.  **全中（$\texttt{Strike}$）** ： 第一次投掷击倒所有 $10$ 瓶，得 $10$ 分，并获得 **接下来两次投掷** 的瓶数作为奖励分
4.  **第 $10$ 帧特殊规则** ：
    -   补中后获得 $1$ 次额外投掷
    -   全中后获得 $2$ 次额外投掷
    -   额外投掷只计算奖励分

每帧最高可得 $30$ 分（三次投掷全中），总分为 $300$ 分。

## 题目分析

我们需要计算所有可能的保龄球对局中，总分为给定值 $s$ $(0 \le s \le 300)$ 的不同对局数量。

### 问题难点

1.  **状态空间大** ： 每帧有多种可能的结果（普通、补中、全中）
2.  **奖励分依赖** ： 当前帧的得分可能影响后续帧的奖励分计算
3.  **第 $10$ 帧特殊规则** ： 额外投掷使状态转移更复杂
4.  **计数要求** ： 需要枚举所有可能的投掷序列

### 暴力枚举不可行

每帧最多有 $66$ 种投掷组合（第一次 $0$ -$10$ 瓶，第二次 $0$ 到剩余瓶数）， $10$ 帧的总组合数为 $66^{10} \approx 1.6 \times 10^{18}$ ，显然不可行。

## 解题思路

### 核心思想：动态规划（记忆化搜索）

我们采用 **记忆化搜索（$\texttt{Memoization}$）** 来实现动态规划，从目标分数向下递减计算。

### 状态设计

定义状态 $(frame, remain, bonus1, bonus2)$ ：

-   $frame$ ： 当前处理的帧编号（ $1$ - $11$ ，其中 $11$ 用于处理第 $10$ 帧的额外投掷）
-   $remain$ ： 还需要获得的分数（从目标值递减）
-   $bonus1$ ： 当前帧 **第一次** 投掷需要乘以的奖励倍数
-   $bonus2$ ： 当前帧 **第二次** 投掷需要乘以的奖励倍数

**关键理解** ： $bonus1$ 和 $bonus2$ 表示的是 **当前帧** 投掷时需要额外加分的倍数。这些倍数是由 **之前** 帧的 $\texttt{strike}$ 或 $\texttt{spare}$ 产生的。

### 奖励机制详解

1.  **$\texttt{Spare}$（补中）** ： 当前帧是 $\texttt{spare}$ → 下一帧的第一次投掷得分要 **额外加一次** （即 $bonus1 = 1$ ）
2.  **$\texttt{Strike}$（全中）** ： 当前帧是 $\texttt{strike}$ → 下一帧的 **两次** 投掷得分都要额外加一次（即 $bonus1 = 1, bonus2 = 1$ ）
3.  **连续 $\texttt{Strike}$** ： 如果连续两帧都是 $\texttt{strike}$，那么第二帧的第二次投掷的奖励倍数会累积（即 $bonus2$ 可能为 $2$ ）

### 状态转移分析

#### 第 $1$ - $9$ 帧的处理（ $frame \le 10$ ）

对于第 $frame$ 帧（ $frame \le 10$ ，实际上处理第 $1$ - $9$ 帧）：

1.  **非全中情况** （第一次投掷 $first < 10$ ）：
    -   枚举第二次投掷 $second$ ，满足 $first + second \le 10$
    -   如果 $first + second < 10$ ： 普通帧，无奖励传给下一帧
    -   如果 $first + second = 10$ ： 补中（$\texttt{spare}$），下一帧第一次投掷获得 $1$ 倍奖励

2.  **全中情况** （ $first = 10$ ）：
    -   直接处理，下一帧两次投掷都获得奖励，且 $bonus2$ 的倍数要加 $1$ （因为可能连续 $\texttt{strike}$）

#### 第 $10$ 帧的处理（在 $frame = 11$ 时处理）

在代码中，第 $10$ 帧的额外投掷放在 $frame = 11$ 时统一处理：

1.  **没有额外投掷** （ $bonus1 = 0$ ）： 直接检查剩余分数是否为 $0$
2.  **只有一次额外投掷** （补中情况， $bonus2 = 0$ ）：
    -   枚举额外投掷击倒的瓶数 $extra$
3.  **有两次额外投掷** （全中情况， $bonus2 > 0$ ）：
    -   枚举第一次额外投掷 $extra1$
    -   根据 $extra1$ 的值决定第二次额外投掷 $extra2$ 的取值范围
        -   如果 $extra1 = 10$ （$\texttt{strike}$），则 $extra2$ 可以从 $0$ 到 $10$
        -   否则， $extra1 + extra2 \le 10$

### 分数计算

每次投掷的得分计算为： `击倒瓶数 + 击倒瓶数 × bonus倍数` 。注意，在非第 $10$ 帧中，如果该帧是普通帧或 $\texttt{spare}$，其基础分（ $first + second$ ）已经包含了两次投掷的瓶数，奖励分则通过 $bonus1$ 和 $bonus2$ 按次添加。对于 $\texttt{strike}$，其基础分固定为 $10$ ，但奖励分（即接下来两次投掷的得分）会在后续帧中作为 $bonus$ 加上。

### 算法复杂度

-   状态数： $frame$ ( $12$ ) × $remain$ ( $301$ ) × $bonus1$ ( $3$ ) × $bonus2$ ( $3$ ) ≈ $32,508$
-   每个状态的计算量： 最多枚举约 $10 \times 11 + 1 = 111$ 种情况（非 $\texttt{strike}$ 情况 $10 \times 11 = 110$ 种，$\texttt{strike}$ 情况 $1$ 种）
-   总计算量： 约 $3.6$ 百万次操作，完全可行。

### 边界条件处理

1.  **分数溢出** ： 如果 $remain < 0$ ，直接返回 $0$ （不可能达到目标）
2.  **游戏结束** ： 当 $frame > 11$ 时，检查 $remain \ \texttt{==} \  0$
3.  **第 $10$ 帧结束** ： 在 $frame = 11$ 中处理所有额外投掷后，进入 $frame = 12$ 判断结束。

## 代码实现与详细注释

```cpp
// Innumerous Bowling Games
// UVa ID: 11238
// Verdict: Accepted
// Submission Date: 2026-01-24
// UVa Run Time: 0.000s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net


#include <bits/stdc++.h>
using namespace std;

typedef long long ll;
ll dp[15][310][3][3];

// frame: 当前帧编号（1-10是正常帧，11处理第10帧的额外投掷）
// remain: 还需要获得的分数
// bonus1: 当前帧第一次投掷的奖励倍数
// bonus2: 当前帧第二次投掷的奖励倍数
ll dfs(int frame, int remain, int bonus1, int bonus2) {
    // 如果剩余分数为负，说明这条路径不可能达到目标分数
    if (remain < 0) return 0;
    // 所有帧都已处理完毕，检查是否恰好达到目标分数
    if (frame > 11) return remain == 0;
    // 记忆化：如果这个状态已经计算过，直接返回结果
    ll &result = dp[frame][remain][bonus1][bonus2];
    if (result != -1) return result;
    result = 0;
    if (frame <= 10) {
        // 处理非全中情况（第一次投掷击倒的瓶数first < 10）
        for (int first = 0; first < 10; ++first) {
            for (int second = 0; second <= 10; ++second) {
                // 确保两次投掷击倒的瓶数不超过10
                if (first + second < 10) {
                    // 普通帧：两次投掷后还有剩余瓶，无奖励传给下一帧
                    // 当前帧得分 = 基础分(first+second) + 奖励分(first*bonus1 + second*bonus2)
                    int score = (first + second) + first * bonus1 + second * bonus2;
                    // 下一帧没有来自当前帧的奖励
                    result += dfs(frame + 1, remain - score, 0, 0);
                } else if (first + second == 10) {
                    // 补中（spare）：第二次投掷清空所有剩余瓶
                    // 当前帧得分 = 10分 + 奖励分(first*bonus1 + second*bonus2)
                    int score = 10 + first * bonus1 + second * bonus2;
                    // 下一帧的第一次投掷将获得1倍奖励（对应bonus1=1）
                    result += dfs(frame + 1, remain - score, 1, 0);
                }
                // 注意：当first+second>10时，这种情况不会发生，所以不处理
            }
        }
        // 处理全中情况（strike）：第一次投掷就击倒所有10个瓶
        // 当前帧得分 = 10分 + 第一次投掷的奖励分(10*bonus1)
        // 注意：第二次投掷的奖励分会在下一帧作为bonus2被计算
        int strikeScore = 10 + 10 * bonus1;
        // 下一帧的两次投掷都将获得奖励：
        // bonus2 + 1: 下一帧第二次投掷的奖励倍数（累积可能存在的连续strike奖励）
        // 1: 下一帧第一次投掷的奖励倍数（因为当前帧是strike）
        result += dfs(frame + 1, remain - strikeScore, bonus2 + 1, 1);
    } else {
        // 第11帧：专门处理第10帧可能存在的额外投掷
        if (bonus1 > 0) {
            // 第10帧有额外投掷（说明第10帧是spare或strike）
            if (bonus2 == 0) {
                // spare情况：只有一次额外投掷
                for (int extra = 0; extra <= 10; ++extra) {
                    // 额外投掷的得分只计算奖励分（extra * bonus1）
                    int score = extra * bonus1;
                    result += dfs(frame + 1, remain - score, bonus2, 0);
                }
            } else {
                // strike情况：有两次额外投掷
                for (int extra1 = 0; extra1 <= 10; ++extra1) {
                    if (extra1 == 10) {
                        // 第一次额外投掷也是strike
                        for (int extra2 = 0; extra2 <= 10; ++extra2) {
                            // 得分 = 第一次额外投掷的奖励分 + 第二次额外投掷的奖励分
                            int score = 10 * bonus1 + extra2 * bonus2;
                            result += dfs(frame + 1, remain - score, 0, 0);
                        }
                    } else {
                        // 第一次额外投掷不是strike
                        for (int extra2 = 0; extra1 + extra2 <= 10; ++extra2) {
                            // 得分 = 两次额外投掷的奖励分
                            int score = extra1 * bonus1 + extra2 * bonus2;
                            result += dfs(frame + 1, remain - score, 0, 0);
                        }
                    }
                }
            }
        } else {
            // 第10帧没有额外投掷（普通帧），直接检查是否完成
            result += (remain == 0);
        }
    }
    return result;
}

int main() {
    // 初始化记忆化数组为-1，表示未计算
    memset(dp, -1, sizeof(dp));
    int score;
    // 读取每个测试用例，直到遇到-1
    while (cin >> score && score != -1) {
        // 从第1帧开始，需要获得score分，初始没有任何奖励倍数
        cout << dfs(1, score, 0, 0) << '\n';
    }
    return 0;
}
```

## 代码核心逻辑详解

### 1. 记忆化数组
```cpp
ll dp[15][310][3][3];
```
- 第一维 $frame$ ： 帧编号 $1$ - $12$ （实际使用到 $11$ ，多开空间防越界）
- 第二维 $remain$ ： 剩余需要获得的分数 $0$ - $300$
- 第三维 $bonus1$ ： 奖励倍数 $0$ - $2$ （ $0$ 无奖励， $1$ 或 $2$ 表示需要加 $1$ 倍或 $2$ 倍）
- 第四维 $bonus2$ ： 同上

### 2. 递归函数参数含义
- `frame`： 当前正在处理哪一帧。注意，当处理到第 $11$ 帧时，实际上是在结算第 $10$ 帧可能存在的额外投掷。
- `remain`： 从目标分数中减去已经获得的分数后， **还需要** 多少分。这是一种 **倒着算** 的思路，比正着累加更容易处理奖励分。
- `bonus1`： 当前帧的第一次投掷，其得分需要乘以的倍数。例如，如果上一帧是 $\texttt{spare}$，那么 `bonus1 = 1`，意味着当前帧第一次投掷击倒 $k$ 瓶，除了得到 $k$ 基础分外，还能为上一帧额外贡献 $k$ 分。
- `bonus2`： 当前帧的第二次投掷，其得分需要乘以的倍数。意义同 `bonus1`。

### 3. 第 $1$ - $9$ 帧的转移
这部分代码枚举了当前帧所有可能的投掷结果 `(first, second)`：
- **普通帧** (`first + second < 10`)： 当前帧得分就是 `first+second` 加上应得的奖励分。下一帧没有来自当前帧的奖励，所以传递 `(0, 0)`。
- **补中** (`first + second == 10`)： 当前帧得 $10$ 分加上奖励分。由于是 $\texttt{spare}$，下一帧的第一次投掷将获得奖励，所以传递 `(1, 0)`。
- **全中**： 这是一个特例，不在 `first < 10` 的循环里。单独处理，得分是 $10$ 加上第一次投掷的奖励分（`10 * bonus1`）。对于下一帧，因为当前帧是 $\texttt{strike}$，所以下一帧的两次投掷都要奖励。 `bonus2 + 1` 体现了连续 $\texttt{strike}$ 时奖励倍数的累积。

### 4. 第 $10$ 帧的转移（在 `frame == 11` 时）
这是本题最复杂的部分，需要正确处理第 $10$ 帧的额外投掷规则：
- 如果 `bonus1 == 0`： 意味着第 $10$ 帧是一个普通帧，没有额外投掷，直接判断剩余分数是否为 $0$。
- 如果 `bonus1 > 0` 且 `bonus2 == 0`： 意味着第 $10$ 帧是 $\texttt{spare}$，有 $1$ 次额外投掷。枚举这次投掷击倒的瓶数 `extra`，其得分只作为奖励分（`extra * bonus1`）加入总分。
- 如果 `bonus1 > 0` 且 `bonus2 > 0`： 意味着第 $10$ 帧是 $\texttt{strike}$，有 $2$ 次额外投掷。需要枚举两次投掷的结果 `(extra1, extra2)`，并注意第二次投掷的瓶数可能受第一次影响（如果第一次不是 $\texttt{strike}$）。

### 5. 主函数流程
1.  初始化记忆化数组。
2.  循环读入目标分数 `score`。
3.  调用 `dfs(1, score, 0, 0)` 计算方案数并输出。
4.  遇到 `-1` 结束。

## 算法优化与技巧总结

### 1. 倒序计算的优势
从目标分数向下递减（`remain`）而非从 $0$ 向上累加，是本解法的关键。它避免了在状态中携带“已获得奖励分但未结算”的复杂信息，使得状态定义非常简洁。

### 2. 状态压缩的精妙
仅用两个参数 `(bonus1, bonus2)` 就编码了所有必要的奖励信息，体现了出色的状态压缩思想。

### 3. 分离处理第 $10$ 帧
将第 $10$ 帧的特殊逻辑（额外投掷）放到 `frame == 11` 中处理，使得前 $9$ 帧的状态转移逻辑保持统一和清晰，是模块化思维的体现。

### 4. 记忆化搜索的实现
使用引用 `ll &result` 来更新和返回记忆化数组中的值，是竞赛编程中的常见技巧，既简洁又高效。

## 总结

本题是一个经典的动态规划计数问题，难度在于对保龄球复杂规则的建模。通过设计 `(frame, remain, bonus1, bonus2)` 四维状态，并采用倒序计算和记忆化搜索，我们成功地将一个看似指数级的问题转化为一个仅有数万个状态、可在瞬间求解的问题。解决此题不仅需要熟练掌握动态规划，还需要细心分析游戏规则并将其转化为可计算的状态转移方程。本题的解法展示了算法设计在解决复杂现实问题中的强大能力。
