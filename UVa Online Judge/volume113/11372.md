[UVa 11372 Arranging a Contest](https://blog.csdn.net/metaphysis/article/details/161948390)

## 题目描述

$\texttt{NPS}$ 需要从题库中选出 $6$ 道题目作为新手赛的赛题。每道题目有唯一的 $\texttt{ID}$、一个难度等级（ $\texttt{E}$ 表示容易、$\texttt{M}$ 表示中等、$\texttt{H}$ 表示困难 ）、一个类型（ $\texttt{D}$ 表示动态规划、$\texttt{G}$ 表示图论、$\texttt{M}$ 表示数学、$\texttt{X}$ 表示其他 ）和一个喜好指数（整数）。选择需要满足以下条件：

- 恰好有 $2$ 道容易题（ $\texttt{E}$ ）和 $2$ 道困难题（ $\texttt{H}$ ）。
- 至少有 $2$ 道 $\texttt{DP}$ 题（类型 $\texttt{D}$ ）、至少 $1$ 道图论题（类型 $\texttt{G}$ ）、至少 $1$ 道数学题（类型 $\texttt{M}$ ）。
- 在满足上述条件的前提下，最大化 $6$ 道题目的喜好指数之和。
- 如果有多组解，输出 $\texttt{ID}$ 序列字典序最小的一组（将输出行视为字符串比较 $\texttt{ASCII}$ 值）。

## 输入格式

每个测试用例第一行是一个整数 $N$（ $6 \le N \le 200$ ），表示题库中的题目数量。  
接下来 $N$ 行，每行格式为：

```
ID 题目名 难度 类型 喜好指数
```

其中：

- $\texttt{ID}$ 是 $3$ 位数字字符串（如 `000` ）。
- 题目名是一个字符串（可以包含下划线）。
- 难度：`E`（容易）、`M`（中等）、`H`（困难）。
- 类型：`D`（DP）、`G`（图论）、`M`（数学）、`X`（其他）。
- 喜好指数是一个正整数。

输入以一行 `0` 结束。

## 输出格式

对于每个测试用例，如果无法满足要求，输出 `No solution.`。否则，输出选中的 $6$ 道题目的 $\texttt{ID}$，按 $\texttt{ID}$ 升序排列，每两个 $\texttt{ID}$ 之间用一个空格隔开。

输入


## 题目分析

本题是一个带有复杂约束的组合优化问题。需要从最多 $N = 200$ 个物品中选出恰好 $6$ 个，同时满足：

- **难度约束**：恰好 $2$ 个 $\texttt{E}$、$2$ 个 $\texttt{H}$。注意难度 $\texttt{M}$ 的数量不受限制，但由于总数为 $6$，在固定 $\texttt{E}$ 和 $\texttt{H}$ 各 $2$ 个后，$\texttt{M}$ 的数量自动确定为 $6 - 2 - 2 = 2$ 个。因此难度分配是**唯一确定**的：必须选 $2$ 个 $\texttt{E}$、$2$ 个 $\texttt{M}$、$2$ 个 $\texttt{H}$。
- **类型约束**：$\texttt{D} \ge 2$、$\texttt{G} \ge 1$、$\texttt{M} \ge 1$。
- **优化目标**：最大化喜好指数之和，次目标为 $\texttt{ID}$ 序列字典序最小。

直接枚举所有 $6$ 元组会达到 $\binom{200}{6} \approx 1.3 \times 10^{12}$，不可行。  
需要利用约束的稀疏性和物品的分类结构来设计高效的枚举算法。

## 解题思路

### 状态空间分析

由于难度分配是固定的（ $\texttt{E}$、$\texttt{M}$、$\texttt{H}$ 各 $2$ 个），我们可以将问题按难度拆分成三个独立的子问题：从 $\texttt{E}$ 难度中选 $2$ 题，从 $\texttt{M}$ 难度中选 $2$ 题，从 $\texttt{H}$ 难度中选 $2$ 题。三个子问题之间没有难度上的耦合，仅在类型约束上通过累加产生联系。

类型有四种：$\texttt{D}$、$\texttt{G}$、$\texttt{M}$、$\texttt{X}$。对于每个难度，我们需要决定从每种类型中选取多少道题目。设：

- 从 $\texttt{E}$ 难度中选取的 $\texttt{D}, \texttt{G}, \texttt{M}, \texttt{X}$ 数量分别为 $e_D, e_G, e_M, e_X$，满足 $e_D + e_G + e_M + e_X = 2$。
- 从 $\texttt{M}$ 难度中选取的各类数量分别为 $m_D, m_G, m_M, m_X$，满足 $m_D + m_G + m_M + m_X = 2$。
- 从 $\texttt{H}$ 难度中选取的各类数量分别为 $h_D, h_G, h_M, h_X$，满足 $h_D + h_G + h_M + h_X = 2$。

类型总数满足：

- $e_D + m_D + h_D \ge 2$
- $e_G + m_G + h_G \ge 1$
- $e_M + m_M + h_M \ge 1$

### 枚举策略

上述分配方案的总数非常有限：

- 将 $2$ 个物品分配到 $4$ 个类型（允许空），方案数为 $\binom{2+4-1}{4-1} = \binom{5}{3} = 10$。
- 三个难度各自独立，因此总枚举状态数为 $10 \times 10 \times 10 = 1000$ 种。

对于每种分配方案，我们只需要检查对应难度和类型的题目列表中是否有足够多的题目（即列表长度 $\ge$ 所需数量）。如果足够，就**直接取该列表的前若干个**（即喜好指数最高的那些题目），因为每个列表内部已经按喜好指数降序、$\texttt{ID}$ 升序排序。

### 为什么可以贪心地取前几个？

对于固定的分配 $(e_D, e_G, e_M, e_X)$，要从 $\texttt{E}$ 难度的 $\texttt{D}$ 类型题目中选出 $e_D$ 个。由于最终优化目标是**最大化总喜好指数**，且不同难度和类型之间的选择相互独立（没有跨类别的资源竞争），因此对于单个列表，取喜好指数最高的前 $e_D$ 个一定是最优的。如果存在更优的替换，一定会产生更大的总喜好或更小的字典序，但列表已按喜好降序、$\texttt{ID}$ 升序排序，前 $e_D$ 个就是该数量下的最优组合。

同理适用于 $\texttt{M}$ 和 $\texttt{H}$ 难度的各个列表。

### 字典序处理

当总喜好指数相等时，需要比较 $\texttt{ID}$ 序列的字典序。由于我们从每个列表中取的是前若干个（已经按 $\texttt{ID}$ 升序排列），但不同列表的 $\texttt{ID}$ 混合后顺序会被打乱。因此，在收集完 $6$ 个题目的 $\texttt{ID}$ 后，需要将它们排序后再与当前最优解比较字典序。

### 算法步骤

1. 读入 $N$ 个题目，按难度（$\texttt{E}$、$\texttt{M}$、$\texttt{H}$）和类型（$\texttt{D}$、$\texttt{G}$、$\texttt{M}$、$\texttt{X}$）分成 $3 \times 4 = 12$ 个列表。
2. 对每个列表内部按喜好指数降序、$\texttt{ID}$ 升序排序。
3. 枚举所有可能的 $(e_D, e_G, e_M, e_X)$ 分配（$10$ 种）。
4. 枚举所有 $(m_D, m_G, m_M, m_X)$ 分配（$10$ 种）。
5. 枚举所有 $(h_D, h_G, h_M, h_X)$ 分配（$10$ 种）。
6. 对于每种分配，检查各列表长度是否足够，若不足则跳过。
7. 从每个列表中取出前对应数量的题目，计算总喜好指数和 $\texttt{ID}$ 列表。
8. 检查类型总数是否满足 $\texttt{D} \ge 2$、$\texttt{G} \ge 1$、$\texttt{M} \ge 1$。
9. 更新全局最优解（总喜好优先，字典序次之）。
10. 若没有可行解，输出 `No solution.`，否则输出最优解的 $\texttt{ID}$（排序后）。

### 复杂度分析

- 预处理排序：$O(N \log N)$，$N \le 200$。
- 枚举分配：$10 \times 10 \times 10 = 1000$ 种。
- 每种分配 $O(1)$ 计算（取前若干个、求和、排序 $6$ 个元素）。
- 总时间复杂度 $O(N \log N + 1000)$，远低于 $1000\ \text{ms}$ 限制。
- 空间复杂度 $O(N)$。

## 代码实现

```cpp
// Arranging a Contest
// UVa ID: 11372
// Verdict: Accepted
// Submission Date: 2026-06-13
// UVa Run Time: 0.010s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

struct Problem {
    string id;
    char difficulty, type;
    int favor;
};

bool cmpFavorID(const Problem& a, const Problem& b) {
    if (a.favor != b.favor) return a.favor > b.favor;
    return a.id < b.id;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    while (cin >> N && N) {
        vector<Problem> problems(N);
        string name;
        for (int i = 0; i < N; ++i)
            cin >> problems[i].id >> name >> problems[i].difficulty >> problems[i].type >> problems[i].favor;

        // 按难度和类型分组
        vector<Problem> byDiffType[3][4];
        for (auto& p : problems) {
            int d = (p.difficulty == 'E' ? 0 : (p.difficulty == 'M' ? 1 : 2));
            int t = (p.type == 'D' ? 0 : (p.type == 'G' ? 1 : (p.type == 'M' ? 2 : 3)));
            byDiffType[d][t].push_back(p);
        }

        // 每组内排序
        for (int i = 0; i < 3; ++i)
            for (int j = 0; j < 4; ++j)
                sort(byDiffType[i][j].begin(), byDiffType[i][j].end(), cmpFavorID);

        vector<string> bestIds;
        int maxFavor = -1;

        // 枚举从 E(0) 中选 2 个的分配
        for (int ed = 0; ed <= 2; ++ed)
            for (int eg = 0; eg <= 2 - ed; ++eg)
                for (int em = 0; em <= 2 - ed - eg; ++em) {
                    int ex = 2 - ed - eg - em;
                    if (ex < 0) continue;
                    // 检查 E 中各类型数量足够
                    if (ed > (int)byDiffType[0][0].size() || eg > (int)byDiffType[0][1].size() ||
                        em > (int)byDiffType[0][2].size() || ex > (int)byDiffType[0][3].size())
                        continue;

                    // 枚举 H(2) 中选 2 个的分配
                    for (int hd = 0; hd <= 2; ++hd)
                        for (int hg = 0; hg <= 2 - hd; ++hg)
                            for (int hm = 0; hm <= 2 - hd - hg; ++hm) {
                                int hx = 2 - hd - hg - hm;
                                if (hx < 0) continue;
                                if (hd > (int)byDiffType[2][0].size() || hg > (int)byDiffType[2][1].size() ||
                                    hm > (int)byDiffType[2][2].size() || hx > (int)byDiffType[2][3].size())
                                    continue;

                                // 枚举 M(1) 中选 0~2 个，但 M 难度不贡献 E/H 计数
                                for (int mCnt = 0; mCnt <= 2; ++mCnt) {
                                    for (int md = 0; md <= mCnt; ++md)
                                        for (int mg = 0; mg <= mCnt - md; ++mg)
                                            for (int mm = 0; mm <= mCnt - md - mg; ++mm) {
                                                int mx = mCnt - md - mg - mm;
                                                if (mx < 0) continue;
                                                if (md > (int)byDiffType[1][0].size() || mg > (int)byDiffType[1][1].size() ||
                                                    mm > (int)byDiffType[1][2].size() || mx > (int)byDiffType[1][3].size())
                                                    continue;

                                                int totalD = ed + hd + md;
                                                int totalG = eg + hg + mg;
                                                int totalM = em + hm + mm;
                                                if (totalD < 2 || totalG < 1 || totalM < 1) continue;

                                                // 收集所有候选题目
                                                vector<Problem> candidates;
                                                auto addCandidates = [&](int diff, int type, int cnt) {
                                                    for (int i = 0; i < cnt; ++i)
                                                        candidates.push_back(byDiffType[diff][type][i]);
                                                };
                                                addCandidates(0, 0, ed); addCandidates(0, 1, eg);
                                                addCandidates(0, 2, em); addCandidates(0, 3, ex);
                                                addCandidates(2, 0, hd); addCandidates(2, 1, hg);
                                                addCandidates(2, 2, hm); addCandidates(2, 3, hx);
                                                addCandidates(1, 0, md); addCandidates(1, 1, mg);
                                                addCandidates(1, 2, mm); addCandidates(1, 3, mx);
                                                if ((int)candidates.size() != 6) continue;
                                                int curFavor = 0;
                                                vector<string> ids;
                                                for (auto& p : candidates) {
                                                    curFavor += p.favor;
                                                    ids.push_back(p.id);
                                                }
                                                sort(ids.begin(), ids.end());
                                                if (curFavor > maxFavor || (curFavor == maxFavor && ids < bestIds)) {
                                                    maxFavor = curFavor;
                                                    bestIds = ids;
                                                }
                                            }
                                }
                            }
                }

        if (maxFavor == -1) cout << "No solution.\n";
        else {
            for (int i = 0; i < 6; ++i) {
                if (i) cout << ' ';
                cout << bestIds[i];
            }
            cout << '\n';
        }
    }
    return 0;
}
```

## 总结

本题的核心技巧在于**利用约束的确定性进行状态拆分**：

1. **难度分配唯一**：由于要求恰好 $2$ 个 $\texttt{E}$ 和 $2$ 个 $\texttt{H}$，且总数为 $6$，$\texttt{M}$ 的数量自动固定为 $2$。这大大简化了问题，将原问题分解为三个独立的子问题。

2. **枚举数量分配而非具体物品**：每个难度内，将 $2$ 个物品分配到 $4$ 种类型的方案数仅为 $10$ 种。三个难度组合后总枚举量仅为 $1000$ 种，远小于直接枚举物品组合。

3. **贪心取前几个**：在每个类型列表中，由于没有跨类别的资源竞争，取喜好指数最高的前若干个一定是局部最优的。这是因为列表已按喜好降序、$\texttt{ID}$ 升序排序，任何替换都会降低总喜好或增大字典序。

4. **字典序处理**：在总喜好相等时，将 $\texttt{ID}$ 排序后比较，保证了最终输出的字典序最小。

这种方法避免了复杂的搜索或动态规划，体现了**组合数学与贪心策略**在约束优化问题中的强大威力。当物品总数较小但约束维度较高时，枚举所有可行的**数量分配**往往比枚举具体物品更加高效。
