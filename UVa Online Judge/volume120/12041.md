## 题目描述

我们定义了一个类似于斐波那契数列的字符串序列：

- $BFS(0) = \text{"0"}$
- $BFS(1) = \text{"1"}$
- 对于所有 $n > 1$，$BFS(n) = BFS(n-2) + BFS(n-1)$，其中 $+$ 表示字符串连接操作

因此，该序列的前几个字符串为：
$BFS(0) = \text{"0"}$，$BFS(1) = \text{"1"}$，$BFS(2) = \text{"01"}$，$BFS(3) = \text{"101"}$，$BFS(4) = \text{"01101"}$，依此类推。

给定 $T$ 个测试用例，每个测试用例包含三个整数 $N$、$i$、$j$（都是基于 $0$ 的索引），要求输出 $BFS(N)$ 中从第 $i$ 个到第 $j$ 个位置的子串。

**约束条件：**
- $T \leq 100$
- $0 \leq N, i, j \leq 2^{31}-1$
- $i \leq j$ 且 $j-i \leq 10000$
- $i$ 和 $j$ 都是有效索引

## 题目分析

### 关键观察

1. **字符串长度增长极快**：$BFS(n)$ 的长度就是斐波那契数列的第 $n$ 项（从 $fib(0)=1$ 开始）。由于斐波那契数列呈指数级增长，$BFS(n)$ 的长度很快就会变得非常大。

2. **递归结构**：$BFS(n)$ 由 $BFS(n-2)$ 和 $BFS(n-1)$ 连接而成，这种递归结构使得我们可以通过递归或迭代的方式定位任意位置的字符，而无需构建整个字符串。

3. **索引范围限制**：虽然 $N$ 可以非常大（最大 $2^{31}-1$），但 $j-i \leq 10000$，这意味着我们只需要生成一小段子串，而不是整个字符串。

4. **压缩优化**：当 $n$ 足够大时，$BFS(n)$ 的长度会超过题目中可能出现的最大索引值 $2^{31}-1$。此时，我们可以将大的 $n$ 压缩到一个固定的值，同时保持字符串的奇偶性不变，以确保字符串开头字符的正确性。

### 解题思路

1. **预计算长度**：预先计算斐波那契数列的前若干项，作为 $BFS(n)$ 的长度。由于斐波那契数增长极快，计算前 $64$ 项就足够了。

2. **递归查询字符**：对于给定的 $n$ 和位置 $pos$，利用 $BFS(n) = BFS(n-2) + BFS(n-1)$ 的性质：
   - 如果 $pos < |BFS(n-2)|$，则字符在 $BFS(n-2)$ 中
   - 否则，字符在 $BFS(n-1)$ 中，位置为 $pos - |BFS(n-2)|$

3. **压缩大 $N$**：当 $N \geq 50$ 时，将其压缩到 $50$ 或 $51$（保持原 $N$ 的奇偶性），因为：
   - $|BFS(50)|$ 已经远超 $2^{31}-1$，足够覆盖所有可能的索引
   - 保持奇偶性确保字符串开头字符正确（奇数 $n$ 以 $\text{"1"}$ 开头，偶数 $n$ 以 $\text{"0"}$ 开头）

4. **逐字符输出**：对于每个测试用例，从位置 $i$ 到 $j$ 逐个字符查询并输出。

## 算法复杂度分析

- **预计算**：$O(64)$，常数时间
- **每个字符查询**：最坏情况下 $O(50)$ 次递归调用
- **每个测试用例**：$O((j-i) \times 50)$
- **总体复杂度**：$O(T \times 10000 \times 50)$，在题目约束下完全可行

```cpp
// BFS(Binary Fibonacci String)
// UVa ID: 12041

#include <bits/stdc++.h>
using namespace std;

long long fib[64]; // 存储BFS(n)的长度，即斐波那契数列，fib[0]=|BFS(0)|=1, fib[1]=|BFS(1)|=1

// 递归查找BFS(n)中第pos个字符（0-based）
char getCharAt(long long n, long long pos) {
    if (n == 0) return '0'; // 基础情况：BFS(0) = "0"
    if (n == 1) return '1'; // 基础情况：BFS(1) = "1"
    // BFS(n) = BFS(n-2) + BFS(n-1)
    if (pos < fib[n - 2]) return getCharAt(n - 2, pos);      // 字符在前半部分(BFS(n-2))
    else return getCharAt(n - 1, pos - fib[n - 2]); // 字符在后半部分(BFS(n-1))
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    // 预计算斐波那契数列作为BFS字符串的长度
    fib[0] = fib[1] = 1; // BFS(0)和BFS(1)的长度都是1
    for (int i = 2; i < 64; i++) fib[i] = fib[i - 1] + fib[i - 2]; // 斐波那契递推
    int t;
    cin >> t;
    while (t--) {
        long long n, i, j;
        cin >> n >> i >> j;
        // 关键优化：当n过大时，压缩到50或51（保持奇偶性）
        // 因为斐波那契数增长极快，BFS(50)长度已远超题目最大索引2^31-1
        // 保持奇偶性确保字符串开头字符正确（奇数n以'1'开头，偶数n以'0'开头）
        if (n >= 50) n = 50 + (n % 2);
        // 输出BFS(n)中从位置i到j的子串
        for (long long pos = i; pos <= j; pos++)
            cout << getCharAt(n, pos);
        cout << '\n';
    }
    return 0;
}
```

## 总结

本题的关键在于利用斐波那契字符串的递归性质和斐波那契数列的快速增长特性。通过递归查询字符和压缩大 $N$ 的优化技巧，我们能够在不需要构建整个字符串的情况下，高效地输出任意位置的子串。这种思路对于处理具有递归结构的大规模数据具有很好的借鉴意义。
