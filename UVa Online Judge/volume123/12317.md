## 题目描述

$\texttt{Alice}$ 和 $\texttt{Bob}$ 需要通过网络传输文本文档，为了提高传输效率，他们使用了一种基于基础文档集合的编码方案。具体来说：

- 每个文档用其包含的 **不同术语的集合** 表示（忽略术语的频率和位置）。
- $\texttt{Alice}$ 和 $\texttt{Bob}$ 事先共享一组 **基础文档** ，每个基础文档也有自己的术语集合。
- 传输文档时，$\texttt{Alice}$ 找出能够 **组合** 出目标文档的基础文档集合（组合方式为集合的并集），然后只传输这些基础文档的索引。
- $\texttt{Bob}$ 收到索引后，通过合并对应基础文档的术语集合来重建原始文档。

你的任务是：对于每个目标文档，找到能够表示它的 **最少基础文档数量** 。如果无法表示，则输出 $0$ 。

## 输入格式

每个测试用例包含：
- 一行两个整数 $M$ 和 $N$ （ $1 \le M, N \le 100$ ），分别表示基础文档数量和目标文档数量。
- 接下来 $M + N$ 行，每行格式为： $k\ t_1\ t_2\ \ldots\ t_k$ ，其中 $k$ 表示文档中不同术语的数量（ $1 \le k \le 16$ ）， $t_i$ 表示具体的术语编号（ $1 \le t_i \le 16$ ）。前 $M$ 行是基础文档，后 $N$ 行是目标文档。
- 输入以 `0 0` 结束。

## 输出格式

对于每个测试用例，输出一行 $N$ 个整数 $r_1\ r_2\ \ldots\ r_N$ ，其中 $r_i$ 表示表示第 $i$ 个目标文档所需的最少基础文档数；若无法表示，则输出 $0$ 。

## 题目分析

### 问题本质

这是一个 **集合覆盖问题** 的变种：
- 给定若干个基础集合（基础文档的术语集合）。
- 需要选择最少数量的基础集合，使得它们的并集等于目标集合（目标文档的术语集合）。

由于术语数量最多为 $16$ ，我们可以用 **状态压缩** 的技巧来表示集合，将每个集合编码为一个 $16$ 位的二进制数（位掩码）。

### 关键约束

1. **术语数量少** ：最多 $16$ 个不同的术语，因此所有可能的术语集合数量为 $2^{16} = 65536$ ，这是一个可以接受的状态空间。
2. **基础文档数量适中** ：最多 $100$ 个，可以在状态转移时遍历。
3. **目标文档数量** ：最多 $100$ 个，但我们可以预处理所有可能状态的结果，然后直接查询。

### 解题思路

#### 1. 状态表示

用 $16$ 位二进制数表示一个术语集合，第 $i$ 位为 $1$ 表示包含术语 $i+1$ （因为术语编号从 $1$ 开始）。

例如：
- 基础文档 $\{2, 5, 7, 10\}$ 表示为：第 $1$ 、 $4$ 、 $6$ 、 $9$ 位为 $1$ （因为 $2-1=1$ , $5-1=4$ , $7-1=6$ , $10-1=9$ ）。
- 位掩码： `(1<<1) | (1<<4) | (1<<6) | (1<<9)` 。

#### 2. 动态规划定义

定义 $dp[mask]$ 表示：通过选择若干基础文档，能够 **恰好覆盖** 术语集合 $mask$ 所需的最少基础文档数量。

初始状态：
- $dp[0] = 0$ （空集合不需要任何基础文档）。
- 其他状态初始化为无穷大（ $\infty$ ，表示不可达）。

#### 3. 状态转移

对于每个当前状态 $mask$ ，如果它是可达的（即 $dp[mask] \ne \infty$ ），我们尝试添加一个基础文档 $basis$ （其术语集合对应的位掩码）：
- 新状态为 $newMask = mask\ |\ basis$ 。
- 转移方程： $dp[newMask] = \min(dp[newMask], dp[mask] + 1)$ 。

由于基础文档可以重复使用（即一个基础文档可以被选择多次），这相当于一个 **完全背包** 问题。但我们可以通过 **广度优先更新** 的方式处理：从小到大遍历所有 $mask$ ，对每个 $mask$ 尝试所有基础文档，更新 $newMask$ 。因为 $newMask$ 总是大于等于 $mask$ （按位或操作不会减少 $1$ 的位数），所以不会出现循环依赖。

#### 4. 算法流程

1. 读取所有基础文档，转换为位掩码。
2. 初始化 $dp$ 数组，大小为 $2^{16}$ ，所有值设为无穷大， $dp[0] = 0$ 。
3. 遍历所有 $mask$ 从 $0$ 到 $2^{16}-1$ ：
   - 如果 $dp[mask]$ 不可达，跳过。
   - 对于每个基础文档的位掩码 $basis$ ，计算 $newMask = mask\ |\ basis$ ，并尝试更新 $dp[newMask]$ 。
4. 对于每个目标文档：
   - 转换为位掩码 $targetMask$ 。
   - 查询 $dp[targetMask]$ ，若为无穷大则输出 $0$ ，否则输出该值。

#### 5. 复杂度分析

- 状态数： $2^{16} = 65536$ 。
- 每个状态尝试 $M$ 个基础文档（最多 $100$ 个）。
- 总时间复杂度： $O(2^{16} \times M) \approx 6.5 \times 10^6$ 次操作，完全可行。
- 空间复杂度： $O(2^{16})$ 个整数，约 $256\ \text{KB}$ 。

#### 6. 为什么不能对每个目标文档单独计算？

如果对每个目标文档单独计算，复杂度为 $O(N \times 2^{16} \times M)$ ，在最坏情况下（ $N=100, M=100$ ）将达到 $6.5 \times 10^8$ 次操作，容易超时。因此，我们选择 **预处理所有状态** ，然后直接查询，将复杂度降低 $N$ 倍。

## 代码实现

```cpp
// Document Compression
// UVa ID: 12317
// Verdict: Accepted
// Submission Date: 2025-12-26
// UVa Run Time: 0.080s
//
// 版权所有（C）2025，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

const int INF = 1e9;

int main() {
    int m, n;
    while (cin >> m >> n and (m or n)) {
        // 读取基础文档
        vector<int> basisMasks(m);
        for (int i = 0; i < m; ++i) {
            int k, term;
            cin >> k;
            int mask = 0;
            while (k--) {
                cin >> term;
                mask |= (1 << (term - 1)); // 术语从 1 开始，映射到 0-15 位
            }
            basisMasks[i] = mask;
        }
        // DP数组，初始化为无穷大
        vector<int> dp(1 << 16, INF);
        dp[0] = 0;
        // 遍历所有状态
        for (int mask = 0; mask < (1 << 16); ++mask) {
            if (dp[mask] == INF) continue; // 无法达到的状态
            // 尝试添加每个基础文档
            for (int basis : basisMasks) {
                int newMask = mask | basis;
                if (dp[newMask] > dp[mask] + 1) {
                    dp[newMask] = dp[mask] + 1;
                }
            }
        }
        // 处理每个目标文档
        vector<int> results;
        for (int docIdx = 0; docIdx < n; ++docIdx) {
            int k, term;
            cin >> k;
            int targetMask = 0;
            while (k--) {
                cin >> term;
                targetMask |= (1 << (term - 1));
            }
            // 获取结果
            if (dp[targetMask] == INF) results.push_back(0);
            else results.push_back(dp[targetMask]);
        }
        // 输出结果
        for (size_t i = 0; i < results.size(); ++i) {
            if (i) cout << ' ';
            cout << results[i];
        }
        cout << '\n';
    }
    return 0;
}
```

## 示例解析

### 样例输入
```
3 1
4 2 5 7 10
3 8 9 10
4 1 2 3 4
7 1 2 3 4 5 7 10
2 3
2 2 1
2 4 3
2 3 4
3 3 1 2
4 3 1 4 2
0 0
```

### 样例输出
```
2
1 0 2
```

### 解释

第一个测试用例：
- 基础文档：
  1. $\{2,5,7,10\}$ → 掩码
  2. $\{8,9,10\}$ → 掩码
  3. $\{1,2,3,4\}$ → 掩码
- 目标文档： $\{1,2,3,4,5,7,10\}$ → 掩码
- 最少需要基础文档 $1$ 和 $3$ ，数量为 $2$ 。

第二个测试用例：
- 基础文档：
  1. $\{2,1\}$ （即 $\{1,2\}$ ）→ 掩码
  2. $\{4,3\}$ （即 $\{3,4\}$ ）→ 掩码
- 目标文档：
  1. $\{3,4\}$ → 只需基础文档 $2$ ，数量 $1$ 。
  2. $\{3,1,2\}$ → 无法用基础文档 $\{1,2\}$ 和 $\{3,4\}$ 组合得到，输出 $0$ 。
  3. $\{3,1,4,2\}$ （即 $\{1,2,3,4\}$ ）→ 需要基础文档 $1$ 和 $2$ ，数量 $2$ 。

## 总结

本题的关键在于：
1. 利用术语数量少的特性，使用 **状态压缩** 将集合表示为位掩码。
2. 通过 **动态规划预处理所有状态** ，避免对每个目标文档重复计算。
3. 正确建模为集合覆盖问题，并设计高效的转移方式。

这种预处理 + 查询的思路在许多状态压缩问题中都非常有效，尤其是在需要回答多个查询的场景下。
