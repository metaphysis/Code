## 题目描述

我们有一个 $M \times N$ 的灯网格，有些灯亮着（用 $1$ 表示），有些灯熄灭（用 $0$ 表示）。一行或一列的“亮度”是指该行或该列中亮灯的数量。你得到了各行亮度的某个排列和各列亮度的某个排列。不幸的是，这些值并不准确，但我们知道它们至少不是高估值（即实际亮度 $\geq$ 给定值）。你需要求出这个网格中最少的可能亮灯数量。

### 输入格式
第一行包含一个整数 $T \leq 100$ 表示测试用例的数量。每个测试用例开始于两个整数 $M$ 和 $N$（均在 $[1, 1000]$ 内），分别表示网格的行数和列数。接下来两行给出亮度值：第一行包含 $M$ 个行亮度值，第二行包含 $N$ 个列亮度值。

### 输出格式
对于每个测试用例，输出一行，表示最少的可能亮灯数量。

### 样例输入
```
3
2 2
2 0
0 2
1 4
2
1 0 1 1
2 4
3 1
0 2 1 2
```

### 样例输出
```
3
3
5
```

## 题目分析与解题思路

### 问题本质分析

我们需要理解这个问题的几个关键点：

1. **排列性质**：输入的行亮度是实际各行亮度的某个排列，列亮度也是实际各列亮度的某个排列。这意味着我们可以自由地重新排列行和列的顺序来最小化总亮灯数。

2. **下界性质**：给定的亮度值不大于实际值，即 $r_i \leq$ 实际第 $i$ 行亮度，$c_j \leq$ 实际第 $j$ 列亮度。

3. **优化目标**：寻找最小的总亮灯数 $L$，使得存在一个 $M \times N$ 的 $0/1$ 矩阵（$1$ 表示灯亮，$0$ 表示灯灭），该矩阵经过适当的行和列重排后，满足：
   - 重排后的第 $i$ 行亮灯数 $\geq$ 排序后的第 $i$ 个行亮度值
   - 重排后的第 $j$ 列亮灯数 $\geq$ 排序后的第 $j$ 个列亮度值

### 关键洞察

由于可以自由排列行和列，最优策略是：
- 将行亮度值从大到小排序：$r_{(1)} \geq r_{(2)} \geq \cdots \geq r_{(M)}$
- 将列亮度值从大到小排序：$c_{(1)} \geq c_{(2)} \geq \cdots \geq c_{(N)}$

这样做的原因是我们希望将较大的亮度需求与更容易满足的行/列相匹配。在构造矩阵时，亮灯数较多的行和列有更多的灵活性来满足较大的亮度需求。

### 数学建模与定理基础

这个问题本质上是判断一个二分图的度序列是否可图化（$\texttt{graphic}$）的变体。具体来说，我们需要找到一个二分图，其中：
- 左侧有 $M$ 个顶点（代表行），右侧有 $N$ 个顶点（代表列）
- 每条边对应一个亮着的灯
- 左侧顶点 $i$ 的度数 $\geq r_{(i)}$
- 右侧顶点 $j$ 的度数 $\geq c_{(j)}$

我们需要最小化总边数（即总亮灯数）。

### $\texttt{Gale-Ryser}$ 定理的应用

对于二分图度序列的可图性，有一个经典的 **$\texttt{Gale-Ryser}$ 定理**。该定理的一个推论给出了存在性条件：

对于排序后的行亮度 $r_{(1)} \geq r_{(2)} \geq \cdots \geq r_{(M)}$ 和列亮度 $c_{(1)} \geq c_{(2)} \geq \cdots \geq c_{(N)}$，存在满足条件的二分图当且仅当对于所有 $k = 1, \ldots, M$ 和 $l = 1, \ldots, N$，有：

$$
\sum_{i=1}^k r_{(i)} \leq \sum_{j=1}^N \min(c_{(j)}, k)
$$

并且对称地，对于所有 $l = 1, \ldots, N$ 和 $k = 1, \ldots, M$，有：

$$
\sum_{j=1}^l c_{(j)} \leq \sum_{i=1}^M \min(r_{(i)}, l)
$$

然而，我们需要的是**最小总边数**，而不仅仅是存在性。通过分析，我们可以得到最小总亮灯数 $L$ 必须满足：

$$
L = \max\left( \sum_{i=1}^M r_i, \sum_{j=1}^N c_j, \max_{1 \leq k \leq M, 1 \leq l \leq N} \left( \sum_{i=1}^k r_{(i)} + \sum_{j=1}^l c_{(j)} - k \cdot l \right) \right)
$$

### 公式推导与解释

让我们详细解释这个公式的每一项：

1. **$\sum_{i=1}^M r_i$**：所有行亮度需求的总和。由于每个亮灯贡献给某一行，总亮灯数必须至少等于这个值。

2. **$\sum_{j=1}^N c_j$**：所有列亮度需求的总和。由于每个亮灯贡献给某一列，总亮灯数必须至少等于这个值。

3. **$\max_{k,l} \left( \sum_{i=1}^k r_{(i)} + \sum_{j=1}^l c_{(j)} - k \cdot l \right)$**：这是最关键的部分。考虑前 $k$ 大的行需求（共需 $\sum_{i=1}^k r_{(i)}$ 个亮灯）和前 $l$ 大的列需求（共需 $\sum_{j=1}^l c_{(j)}$ 个亮灯）。这些行和列的交集最多包含 $k \cdot l$ 个格子。因此，要同时满足这些行和列的需求，至少需要：

   $$
   \sum_{i=1}^k r_{(i)} + \sum_{j=1}^l c_{(j)} - k \cdot l
   $$

   个亮灯。因为 $k \cdot l$ 个格子中的每个亮灯可以同时满足一个行需求和一个列需求，所以这个表达式表示了在交集区域中"节省"的亮灯数。

### 算法步骤

基于上述分析，算法步骤如下：

1. 读取 $M$ 和 $N$，以及行亮度数组和列亮度数组。
2. 计算行亮度总和 $\texttt{sumRow}$ 和列亮度总和 $\texttt{sumCol}$。
3. 将行亮度数组和列亮度数组分别按降序排序。
4. 初始化答案为 $\max(\texttt{sumRow}, \texttt{sumCol})$。
5. 预处理列亮度的前缀和数组 $\texttt{colPrefix}$，其中 $\texttt{colPrefix}[j] = \sum_{t=1}^j c_{(t)}$。
6. 遍历 $k$ 从 $1$ 到 $M$：
   - 维护前 $k$ 大行亮度的前缀和 $\texttt{rowPrefix}$。
   - 对于每个 $l$ 从 $1$ 到 $N$，计算：
     $$
     \texttt{value} = \texttt{rowPrefix} + \texttt{colPrefix}[l] - k \cdot l
     $$
   - 用 $\texttt{value}$ 更新答案。
7. 输出答案。

### 时间复杂度分析

- 排序：$O(M \log M + N \log N)$
- 计算答案：$O(M \times N)$，最坏情况下为 $10^6$ 次操作
- 总复杂度：对于 $T \leq 100$，最坏情况约为 $10^8$ 次操作，在合理时间内可以完成

### 正确性验证

让我们用样例验证算法：

**样例 $1$**：
```
2 2
2 0
0 2
```
- 行亮度：$[2, 0]$，排序后：$[2, 0]$，总和为 $2$
- 列亮度：$[0, 2]$，排序后：$[2, 0]$，总和为 $2$
- 初始答案：$\max(2, 2) = 2$
- $k=1$：$\texttt{rowPrefix}=2$
  - $l=1$：$\texttt{colPrefix}[1]=2$，$\texttt{value}=2+2-1=3$，更新答案为 $3$
  - $l=2$：$\texttt{colPrefix}[2]=2$，$\texttt{value}=2+2-2=2$
- $k=2$：$\texttt{rowPrefix}=2+0=2$
  - $l=1$：$\texttt{value}=2+2-2=2$
  - $l=2$：$\texttt{value}=2+2-4=0$
- 最终答案：$3$ ✓

### 边界情况考虑

1. **需求超过网格尺寸**：如果某个 $r_i > N$ 或 $c_j > M$，根据题目保证，这种情况不会发生，因为输入值不超过实际值，而实际值不可能超过网格尺寸。
2. **零需求**：处理 $r_i = 0$ 或 $c_j = 0$ 的情况正常，排序后会排在最后。
3. **大规模数据**：使用 `long long` 类型防止溢出。

## 代码实现


```cpp
// Grid of Lamps
// UVa ID: 12382
// Verdict: Accepted
// Submission Date: 2025-12-04
// UVa Run Time: 0.000s
//
// 版权所有（C）2025，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int t;
    cin >> t;
    
    while (t--) {
        int m, n;
        cin >> m >> n;
        
        vector<int> rowReq(m), colReq(n);
        long long sumRow = 0, sumCol = 0;
        
        for (int i = 0; i < m; i++) {
            cin >> rowReq[i];
            sumRow += rowReq[i];
        }
        
        for (int j = 0; j < n; j++) {
            cin >> colReq[j];
            sumCol += colReq[j];
        }
        
        // 行从大到小排序
        sort(rowReq.begin(), rowReq.end(), greater<int>());
        // 列从大到小排序
        sort(colReq.begin(), colReq.end(), greater<int>());
        
        long long result = max(sumRow, sumCol);
        
        // 预处理列前缀和
        vector<long long> colPrefix(n + 1, 0);
        for (int j = 0; j < n; j++) {
            colPrefix[j + 1] = colPrefix[j] + colReq[j];
        }
        
        // 计算 max_{k,l} (sumTopKRow + sumTopLCol - k*l)
        long long rowPrefix = 0;
        for (int k = 1; k <= m; k++) {
            rowPrefix += rowReq[k - 1];
            
            // 对于给定的 k，找到最大的 l 使得 colReq[l-1] >= k
            int l = 0;
            for (int j = 0; j < n; j++) {
                if (colReq[j] >= k) l = j + 1;
                else break;
            }
            
            // 对于 l 从 1 到 n，计算表达式
            for (int lj = 1; lj <= n; lj++) {
                long long colSum = colPrefix[lj];
                long long value = rowPrefix + colSum - 1LL * k * lj;
                if (value > result) result = value;
            }
        }
        
        cout << result << "\n";
    }
    
    return 0;
}
```

## 总结

本题的关键在于理解行和列亮度可以自由排列的性质，并应用组合数学中关于二分图度序列的定理。通过将亮度值排序并计算特定表达式，我们可以在 $O(M \times N)$ 时间内找到最小总亮灯数。这个问题展示了如何将看似复杂的组合优化问题转化为简洁的数学公式求解。
