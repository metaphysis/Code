## 题目描述

$\texttt{ACM}$（$\texttt{Advanced Car Management}$，高级汽车管理）租车公司以其优质的服务而闻名。镇上共有 $C$ 家汽车公司，第 $k$ 家公司拥有 $c_k$ 辆汽车，每辆汽车的价格为 $p_k$ 。同时，镇上有 $R$ 个汽车维修中心，第 $i$ 个维修中心需要 $d_i$ 天完成维修，每辆车的维修费用为 $s_i$ 。维修中心可以同时维修任意数量的汽车。

$\texttt{ACM}$ 公司获得了接下来 $N$ 天的租车需求表，第 $j$ 天需要 $r_j$ 辆汽车。公司希望以最小成本满足所有需求。初始时，公司的车库是空的，但可以存储任意数量的汽车。

**关键规则**：一辆汽车使用一天后，如果想再次使用，必须送去维修中心进行维修。

## 输入格式

第一行包含 $T$ （ $\leq 100$ ）表示测试用例数量。

每个用例以三个整数 $N, C, R$ （ $1 \leq N, C, R \leq 50$ ）开始。下一行包含 $N$ 个整数，其中第 $j$ 个整数表示 $r_j$ （ $0 \leq r_j \leq 100$ ）。下一行包含 $2C$ 个整数，其中第 $k$ 个整数对表示 $c_k$ 和 $p_k$ （ $1 \leq c_k, p_k \leq 100$ ）。下一行包含 $2R$ 个整数，其中第 $i$ 个整数对表示 $d_i$ 和 $s_i$ （ $1 \leq d_i, s_i \leq 100$ ）。

## 输出格式

对于每个用例，输出用例编号和满足所有需求的最小成本。如果不可能满足所有需求，输出 `impossible` 。

## 样例分析

### 样例输入
```
2
3 2 1
10 20 30
40 90 15 100
1 5
3 2 1
10 20 30
40 90 15 100
2 5
```

### 样例输出
```
Case 1: 4650
Case 2: impossible
```

**样例 $1$ 解释**：
- 购买 $50$ 辆汽车：$40$ 辆来自公司 $1$（成本 $40 \times 90 = 3600$ ），$10$ 辆来自公司 $2$（成本 $10 \times 100 = 1000$ ）
- 第 $1$ 天：使用 $10$ 辆汽车，然后送修（成本 $10 \times 5 = 50$ ），这些汽车将在第 $3$ 天返回
- 第 $2$ 天：使用 $20$ 辆汽车
- 第 $3$ 天：使用 $20$ 辆未使用的汽车加上 $10$ 辆维修好的汽车
- 总成本： $3600 + 1000 + 50 = 4650$

**样例 $2$ 解释**：由于维修需要 $2$ 天，汽车无法及时返回以满足需求，因此不可能满足所有需求。

## 问题分析

这是一个典型的**资源调度优化问题**，具有以下特点：

1. **时间维度**：需求分布在连续的 $N$ 天内
2. **资源复用**：汽车可以通过维修重复使用
3. **时间延迟**：维修需要 $d_i$ 天，期间汽车不可用
4. **成本最小化**：需要最小化购买成本和维修成本的总和

### 核心挑战

- **购买决策**：需要决定从哪些公司购买多少辆汽车，每个公司有数量和价格限制
- **调度决策**：需要决定每天哪些汽车投入使用，哪些汽车送去维修，以及选择哪个维修中心
- **库存管理**：未使用的汽车可以存储到未来使用

### 建模思路

这个问题可以建模为**最小费用最大流问题**（ $\texttt{Min-Cost Max-Flow}$ ），通过构建适当的网络流图来同时处理购买、使用、维修和库存等决策。

## 解题思路：最小费用最大流建模

### 节点设计

我们需要构建以下节点：

1. **源点** $s$ （节点 $0$）
2. **需求节点** $day_{i_{demand}}$ （节点 $1$ 到 $N$ ）：表示第 $i$ 天需要用车
3. **供应节点** $day_{i_{supply}}$ （节点 $N+1$ 到 $2N$ ）：表示第 $i$ 天有车可用
4. **购买节点** $purchase$ （节点 $2N+1$ ）：集中处理汽车购买
5. **汇点** $t$ （节点 $2N+2$ ）

### 边的构建与含义

#### 1. 强制需求边

- $s \rightarrow day_{i_{demand}}$ ：容量 $r_i$ ，费用 $0$
  - **含义**：第 $i$ 天必须有 $r_i$ 的流量流出，表示需要满足 $r_i$ 辆车的需求

- $day_{i_{supply}} \rightarrow t$ ：容量 $r_i$ ，费用 $0$
  - **含义**：第 $i$ 天必须有 $r_i$ 的流量流入汇点，表示实际提供了 $r_i$ 辆车

#### 2. 购买相关边

- $s \rightarrow purchase$ ：容量 $c_k$ ，费用 $p_k$ （为每个公司创建一条边）
  - **含义**：从第 $k$ 家公司最多购买 $c_k$ 辆车，每辆车成本 $p_k$

- $purchase \rightarrow day_{i_{supply}}$ ：容量 $\infty$ ，费用 $0$
  - **含义**：购买的车可以在任何一天首次使用

#### 3. 库存传递边

- $day_{i_{demand}} \rightarrow day_{{i+1}_{demand}}$ ：容量 $\infty$ ，费用 $0$
  - **含义**：第 $i$ 天未使用的"需求容量"可以传递到第 $i+1$ 天

#### 4. 维修边（关键边）

- $day_{i_{demand}}$  $\rightarrow$  $day_{{i+d_j+1}_{supply}}$ ：容量 $\infty$ ，费用 $s_j$
  - **含义**：第 $i$ 天使用的车，经过第 $j$ 个维修中心维修 $d_j$ 天后，在第 $i+d_j+1$ 天再次可用
  - **注意**：维修需要 $d_j$ 天，所以汽车在第 $i+d_j+1$ 天才可用（不是 $i+d_j$ ）

### 流量解释

在这个模型中，**每单位流量代表一辆车在一天的使用**。流量从源点出发，经过以下可能路径：

1. **新车首次使用**： $s \rightarrow purchase \rightarrow day_{i_{supply}} \rightarrow t$ 
   - 产生购买成本 $p_k$

2. **库存传递**： $s \rightarrow day_{i_{demand}} \rightarrow day_{{i+1}_{demand}} \rightarrow \cdots \rightarrow day_{j_{demand}} \rightarrow day_{j_{supply}} \rightarrow t$ 
   - 不产生额外成本

3. **维修后再次使用**： $s \rightarrow day_{i_{demand}} \rightarrow day_{{i+d+1}_{supply}} \rightarrow t$ 
   - 产生维修成本 $s$

### 算法正确性证明

1. **需求满足**：由于从 $s$ 到 $day_{i_{demand}}$ 的边容量为 $r_i$ ，且从 $day_{i_{supply}}$ 到 $t$ 的边容量也为 $r_i$ ，所以必须恰好有 $r_i$ 的流量通过第 $i$ 天的节点，确保需求被满足。

2. **资源守恒**：流量从需求节点到供应节点的唯一途径是库存传递或维修，这正确模拟了汽车的可用性变化。

3. **成本计算**：
   - 购买成本：当流量通过 $s \rightarrow purchase$ 边时产生
   - 维修成本：当流量通过维修边时产生
   - 库存传递：免费

4. **时间约束**：维修边 $day_{i_{demand}} \rightarrow day_{{i+d+1}_{supply}}$ 确保汽车维修 $d$ 天后才能再次使用。

### 复杂度分析

- **节点数**： $O(N)$ ，具体为 $2N+3 \leq 203$ （ $N \leq 50$ ）
- **边数**： $O(N \times R + C)$ ，具体约为 $N + N + C + N + (N-1) + N \times R \leq 50 + 50 + 50 + 50 + 49 + 50 \times 50 = 2699$ 
- **算法复杂度**：使用 $\texttt{SPFA}$ 算法的最小费用流，复杂度为 $O(F \cdot V \cdot E)$ ，其中 $F$ 是总流量（总需求）， $V$ 是节点数， $E$ 是边数。在本问题中， $F \leq N \times \max(r_j) = 50 \times 100 = 5000$ ，因此总计算量在可接受范围内。

## 算法实现细节

### 最小费用最大流算法

我们使用基于 $\texttt{SPFA}$ （ $\texttt{Shortest Path Faster Algorithm}$ ）的最小费用流算法：

1. **寻找增广路**：每次使用 $\texttt{SPFA}$ 寻找从源点到汇点的最短路径（按费用）
2. **增广流量**：沿着找到的路径增加流量，更新残余网络
3. **计算成本**：累计流量和费用
4. **终止条件**：当无法找到从源点到汇点的增广路时终止

### 关键实现要点

1. **残余网络**：每条边需要存储反向边，用于流量调整
2. **负费用处理**：本题中所有费用非负，因此 $\texttt{SPFA}$ 可以正确处理
3. **流量限制**：每条边的容量限制了可以通过的最大流量

```cpp
// Rent a Car

#include <bits/stdc++.h>
using namespace std;

const int INF = 0x3f3f3f3f;
const int MAXN = 205;

struct Edge {
    int to, capacity, cost, rev;
    Edge(int t, int cap, int c, int r) : to(t), capacity(cap), cost(c), rev(r) {}
};

class MinCostMaxFlow {
    int n;
    vector<vector<Edge>> graph;
    vector<int> dist, inq, prevNode, prevEdge;
    
public:
    MinCostMaxFlow(int size) : n(size) {
        graph.resize(n);
        dist.resize(n);
        inq.resize(n);
        prevNode.resize(n);
        prevEdge.resize(n);
    }
    
    void addEdge(int from, int to, int capacity, int cost) {
        graph[from].emplace_back(to, capacity, cost, graph[to].size());
        graph[to].emplace_back(from, 0, -cost, graph[from].size() - 1);
    }
    
    bool spfa(int source, int sink) {
        fill(dist.begin(), dist.end(), INF);
        fill(inq.begin(), inq.end(), 0);
        queue<int> q;
        q.push(source);
        dist[source] = 0;
        inq[source] = 1;
        while (!q.empty()) {
            int u = q.front();
            q.pop();
            inq[u] = 0;
            for (int i = 0; i < graph[u].size(); i++) {
                Edge& e = graph[u][i];
                if (e.capacity > 0 && dist[u] + e.cost < dist[e.to]) {
                    dist[e.to] = dist[u] + e.cost;
                    prevNode[e.to] = u;
                    prevEdge[e.to] = i;
                    if (!inq[e.to]) {
                        inq[e.to] = 1;
                        q.push(e.to);
                    }
                }
            }
        }
        return dist[sink] < INF;
    }
    
    pair<int, int> solve(int source, int sink) {
        int flow = 0, cost = 0;
        while (spfa(source, sink)) {
            // 计算增广路的流量
            int f = INF;
            for (int v = sink; v != source; v = prevNode[v]) {
                int u = prevNode[v];
                int idx = prevEdge[v];
                f = min(f, graph[u][idx].capacity);
            }
            // 更新流量和费用
            flow += f;
            cost += f * dist[sink];
            // 更新残余网络
            for (int v = sink; v != source; v = prevNode[v]) {
                int u = prevNode[v];
                int idx = prevEdge[v];
                graph[u][idx].capacity -= f;
                int rev = graph[u][idx].rev;
                graph[v][rev].capacity += f;
            }
        }
        return {flow, cost};
    }
};

int main() {
    cin.tie(0); cout.tie(0); ios::sync_with_stdio(false);
    int T;  cin >> T;
    for (int caseNo = 1; caseNo <= T; caseNo++) {
        int N, C, R;
        cin >> N >> C >> R;
        vector<int> req(N + 1);
        int totalReq = 0;
        for (int i = 1; i <= N; i++) {
            cin >> req[i];
            totalReq += req[i];
        }
        vector<pair<int, int>> companies(C);
        for (int i = 0; i < C; i++)
            cin >> companies[i].first >> companies[i].second;
        vector<pair<int, int>> services(R);
        for (int i = 0; i < R; i++)
            cin >> services[i].first >> services[i].second;
        // 节点编号：
        // 0: 源点
        // 1..N: 需求节点 (Day_i_demand)
        // N+1..2N: 供应节点 (Day_i_supply)
        // 2N+1: 购买节点
        // 2N+2: 汇点
         int S = 0;
        int demandStart = 1;
        int supplyStart = demandStart + N;
        int purchaseNode = supplyStart + N;
        int T = purchaseNode + 1;
        int totalNodes = T + 1;
        MinCostMaxFlow mcmf(totalNodes);
        // 1. 源点到需求节点：每天必须有r[i]的流量流出
        for (int i = 1; i <= N; i++)
            mcmf.addEdge(S, demandStart + i - 1, req[i], 0);
        // 2. 供应节点到汇点：每天必须有r[i]的流量流入
        for (int i = 1; i <= N; i++)
            mcmf.addEdge(supplyStart + i - 1, T, req[i], 0);
        // 3. 购买边：源点到购买节点
        for (int i = 0; i < C; i++)
            mcmf.addEdge(S, purchaseNode, companies[i].first, companies[i].second);
        // 4. 购买节点到供应节点：购买的车可以在任何天使用
        for (int i = 1; i <= N; i++)
            mcmf.addEdge(purchaseNode, supplyStart + i - 1, INF, 0);
        // 5. 库存传递：今天的未使用需求可以传递到明天
        for (int i = 1; i < N; i++)
            mcmf.addEdge(demandStart + i - 1, demandStart + i, INF, 0);
        // 6. 维修边：今天使用的车，维修d天后，在d+1天后可用
        // 注意：天数是 i + d[j] + 1，不是 i + d[j]
        for (int i = 1; i <= N; i++)
            for (int j = 0; j < R; j++) {
                int serviceDays = services[j].first;
                int serviceCost = services[j].second;
                int futureDay = i + serviceDays + 1;  // 关键：+1
                if (futureDay <= N)
                    // 从需求节点i到供应节点futureDay
                    mcmf.addEdge(demandStart + i - 1, 
                                supplyStart + futureDay - 1, 
                                INF, serviceCost);
            }
        // 运行最小费用最大流
        auto [flow, cost] = mcmf.solve(S, T);
        cout << "Case " << caseNo << ": ";
        if (flow < totalReq) cout << "impossible\n";
        else cout << cost << "\n";
    }
    return 0;
}
```

## 总结

本题展示了如何将复杂的现实世界调度问题转化为网络流问题。通过巧妙的建模，我们将购买、使用、维修和库存等决策统一到最小费用最大流框架中。关键点包括：

1. **节点分裂**：将每天分为需求节点和供应节点，清晰分离"需要车"和"有车可用"的概念
2. **强制需求**：通过容量限制确保每天的需求必须被满足
3. **时间建模**：通过边的连接关系正确表达时间约束（特别是维修延迟）
4. **成本分离**：购买成本和维修成本分别在不同的边上体现

这种建模方法不仅适用于本题，也可以扩展到其他具有时间维度和资源复用的调度问题中。
