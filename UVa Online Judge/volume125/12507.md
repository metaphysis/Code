## 题目描述

一个王国有 $n$ 座城市，编号从 $1$ 到 $n$ ，其中城市 $1$ 是首都。城市之间由若干条双向道路相连。

战争之后，所有道路都被摧毁。国王想要重建一些道路，使得城市之间能够重新连通。但是王国资金紧张，重建道路的总花费不能超过 $K$ 。

给出可以重建的 $m$ 条道路的列表（其他道路已彻底损坏，无法重建），国王希望最大化 **“可达人口”** ，即首都以及所有能够通过重建的道路（直接或间接）与首都相连的城市的人口总和。请你帮助国王计算这个最大值。

### 输入格式

第一行一个整数 $T$ （ $T \leq 20$ ），表示测试用例个数。

每个测试用例格式如下：

- 第一行三个整数 $n$ （ $4 \leq n \leq 16$ ）， $m$ （ $1 \leq m \leq 100$ ）， $K$ （ $1 \leq K \leq 100,000$ ）。
- 第二行 $n$ 个正整数 $p_i$ （ $1 \leq p_i \leq 10,000$ ），表示每个城市的人口。
- 接下来 $m$ 行，每行三个正整数 $u, v, c$ （ $1 \leq u, v \leq n, 1 \leq c \leq 1000$ ），表示一条可以重建的道路，连接城市 $u$ 和 $v$ ，重建花费为 $c$ 。

注意：两个城市之间可能有多条道路；一条道路不会连接同一个城市。

### 输出格式

对于每个测试用例，输出一行一个整数，表示最大的可达人口。

### 样例输入
```
2
4 6 6
500 400 300 200
1 2 4
1 3 3
1 4 2
4 3 5
2 4 6
3 2 7
4 6 5
500 400 300 200
1 2 4
1 3 3
1 4 2
4 3 5
2 4 6
3 2 7
```

### 样例输出
```
1100
1000
```

## 题目分析

### 问题本质

我们需要从给定的 $m$ 条可以重建的道路中选择一个子集，满足：

1. 重建总花费不超过 $K$ 。
2. 首都（城市 $1$ ）能够通过重建的道路到达尽可能多的城市（包括自身）。
3. 目标是最大化这些可达城市的人口总和。

换句话说，我们要找到一个 **包含首都的连通块** ，使得连通块内所有城市连通的最小花费 $\leq K$ ，并最大化连通块内城市的总人口。

### 数据范围分析

- $n \leq 16$ ，这个数字很小，提示我们可以使用 **状态压缩** 来枚举所有包含首都的城市子集。
- $m \leq 100$ ，边数适中，可以在每个子集内运行图算法。
- $K \leq 100,000$ ，花费较大，不能直接作为状态维度，但可以作为可行性判断的阈值。

### 解题思路

由于 $n$ 很小，我们可以枚举所有包含城市 $1$ 的子集 $S$ （用二进制掩码 $mask$ 表示，其中第 $i$ 位为 $1$ 表示城市 $i+1$ 在子集中）。对于每个子集 $S$ ，我们需要判断：

1. $S$ 内的所有城市是否能通过给定的道路连通成一个连通块（且首都必须在其中）。
2. 如果能连通，计算连通 $S$ 内所有城市的最小花费（即最小生成树的花费）。
3. 如果最小花费 $\leq K$ ，则 $S$ 是一个可行解，计算 $S$ 内城市的总人口，并更新答案。

因此，算法的核心步骤为：

1. 预处理每个子集 $mask$ 的总人口 $population[mask]$ 。
2. 枚举所有包含城市 $1$ 的子集 $mask$ 。
3. 对于每个 $mask$ ，从所有给定的边中筛选出两端都在 $mask$ 内的边，构成一个子图。
4. 在该子图上运行 $\texttt{Kruskal}$ 算法，计算最小生成树的花费 $cost$ ，并检查是否所有在 $mask$ 内的城市都连通（即是否与首都同属一个连通分量）。
5. 若 $cost \leq K$ 且所有城市连通，则用 $population[mask]$ 更新答案。

### 为什么这样做是正确的？

- 我们枚举了所有可能成为“可达城市集合”的子集。
- 对于每个子集，最小生成树给出了连通这些城市的最小花费，如果这个花费都不超过 $K$ ，那么一定存在一种重建方案使得这些城市全部与首都连通。
- 如果最小生成树的花费超过 $K$ ，那么无论怎么选边，连通这些城市的花费都会超过 $K$ ，因此该子集不可行。
- 由于我们枚举了所有子集，并取其中人口最大值，因此最终答案一定是全局最优解。

### 时间复杂度

- 子集总数： $2^{n-1}$ （因为必须包含城市 $1$ ，实际枚举 $2^{n-1}$ 个）。
- 每个子集运行一次 $\texttt{Kruskal}$ ，边的筛选和排序复杂度为 $O(m \log m)$ 。
- 总复杂度为 $O(2^{n-1} \times m \log m)$ 。当 $n \leq 16, m \leq 100$ 时，计算量在可接受范围内（约 $2^{15} \times 100 \times \log 100 \approx 3.2 \times 10^6$ 次操作）。

## 算法细节与实现要点

### 1. 状态表示与预处理

用整数 $mask$ 的二进制位表示城市是否在子集中，第 $i$ 位（ $0$ 起始编号）对应城市 $i+1$ 。  
预处理数组 $subsetPopulation[mask]$ 可以在 $O(n \cdot 2^n)$ 内完成。

### 2. 边的筛选

对于每个 $mask$ ，遍历所有 $m$ 条边，如果边的两个端点城市在 $mask$ 中对应的位都为 $1$ ，则将该边加入当前子集的边集。

### 3. 最小生成树与连通性检查

使用 $\texttt{Kruskal}$ 算法时需要注意：

- 需要对当前子集的边按花费排序。
- 使用并查集维护连通性。
- 在合并边时计数，当合并次数达到 $|S|-1$ 时即可提前终止（因为树有 $|S|-1$ 条边）。
- 最后检查所有在 $mask$ 中的城市是否都与首都（城市 $1$ ，对应位 $0$ ）在同一个并查集根下。如果有一个不在，说明该子集无法连通。

### 4. 特殊情况的处理

- 如果子集只包含首都（ $mask = 1$ ），则不需要任何边，花费为 $0$ ，人口就是首都人口。
- 两个城市之间可能有多条边， $\texttt{Kruskal}$ 会自动选择花费最小的边，因此不影响结果。
- 注意输入中的城市编号是 $1$ -based，而状态压缩是 $0$ -based，需要小心转换。

## 代码实现

```cpp
// Kingdoms
// UVa ID: 12507
// Verdict: Accepted
// Submission Date: 2025-12-14
// UVa Run Time: 0.050s
//
// 版权所有（C）2025，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

struct Edge {
    int u, v, cost;
    bool operator<(const Edge& other) const {
        return cost < other.cost;
    }
};

int findParent(vector<int>& parent, int x) {
    if (parent[x] != x) parent[x] = findParent(parent, parent[x]);
    return parent[x];
}

bool unionSets(vector<int>& parent, vector<int>& rank, int a, int b) {
    int ra = findParent(parent, a), rb = findParent(parent, b);
    if (ra == rb) return false;
    if (rank[ra] < rank[rb]) parent[ra] = rb;
    else if (rank[ra] > rank[rb]) parent[rb] = ra;
    else parent[rb] = ra, rank[ra]++;
    return true;
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        int n, m, k;
        cin >> n >> m >> k;
        vector<int> population(n + 1);
        for (int i = 1; i <= n; i++) cin >> population[i];
        vector<Edge> edges(m);
        for (int i = 0; i < m; i++) cin >> edges[i].u >> edges[i].v >> edges[i].cost;

        // 预处理所有包含城市1的子集的总人口
        int maxMask = 1 << n;
        vector<int> subsetPopulation(maxMask, 0);
        for (int mask = 0; mask < maxMask; mask++) {
            if (!(mask & 1)) continue; // 必须包含城市1（第0位）
            for (int i = 0; i < n; i++)
                if (mask & (1 << i)) subsetPopulation[mask] += population[i + 1];
        }

        int ans = 0;
        // 枚举所有包含城市1的子集
        for (int mask = 1; mask < maxMask; mask += 2) { // 保证第0位为1
            // 筛选出两端都在子集内的边
            vector<Edge> subsetEdges;
            for (const Edge& e : edges) {
                int u = e.u - 1, v = e.v - 1; // 转为0-based
                if ((mask >> u) & 1 && (mask >> v) & 1) subsetEdges.push_back(e);
            }
            sort(subsetEdges.begin(), subsetEdges.end());

            // Kruskal 求最小生成树花费
            vector<int> parent(n), rank(n, 0);
            for (int i = 0; i < n; i++) parent[i] = i;
            int cost = 0, connected = 0;
            int target = __builtin_popcount(mask) - 1; // 生成树应有 |S|-1 条边
            for (const Edge& e : subsetEdges) {
                if (unionSets(parent, rank, e.u - 1, e.v - 1)) {
                    cost += e.cost;
                    connected++;
                }
                if (connected == target) break; // 已形成生成树，提前退出
            }

            // 检查子集内所有城市是否都与首都连通
            int root = findParent(parent, 0); // 首都的根
            bool allConnected = true;
            for (int i = 0; i < n; i++) {
                if ((mask >> i) & 1 && findParent(parent, i) != root) {
                    allConnected = false;
                    break;
                }
            }

            // 如果全部连通且花费不超限，更新答案
            if (allConnected && cost <= k) ans = max(ans, subsetPopulation[mask]);
        }

        cout << ans << endl;
    }
    return 0;
}
```

## 总结

本题是一道结合了 **状态压缩枚举** 与 **最小生成树** 的经典题目。通过枚举所有可能的连通块（城市子集），并利用 $\texttt{Kruskal}$ 算法验证其连通性和最小花费，最终找出满足条件的最优解。

关键点在于：

1. 利用 $n$ 很小的特点，采用状态压缩枚举子集。
2. 对每个子集独立运行最小生成树算法，判断可行性。
3. 注意代码细节，尤其是并查集的操作和连通性检查。

该算法在题目给定的数据范围内完全可行，且思路清晰，实现较为直接。
