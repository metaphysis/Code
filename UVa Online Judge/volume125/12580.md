## 题目描述

有 $N$ 名球员站成一排，你需要从中**按原顺序**选出恰好 $11$ 名球员，使得选出的序列**字典序最大**。如果无法选出 $11$ 人（即 $N < 11$），输出 `go home!`。

字典序比较规则：先比较第 $1$ 人的身高，较高者胜；若相等则比较第 $2$ 人，依此类推。

## 题目分析

这是一个典型的**固定长度最大字典序子序列**问题。与通常的 $\texttt{LIS}$ 或子序列问题不同，这里要求子序列长度固定为 $11$，且只需要字典序最大，不需要考虑身高的单调性等额外条件。

**核心难点**：当第 $1$ 个位置有多个相同的最大值时，不能简单选择最左边的，因为不同的选择会导致剩余部分的可选空间不同，进而影响后续位置的字典序大小。

## 解法一：动态规划

### 思路定义

定义 $dp[i][k]$ 表示：**从第 $i$ 个位置开始，选择 $k$ 个球员能够得到的字典序最大的子序列的第一个位置**。

如果从 $i$ 开始无法选出 $k$ 个球员，则 $dp[i][k] = -1$。

### 状态转移

对于状态 $dp[i][k]$，我们需要在区间 $[i, N-k+1]$ 内选择第一个球员。这个区间保证后面至少能选出 $k-1$ 个球员。

1. 找出区间 $[i, N-k+1]$ 中的最大值 $M$
2. 遍历区间内所有等于 $M$ 的位置 $j$
3. 对于每个候选 $j$，其完整的 $k$ 元组为：
   $$[h[j]] + \text{seq}(dp[j+1][k-1])$$
4. 选择字典序最大的那个候选，将其位置存入 $dp[i][k]$

### 边界条件

- $dp[i][0]$ 表示空序列，可以统一设为 $N+1$（虚拟哨兵位置）
- 当 $k=1$ 时，$dp[i][1] = i$（只有一个位置可选）

### 比较函数

比较两个候选 $j_1$ 和 $j_2$ 时，需要递归地比较它们的完整序列：

1. 比较 $h[j_1]$ 和 $h[j_2]$，不等则直接得出结果
2. 若相等，则比较 $dp[j_1+1][k-1]$ 和 $dp[j_2+1][k-1]$ 对应的序列

### 复杂度分析

- 状态数：$O(N \cdot 11) \approx 2000 \times 11 = 22000$
- 每个状态需要扫描区间找最大值：$O(N)$
- 候选比较：最坏 $O(N)$ 个候选，每个比较 $O(11)$
- 总时间复杂度：$O(N^2 \cdot 11) \approx 4.4 \times 10^7$，可通过

### 参考代码

```cpp
// Yell Classico
// UVa ID: 12580
// Verdict: Accepted
// Submission Date: 2026-04-25
// UVa Run Time: 0.840s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 2005;
int N;
int h[MAXN];
int dp[MAXN][12]; // dp[i][k]：从 i 开始选 k 个的最优起始位置

// 返回 true 表示方案 A 比方案 B 字典序更大
bool isBetter(int posA, int kA, int posB, int kB) {
    if (kA == 0) return false;
    if (kB == 0) return true;
    if (h[posA] != h[posB]) return h[posA] > h[posB];
    // 第一个相等，比较剩余部分
    return isBetter(dp[posA + 1][kA - 1], kA - 1, dp[posB + 1][kB - 1], kB - 1);
}

void solve() {
    // 边界：k = 0 用 pos = N+1 表示空
    for (int i = 1; i <= N + 2; ++i) 
        dp[i][0] = N + 1;
    
    for (int k = 1; k <= 11; ++k) {
        for (int i = N - k + 1; i >= 1; --i) {
            int end = N - k + 1;
            // 找到区间 [i, end] 中的最大值
            int maxVal = -1;
            for (int j = i; j <= end; ++j) 
                if (h[j] > maxVal) maxVal = h[j];
            
            int bestPos = -1;
            // 遍历所有等于 maxVal 的位置
            for (int j = i; j <= end; ++j) {
                if (h[j] == maxVal) {
                    if (bestPos == -1) bestPos = j;
                    else {
                        // 比较 (j 作为第一个) 和 (bestPos 作为第一个)
                        if (isBetter(dp[j + 1][k - 1], k - 1, dp[bestPos + 1][k - 1], k - 1))
                            bestPos = j;
                    }
                }
            }
            dp[i][k] = bestPos;
        }
    }
}

int main() {
    int T;
    scanf("%d", &T);
    for (int caseNo = 1; caseNo <= T; ++caseNo) {
        scanf("%d", &N);
        for (int i = 1; i <= N; ++i) scanf("%d", &h[i]);

        if (N < 11) {
            printf("Case %d: go home!\n", caseNo);
            continue;
        }

        solve();
        
        int cur = dp[1][11];
        printf("Case %d:", caseNo);
        for (int k = 11; k >= 1; --k) {
            printf(" %d", h[cur]);
            if (k == 1) break;
            cur = dp[cur + 1][k - 1];
        }
        printf("\n");
    }
    return 0;
}
```

## 解法二：贪心优化

### 关键洞察

在解法一的比较过程中，我们发现一个重要的性质：

**当区间内有多个相同最大值时，选择最左边的一定不会比选择右边差。**

### 证明

设两个候选位置 $p < q$，且 $h[p] = h[q] = M$（都是区间最大值）。

从 $p$ 开始选 $L$ 个球员，可选的剩余区间是 $[p+1, N]$。  
从 $q$ 开始选 $L$ 个球员，可选的剩余区间是 $[q+1, N]$。

由于 $p+1 \le q$，区间 $[q+1, N]$ 是 $[p+1, N]$ 的子集。这意味着：

- 在每一步决策中，$p$ 方案的候选集都包含了 $q$ 方案的候选集
- 因此 $p$ 方案的每一位都不会小于 $q$ 方案的对应位
- 所以 $p$ 方案的字典序 $\ge$ $q$ 方案的字典序

**结论**：选择最左边的最大值总是最优的，无需进行复杂的序列比较。

### 贪心算法描述

有了上述性质，算法变得极其简单：

1. 初始化 `cur = 1`
2. 对于 $k$ 从 $11$ 到 $1$：
   - 确定区间右边界 `end = N - k + 1`
   - 在区间 `[cur, end]` 中找到最大值及其最左边的位置
   - 输出该最大值
   - 将 `cur` 更新为该位置 `+1`

### 复杂度分析

- 每次选择只需扫描区间一次，$O(N)$
- 共 $11$ 次选择
- 总时间复杂度：$O(11 \cdot N) \approx 22000$，**极快**

### 为什么这个优化是可行的？

解法一之所以需要复杂的比较，是因为它假设不同候选会导致不同的后续序列。但通过数学归纳法可以证明：

- 当 $k=1$ 时，显然选最左最优
- 假设对于 $k-1$ 成立，对于 $k$，选最左的 $M$ 后，剩余问题就是 $k-1$ 规模的相同问题，根据归纳假设继续选最左即可

因此，每一步的贪心选择不会破坏后续的最优性。

### 参考代码

```cpp
// Yell Classico
// UVa ID: 12580
// Verdict: Accepted
// Submission Date: 2026-04-25
// UVa Run Time: 0.000s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 2005;
int N, h[MAXN];

int main() {
    int T;
    scanf("%d", &T);
    for (int caseNo = 1; caseNo <= T; ++caseNo) {
        scanf("%d", &N);
        for (int i = 1; i <= N; ++i) scanf("%d", &h[i]);
        
        if (N < 11) {
            printf("Case %d: go home!\n", caseNo);
            continue;
        }
        
        int cur = 1;
        printf("Case %d:", caseNo);
        
        for (int L = 11; L >= 1; --L) {
            int end = N - L + 1;
            int maxVal = -1, best = -1;
            // 找区间 [cur, end] 中的最大值（取最左边）
            for (int i = cur; i <= end; ++i) {
                if (h[i] > maxVal) {
                    maxVal = h[i];
                    best = i;
                }
            }
            printf(" %d", maxVal);
            cur = best + 1;
        }
        printf("\n");
    }
    return 0;
}
```

## 两种解法对比

| 维度 | 动态规划解法 | 贪心优化解法 |
|------|------------|------------|
| 时间复杂度 | $O(N^2 \cdot 11)$ | $O(11 \cdot N)$ |
| 空间复杂度 | $O(N \cdot 11)$ | $O(N)$ |
| 代码复杂度 | 较复杂，需要递归比较 | 极简，几行核心逻辑 |
| 正确性证明 | 直接，但比较繁琐 | 需借助数学归纳 |

贪心优化解法充分利用了问题的特殊性（长度固定为 $11$）和最优子结构性质，将复杂的 $\texttt{DP}$ 比较简化为简单的区间最大值查询，是本题的最优解。
