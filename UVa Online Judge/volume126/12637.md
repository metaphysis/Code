## 题目分析

$\texttt{Pizza Planet}$ 要在 $\texttt{Gridland}$ 城市中实现 "30 分钟或更少" 的配送承诺，需要最小化所有配送员的总行驶距离。$\texttt{Gridland}$ 是一个网格状城市，两点之间的距离采用曼哈顿距离计算。

问题可以抽象为：有 $R$ 个餐厅和 $N$ 个订单，每个餐厅最多只能配送一个订单，需要将每个订单分配给一个不同的餐厅，使得所有订单的配送距离之和最小。

关键约束条件：
- $1 \leq R \leq 100$，$1 \leq N \leq R$
- 餐厅数量不少于订单数量
- 坐标范围：$-10^3 \leq x, y \leq 10^3$

这是一个典型的**二分图最小权匹配问题**：
- 左部节点：$N$ 个订单
- 右部节点：$R$ 个餐厅
- 边权：订单到餐厅的曼哈顿距离

由于 $N \leq R$，我们需要从 $R$ 个餐厅中选出 $N$ 个与订单一一匹配，使得总距离最小。

## 解题思路

### 1. 问题转化

构建一个 $N \times R$ 的权值矩阵 $cost[i][j]$，表示第 $i$ 个订单到第 $j$ 个餐厅的曼哈顿距离：
$$cost[i][j] = |x_i^{order} - x_j^{rest}| + |y_i^{order} - y_j^{rest}|$$

我们的目标是从矩阵中选出 $N$ 个元素，每行选一个，每列最多选一个，使得选出的元素之和最小。

### 2. 算法选择

对于二分图最小权匹配问题，可以使用**匈牙利算法**（也称为 $\texttt{Kuhn-Munkres}$ 算法）求解。匈牙利算法通常用于求解最大权匹配，但可以通过将权值取负转化为最小权匹配问题。

算法复杂度：$O(n^3)$，其中 $n = \max(N, R)$。在本问题中 $n \leq 100$，完全可行。

### 3. 算法原理

匈牙利算法的核心思想是通过不断调整顶标值来寻找增广路，最终得到最优匹配。

对于最小权匹配，我们使用如下策略：
- 初始顶标：左部顶标 $u[i] = 0$，右部顶标 $v[j] = 0$
- 松弛函数：$slack[j] = \min(cost[i][j] - u[i] - v[j])$
- 通过不断调整顶标，直到找到完美匹配

算法的关键是维护两个数组：
- $u[i]$：左部第 $i$ 个节点的顶标
- $v[j]$：右部第 $j$ 个节点的顶标
- $p[j]$：右部第 $j$ 个节点匹配的左部节点
- $way[j]$：记录增广路径

### 4. 算法步骤

1. 初始化 $u$ 和 $v$ 为 0
2. 对每个左部节点 $i$ 进行匹配：
   - 初始化 $minv$ 数组为无穷大
   - 初始化 $used$ 数组标记已访问的右部节点
   - 设置 $p[0] = i$，$j0 = 0$
   - 循环寻找增广路：
     * 标记当前右部节点 $j0$ 为已访问
     * 对于所有未访问的右部节点 $j$，更新 $minv[j]$ 和 $way[j]$
     * 找到最小的 $minv[j]$ 作为 $delta$
     * 更新顶标：已访问的左部节点 $u$ 增加 $delta$，已访问的右部节点 $v$ 减少 $delta$
     * 未访问的右部节点的 $minv$ 减少 $delta$
     * 移动到下一个右部节点
   - 回溯更新匹配关系
3. 最终最小权值为 $-v[0]$

### 5. 实现细节

- 使用 $\texttt{INF} = 10^9$ 表示无穷大
- 曼哈顿距离计算函数直接使用绝对值运算
- 输入包含多个测试用例，直到文件结束
- 输出每个测试用例的最小总距离

```cpp
#include <bits/stdc++.h>
using namespace std;

const int INF = 1e9;

// 计算曼哈顿距离
int manhattan(pair<int, int> a, pair<int, int> b) {
    return abs(a.first - b.first) + abs(a.second - b.second);
}

// 匈牙利算法求最小权匹配
int hungarian(const vector<vector<int>>& cost) {
    int n = cost.size();      // 左部节点数（订单数）
    int m = cost[0].size();   // 右部节点数（餐厅数）
    
    // u[i] 左部顶标，v[j] 右部顶标
    // p[j] 右部节点匹配的左部节点
    // way[j] 记录增广路径
    vector<int> u(n + 1), v(m + 1), p(m + 1), way(m + 1);
    
    for (int i = 1; i <= n; ++i) {
        p[0] = i;
        int j0 = 0;
        vector<int> minv(m + 1, INF);
        vector<bool> used(m + 1, false);
        
        do {
            used[j0] = true;
            int i0 = p[j0];
            int delta = INF;
            int j1;
            
            // 更新所有未访问右部节点的 minv
            for (int j = 1; j <= m; ++j) {
                if (!used[j]) {
                    int cur = cost[i0 - 1][j - 1] - u[i0] - v[j];
                    if (cur < minv[j]) {
                        minv[j] = cur;
                        way[j] = j0;
                    }
                    if (minv[j] < delta) {
                        delta = minv[j];
                        j1 = j;
                    }
                }
            }
            
            // 更新顶标
            for (int j = 0; j <= m; ++j) {
                if (used[j]) {
                    u[p[j]] += delta;
                    v[j] -= delta;
                } else {
                    minv[j] -= delta;
                }
            }
            
            j0 = j1;
        } while (p[j0] != 0);
        
        // 回溯更新匹配
        do {
            int j1 = way[j0];
            p[j0] = p[j1];
            j0 = j1;
        } while (j0);
    }
    
    // 最小权值即为 -v[0]
    return -v[0];
}

int main() {
    int R, N;
    while (cin >> R >> N) {
        vector<pair<int, int>> restaurants(R), orders(N);
        
        // 读入餐厅坐标
        for (int i = 0; i < R; ++i) {
            cin >> restaurants[i].first >> restaurants[i].second;
        }
        
        // 读入订单坐标
        for (int i = 0; i < N; ++i) {
            cin >> orders[i].first >> orders[i].second;
        }
        
        // 构建成本矩阵：订单 i 到餐厅 j 的距离
        vector<vector<int>> cost(R, vector<int>(N));
        for (int i = 0; i < R; ++i) {
            for (int j = 0; j < N; ++j) {
                cost[i][j] = manhattan(restaurants[i], orders[j]);
            }
        }
        
        // 转置矩阵，使左部为订单，右部为餐厅
        // 这样左部节点数 N <= 右部节点数 R，满足匈牙利算法的要求
        vector<vector<int>> transposedCost(N, vector<int>(R));
        for (int i = 0; i < N; ++i) {
            for (int j = 0; j < R; ++j) {
                transposedCost[i][j] = cost[j][i];
            }
        }
        
        // 求解最小权匹配
        int ans = hungarian(transposedCost);
        cout << ans << endl;
    }
    
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：$O(\max(R, N)^3) \approx O(100^3) = 10^6$，对于每个测试用例完全可行
- **空间复杂度**：$O(R \times N) \approx O(10^4)$，用于存储成本矩阵

## 总结

本题是一个典型的二分图最小权匹配问题，通过匈牙利算法可以高效求解。关键点在于：
1. 正确理解问题并转化为图论模型
2. 处理 $N \leq R$ 的情况，通过转置矩阵满足算法要求
3. 掌握匈牙利算法的实现细节，特别是顶标的更新方式

该算法在 $R, N \leq 100$ 的约束下运行良好，是解决此类问题的标准方法。
