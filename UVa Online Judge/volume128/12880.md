## 题目描述

波尔图读书俱乐部每年都会举办一次图书交换活动。每个会员带来自己最喜欢的一本书，并尝试与其他会员交换，以得到一本自己喜欢的书。 

过去的交换规则很简单：如果会员 $A$ 喜欢会员 $B$ 的书，同时会员 $B$ 也喜欢会员 $A$ 的书，那么他们可以直接交换。但这种方式有一个明显的缺点：很多会员最终无法交换到新书，只能带走自己原来的书。

为了提高交换成功率，我们考虑更灵活的交换方式：不仅限于两人之间的直接交换，还可以进行**多人循环交换** 。例如，会员 $A$ 喜欢会员 $B$ 的书，会员 $B$ 喜欢会员 $C$ 的书，会员 $C$ 喜欢会员 $A$ 的书，那么这三个人可以形成一个交换循环：$A$ 得到 $B$ 的书，$B$ 得到 $C$ 的书，$C$ 得到 $A$ 的书，每个人都能获得一本自己喜欢的新书。

推广开来，我们可以寻找任意大小的交换循环。现在的问题是：给定所有会员以及他们喜欢的书（注意：每个人永远不会喜欢自己带来的书），能否找到一种交换方案，使得**每个会员**都能得到一本自己喜欢的新书？

### 输入格式

输入包含多个测试用例。每个测试用例格式如下：

- 第一行：两个整数 $N$ （会员人数）和 $M$ （“喜欢”关系的总数）。
- 接下来 $M$ 行：每行两个整数 $A$ 和 $B$ ，表示会员 $A$ 喜欢会员 $B$ 带来的书（ $0 \le A, B < N$ ，且 $A \ne B$ ）。

### 输出格式

对于每个测试用例，如果能够找到一种交换方案使得每个会员都获得一本自己喜欢的新书，则输出 `YES` ；否则输出 `NO` 。

### 数据范围

- $2 \le N \le 10\,000$
- $1 \le M \le 20\,000$ 且 $M \le N^2 - N$

## 题目分析

### 问题转化

我们需要为每个会员分配一本新书（不能是他自己带来的书），并且分配的这本书必须是他喜欢的。设共有 $N$ 个会员，编号为 $0$ 到 $N-1$ 。会员 $i$ 带来的书可以看作“资源 $i$ ”。那么，一个有效的交换方案可以看作一个**排列** $\pi$ ，满足：

1. $\pi(i) \ne i$ （不能得到自己的书）；
2. 会员 $i$ 喜欢会员 $\pi(i)$ 的书，即存在有向边 $i \to \pi(i)$ 。

这实际上是一个**匹配问题** ：把每个会员看作“需求者”，把每本书看作“资源”，如果会员 $i$ 喜欢会员 $j$ 的书，就在需求者 $i$ 和资源 $j$ 之间连一条边。我们需要找到一个**完美匹配** ，即每个需求者都匹配到一个不同的资源，并且匹配不能是自环（ $i$ 不能匹配 $i$ ）。

因此，原问题等价于：给定一个二分图，左部为 $N$ 个需求者（会员），右部为 $N$ 个资源（书），边集表示“喜欢”关系。问是否存在一个完美匹配。

### 为什么是二分图匹配？

考虑一个交换方案，它实际上是由若干个不相交的循环组成的。例如，一个三元循环 $A \to B \to C \to A$ 对应于匹配： $A$ 匹配 $B$ ， $B$ 匹配 $C$ ， $C$ 匹配 $A$ 。由于每个会员只能得到一本书，也只会提供一本书，所以匹配必须是一个双射。这正是二分图完美匹配的定义。

### 算法选择

二分图最大匹配的经典算法有：

1. **匈牙利算法** （$\texttt{Hungarian Algorithm}$）：时间复杂度 $O(N \cdot M)$ ，在最坏情况下（ $N=10^4$ ， $M=2\times10^4$ ）可能达到 $2\times10^8$ 次操作，虽然理论上勉强可行，但实际运行可能较慢。
2. **$\texttt{Hopcroft-Karp}$ 算法** ：时间复杂度 $O(\sqrt{N} \cdot M)$ ，对于本题数据范围（ $N=10^4$ ， $M=2\times10^4$ ），操作次数约为 $\sqrt{10^{4}} \times  2 \times$$10^{4}$$= 100 \times 2 \times$$10^{4}$ $= 2 \times 10^6$ ，非常高效。

因此，我们选择 **$\texttt{Hopcroft-Karp}$ 算法** 来求解二分图最大匹配，然后检查匹配数是否等于 $N$ 。

### 算法步骤

1. **建图** ：建立二分图，左部节点为会员（需求者），右部节点为书（资源），根据输入添加边。
2. **运行 $\texttt{Hopcroft-Karp}$ 算法** 计算最大匹配数。
3. **判断** ：如果最大匹配数等于 $N$ ，则输出 `YES` ，否则输出 `NO` 。

### 为什么不是强连通分量？

最初可能会误以为需要整个图强连通，或者每个节点都在某个环中。但考虑以下反例：有 $3$ 个会员 $A,B,C$ ，边为 $A \to B$ ， $B \to A$ ， $A \to C$ ， $C \to A$ 。虽然这三个节点在同一个强连通分量中，但无法形成完美匹配：因为 $B$ 和 $C$ 都只能与 $A$ 匹配，而 $A$ 只能匹配一个，所以总有一个人无法得到新书。这验证了本问题本质是匹配问题，而不是环覆盖问题。

## 代码实现

```cpp
// Book Club
// UVa ID: 12880

// 版权所有（C）2025，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

const int INF = 1e9;

// Hopcroft-Karp 算法求二分图最大匹配
class HopcroftKarp {
private:
    int nLeft, nRight;          // 左部节点数、右部节点数
    vector<vector<int>> adj;    // 邻接表，adj[u] 存储左部节点u连接的右部节点
    vector<int> dist;           // BFS距离数组
    vector<int> matchLeft;      // matchLeft[u] = v 表示左部节点u匹配到右部节点v
    vector<int> matchRight;     // matchRight[v] = u 表示右部节点v匹配到左部节点u
    
    // BFS：构建层次图，返回是否存在增广路
    bool bfs() {
        queue<int> q;
        dist[0] = INF;  // 虚拟节点0，用于标记未匹配的左部节点
        
        // 初始化：将所有未匹配的左部节点加入队列
        for (int u = 1; u <= nLeft; u++) {
            if (matchLeft[u] == 0) {
                dist[u] = 0;
                q.push(u);
            } else {
                dist[u] = INF;
            }
        }
        
        while (!q.empty()) {
            int u = q.front(); q.pop();
            
            // 只处理距离小于INF的节点（即可能找到增广路的节点）
            if (dist[u] < dist[0]) {
                for (int v : adj[u]) {
                    // 如果右部节点v的匹配节点还未被访问
                    if (dist[matchRight[v]] == INF) {
                        dist[matchRight[v]] = dist[u] + 1;
                        q.push(matchRight[v]);
                    }
                }
            }
        }
        
        // 如果虚拟节点0的距离被更新，说明存在增广路
        return dist[0] != INF;
    }
    
    // DFS：在层次图中寻找增广路
    bool dfs(int u) {
        if (u != 0) {
            for (int v : adj[u]) {
                // 按照层次图前进
                if (dist[matchRight[v]] == dist[u] + 1 && dfs(matchRight[v])) {
                    // 找到增广路，更新匹配
                    matchLeft[u] = v;
                    matchRight[v] = u;
                    return true;
                }
            }
            // 当前节点无法找到增广路，标记为无穷大（不再访问）
            dist[u] = INF;
            return false;
        }
        // 到达虚拟节点0，成功找到增广路
        return true;
    }
    
public:
    // 构造函数，初始化左右部节点数
    HopcroftKarp(int leftSize, int rightSize) : 
        nLeft(leftSize), nRight(rightSize), 
        adj(leftSize + 1), 
        dist(leftSize + 1), 
        matchLeft(leftSize + 1, 0), 
        matchRight(rightSize + 1, 0) {}
    
    // 添加边：左部节点u -> 右部节点v
    void addEdge(int u, int v) {
        adj[u].push_back(v);
    }
    
    // 计算最大匹配数
    int maxMatching() {
        int matching = 0;
        
        // 多次BFS+DFS，直到找不到增广路
        while (bfs()) {
            for (int u = 1; u <= nLeft; u++) {
                if (matchLeft[u] == 0 && dfs(u)) {
                    matching++;
                }
            }
        }
        
        return matching;
    }
    
    // 判断是否存在完美匹配
    bool isPerfectMatch() {
        return maxMatching() == nLeft;
    }
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n, m;
    while (cin >> n >> m) {
        // 创建Hopcroft-Karp对象，注意使用1-based编号
        HopcroftKarp hk(n, n);
        
        // 读入边并建图
        for (int i = 0; i < m; i++) {
            int a, b;
            cin >> a >> b;
            // 输入是0-based，转换为1-based
            hk.addEdge(a + 1, b + 1);
        }
        
        // 检查是否存在完美匹配
        if (hk.isPerfectMatch()) {
            cout << "YES\n";
        } else {
            cout << "NO\n";
        }
    }
    
    return 0;
}
```

## 复杂度分析

- **时间复杂度** ：$\texttt{Hopcroft-Karp}$ 算法的时间复杂度为 $O(\sqrt{N} \cdot M)$ ，其中 $N$ 为节点数， $M$ 为边数。对于本题数据范围（ $N \le 10^4$ ， $M \le 2\times10^4$ ），完全可以在时限内完成。
- **空间复杂度** ： $O(N + M)$ ，主要用于存储邻接表和匹配数组。

## 总结

本题的关键在于将图书交换问题转化为**二分图完美匹配**问题。通过建立“需求者-资源”二分图，并利用高效的 $\texttt{Hopcroft-Karp}$ 算法求解最大匹配，我们可以快速判断是否存在满足条件的交换方案。这种转化思想在解决类似“分配”、“配对”问题时非常有用。

值得注意的是，题目虽然描述了“循环交换”，但本质上不需要显式地找出循环，只需要判断完美匹配是否存在即可。这也体现了图论中“匹配”与“环覆盖”之间的深刻联系。
