## 题目描述

自从玛丽学习了回文数，她就完全痴迷于它们。实际上，她想要制作一个回文数目录作为个人项目。

对于不知道的人来说，**回文数** 是一个自然数，从左到右读（避免前导零）与从右到左读是相同的。例如，$1991$ 是一个回文数，但 $1492$ 不是。注意，唯一以数字 $0$ 结尾的回文数就是数字 $0$ 本身。另外，一个数是否是回文数，取决于表示该数所使用的进制。玛丽只对十进制回文数感兴趣，即以常规十进制表示的数。

当然，玛丽构建完整目录的项目是不可能完成的，因为回文数是无限的。但是，如果能够生成连续的回文数组，她仍然会很高兴。这样，她就"更接近"完成项目的目标——打印出完整的回文数目录。

玛丽请求你的帮助。她希望有一个程序，给定两个正整数 $n$ 和 $d$ ，输出大于 $d$ 的前 $n$ 个回文数。

### 输入格式

输入包含多个测试用例。每个测试用例由一行组成，包含两个空格分隔的整数 $n$ 和 $d$ （ $1 \leq n \leq 10^2$ ， $1 \leq d \leq 10^{60}$ ）。数字以十进制表示，没有前导零。

### 输出格式

对于每个测试用例，输出 $n$ 行，每行是大于 $d$ 的前 $n$ 个回文数。按升序输出列表，数字以十进制表示，没有前导零。

### 样例输入

```
3 8
4 175
2 77
1 20003
```

### 样例输出

```
9
11
22
181
191
202
212
88
99
20102
```

## 题目分析

### 问题特点

1. **大整数范围** ： $d$ 最大可达 $10^{60}$ ，这意味着不能使用普通的整数类型（如 `long long` ）来存储和处理数字，必须使用字符串或高精度算法。
2. **输出数量有限** ： $n$ 最大为 $100$ ，这意味着我们可以逐个生成回文数，而不需要一次性生成太多。
3. **回文数特性** ：回文数关于中心对称，这个特性可以用来高效构造回文数。

### 关键挑战

1. **高效生成下一个回文数** ：给定一个大整数，需要快速找到比它大的最小回文数。
2. **处理边界情况** ：如数字全是 $9$ 的情况（ $999 \rightarrow 1001$ ），以及数字已经是回文数的情况。
3. **避免超时** ：虽然 $n$ 不大，但每个数字可能很长（最多 $60$ 位），算法需要足够高效。

---

## 解题思路

### 核心思想：直接构造法

与其逐个检查每个数是否为回文数（这种方法在大数字时效率极低），不如直接构造下一个回文数。思路如下：

1. **将数字分为左右两部分** ：
   - 对于长度为 $len$ 的数字，左半部分为前 $\lceil len/2 \rceil$ 位。
   - 例如：数字 $12345$ ， $len=5$ ，左半部分为 $123$ 。

2. **构造回文数** ：
   - 将左半部分反转后复制到右半部分。
   - 对于奇数长度，右半部分需要去掉中间字符。
   - 例如：左半部分 $123$ ， $len=5$ ，构造的回文数为 $12321$ 。

3. **比较与调整** ：
   - 如果构造的回文数小于等于原数，则将左半部分加 $1$ ，然后重新构造回文数。
   - 例如：原数 $12321$ ，构造得到 $12321$ ，相等，需要将左半部分 $123$ 加 $1$ 得到 $124$ ，重新构造为 $12421$ 。

4. **特殊处理** ：
   - 当数字全是 $9$ 时（如 $999$ ），下一个回文数是 $1001$ 。
   - 注意处理左半部分加 $1$ 后产生的进位（如 $199$ 的左半部分 $19$ 加 $1$ 后变为 $20$ ）。

### 算法步骤

对于每个测试用例：

1. 读取 $n$ 和 $d$ 。
2. 初始化当前数字为 $d$ 。
3. 循环 $n$ 次：
   - 调用 `nextPalindrome` 函数获取下一个回文数。
   - 输出该回文数。
   - 更新当前数字为该回文数。

`nextPalindrome` 函数详细步骤：

1. 检查输入数字是否全是 $9$ ，如果是，直接返回 $100...001$ （长度增加 $1$ ）。
2. 获取数字长度 $len$ 。
3. 取左半部分 $left = s.substr(0, (len+1)/2)$ 。
4. 构造候选回文数 $candidate = makePalindrome(left, len)$ 。
5. 如果 $candidate \leq s$ ，则将左半部分加 $1$ ：
   - 从右向左处理进位。
   - 如果有进位导致长度增加（如 $99 \rightarrow 100$ ），调整左半部分。
   - 重新构造回文数。
6. 返回构造的回文数。

### 复杂度分析

- **时间复杂度** ：每个回文数的构造需要 $O(L)$ 时间，其中 $L$ 是数字长度（最大 $60$ ）。总时间复杂度为 $O(n \cdot L)$ ，对于 $n \leq 100$ 完全可行。
- **空间复杂度** ： $O(L)$ ，主要用于存储字符串。

### 边界情况考虑

1. **输入数字本身就是回文数** ：需要返回比它大的下一个回文数。
2. **数字全是 $9$** ：如 $999$ 的下一个回文数是 $1001$ ，长度增加。
3. **进位处理** ：左半部分加 $1$ 可能产生进位，如 $199$ 的下一个回文数是 $202$ 。
4. **长度为奇数和偶数的区别** ：构造回文数时处理方式不同。

## 代码实现

```cpp
// Next Palindromic Numbers
// UVa ID: 12940
// Verdict: Accepted
// Submission Date: 2026-01-01
// UVa Run Time: 0.010s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

// 将左半部分反转复制到右半部分构造回文数
string makePalindrome(const string &left, int len) {
    string result = left;
    string right = left;
    reverse(right.begin(), right.end());
    if (len % 2 == 1) {
        // 奇数长度，去掉中间字符
        right = right.substr(1);
    }
    result += right;
    return result;
}

// 获取下一个回文数
string nextPalindrome(const string &s) {
    int len = s.length();
    
    // 特殊情况：全是9的数字，如 999 -> 1001
    bool allNine = true;
    for (char c : s) {
        if (c != '9') {
            allNine = false;
            break;
        }
    }
    if (allNine) {
        string result(len + 1, '0');
        result[0] = '1';
        result[len] = '1';
        return result;
    }
    
    // 取左半部分（包含中间字符）
    string left = s.substr(0, (len + 1) / 2);
    
    // 先构造回文数
    string candidate = makePalindrome(left, len);
    
    // 如果构造的数小于等于原数，左半部分加1
    if (candidate <= s) {
        // 左半部分加1
        int carry = 1;
        for (int i = left.length() - 1; i >= 0 && carry; i--) {
            int digit = (left[i] - '0') + carry;
            left[i] = (digit % 10) + '0';
            carry = digit / 10;
        }
        // 如果有进位（如 999 -> 1000），需要特殊处理
        if (carry) {
            // 这种情况应该已经被allNine检测到了，但为了安全还是处理
            left = "1" + string(left.length() - 1, '0');
        }
        // 重新构造
        candidate = makePalindrome(left, len);
    }
    
    return candidate;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int n;
    string d;
    while (cin >> n >> d) {
        string current = d;
        for (int i = 0; i < n; i++) {
            current = nextPalindrome(current);
            cout << current << "\n";
        }
    }
    return 0;
}
```

## 代码说明

### 主要函数

1. **`makePalindrome` 函数** ：
   - 输入：左半部分字符串和数字总长度。
   - 功能：将左半部分反转后复制到右半部分，构造完整的回文数。
   - 注意：根据长度奇偶性调整右半部分。

2. **`nextPalindrome` 函数** ：
   - 输入：当前数字的字符串表示。
   - 功能：返回大于输入数字的最小回文数。
   - 步骤：
     - 检查是否全是 $9$ ，是则返回 $100...001$ 。
     - 取左半部分。
     - 构造候选回文数。
     - 如果候选数不大于原数，左半部分加 $1$ 后重新构造。

3. **`main` 函数** ：
   - 读取多组测试数据。
   - 对每组数据，循环生成 $n$ 个回文数并输出。

### 优化技巧

1. **快速 $\texttt{I/O}$** ：使用 `ios::sync_with_stdio(false)` 和 `cin.tie(nullptr)` 加速输入输出。
2. **避免不必要操作** ：直接构造回文数，而不是逐个检查。
3. **提前处理特殊情况** ：全是 $9$ 的情况单独处理，避免复杂逻辑。

### 注意事项

1. 字符串比较（ `candidate <= s` ）是按字典序比较，对于数字字符串是有效的。
2. 左半部分加 $1$ 时，从右向左处理进位。
3. 当左半部分加 $1$ 后长度可能增加，需要特殊处理（虽然这种情况已被全是 $9$ 的情况覆盖，但为了代码健壮性保留）。

## 总结

本题的关键在于利用回文数的对称性质，通过直接构造法高效生成下一个回文数，而不是逐个检查。主要步骤包括：

1. 将数字分为左右两部分。
2. 用左半部分构造回文数。
3. 如果构造的数不够大，左半部分加 $1$ 后重新构造。
4. 特殊处理全是 $9$ 的情况。

算法时间复杂度为 $O(n \cdot L)$ ，其中 $L$ 是数字长度，完全满足题目要求。通过字符串操作处理大整数，避免了高精度计算的复杂性。

这种"构造而非检查"的思路在解决回文数相关问题时非常有效，可以推广到其他类似问题中。
