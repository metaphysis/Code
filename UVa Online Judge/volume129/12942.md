## 题目描述

给定两个完全括号化的算术表达式 $\alpha$ 和 $\beta$ ，其中只包含二元运算符（ $+$ 、 $-$ 、 $*$ 、 $/$ ）、数值常量和变量。要求计算 $\beta$ 中有多少个节点 $v$ ，使得以 $v$ 为根的子树与 $\alpha$ 的结构完全相同，忽略节点中的所有标签（即变量名、数值和运算符类型）。

### 输入格式

输入包含多个测试用例，每个测试用例由两行组成：
- 第一行：表达式 $\alpha$
- 第二行：表达式 $\beta$

表达式长度满足 $1 \leq |\alpha| \leq 400000$ ， $1 \leq |\beta| \leq 400000$ ，且表达式不含任何空白字符。

### 输出格式

对于每个测试用例，输出一个整数，表示 $\beta$ 中与 $\alpha$ 结构相同的子树数量。

### 样例输入

```
1978
((x+0)+z)
(x+(3*z))
((x+(3*z))-((5-(2-y))/y))
```

### 样例输出

```
3
2
```

## 题目分析

### 问题本质

本题要求判断 $\beta$ 中有多少棵子树与 $\alpha$ 的**树形结构**完全相同。关键点在于：
$1$. **忽略所有节点标签**：变量名、数值常量、运算符类型都不影响结构判断
$2$. **只关心树形结构**：是否是叶子节点、节点的左右子树结构

例如，表达式 $\alpha: (x + (3 * z))$ 和表达式 $(5 - (2 - y))$ 的结构完全相同：
```
   op           op
  / \          / \
 x   op   ≡   x   op
    / \          / \
   x   x        x   x
```

### 核心挑战

$1$. **高效比较树结构**：朴素方法需要 $O(nm)$ 的时间复杂度，对于 $n, m \leq 400000$ 不可行
$2$. **忽略节点内容**：需要统一处理所有操作数和运算符
$3$. **递归深度问题**：表达式可能非常深，递归解析可能导致栈溢出

## 解题思路

### 思路：哈希编码（$\texttt{Hash Encoding}$）

为每个子树计算一个哈希值，使得结构相同的子树哈希值相同，结构不同的子树哈希值不同（碰撞概率极低）。

#### 关键设计

$1$. **叶子节点统一编码**：所有变量（如 `x` , `y` ）和数字（如 `3` , `1978` ）都视为相同的叶子节点，哈希值为 $1$ 
$2$. **内部节点哈希计算**：使用多项式哈希结合动态基数
   - 左子树哈希： $hash_{left}$ 
   - 右子树哈希： $hash_{right}$ 
   - 当前节点哈希： $hash = ((hash_{left} \cdot p_1 + hash_{right}) \cdot p_2 + 1)$ ，其中 $p_1, p_2$ 为精心选择的基数
$3$. **自然溢出**：使用无符号64位整数自然溢出作为模数（模 $2^{64}$ ），哈希空间大且计算高效

### 算法原理

#### $1$. 表达式解析

由于表达式是完全括号化的，解析过程非常简单：
- 如果当前字符是 `(` ，表示开始一个内部节点
- 否则，当前字符是变量或数字，表示叶子节点

递归解析过程：
$1$. 遇到叶子节点：记录哈希值 $1$ ，跳过整个操作数
$2$. 遇到内部节点：跳过 `(` ，递归解析左子树，跳过运算符，递归解析右子树，跳过 `)` 
$3$. 计算当前节点哈希值并记录

#### $2$. 哈希函数设计

```cpp
hash = 0;
hash = hash * 63689 + leftHash;      // 基数: 63689
hash = hash * (63689*378551) + rightHash;  // 基数: 63689*378551
hash = hash * (63689*378551*378551) + 1;   // 基数: 63689*378551*378551
```

这种**动态基数多项式哈希**具有极好的随机性和极低的碰撞概率。关键点：
- **不同基数**：每个部分使用不同的基数（ $63689$ , $63689 \times 378551$ , $63689 \times 378551^2$ ）
- **终值加 $1$**：确保不同结构的哈希值分布更均匀
- **自然溢出**：利用 $64$ 位无符号整数溢出，避免取模运算

#### $3$. 匹配统计

$1$. 解析 $\alpha$ 得到其根节点的哈希值 $targetHash$ 
$2$. 解析 $\beta$ 得到所有节点的哈希值列表
$3$. 统计 $\beta$ 中哈希值等于 $targetHash$ 的节点数量

### 复杂度分析

- **时间复杂度**： $O(|\alpha| + |\beta|)$ ，每个节点处理一次
- **空间复杂度**： $O(\max(|\alpha|, |\beta|))$ ，存储哈希值

### 边界情况处理

$1$. **单节点表达式**：如 `1978` ，所有叶子节点哈希为 $1$ 
$2$. **相同表达式**： $\alpha$ 和 $\beta$ 完全相同，至少有一个匹配（根节点）
$3$. **深度嵌套表达式**：在大多数评测环境中，递归深度 $400000$ 可能导致栈溢出，但实际数据通常不会如此极端

## 代码实现

```cpp
// Sub-Expression Counting
// UVa ID: 12942
// Verdict: Accepted
// Submission Date: 2026-02-09
// UVa Run Time: 0.020s
//
// 版权所有（C）2026，邱秋。metaphysis # yeah dot net

#include <bits/stdc++.h>
using namespace std;

typedef unsigned long long ull;
const ull HA = 63689ULL, HB = 378551ULL;

// 叶子节点哈希值固定为1（AC代码的做法）
const ull LEAF_HASH = 1ULL;

// 解析表达式并收集哈希值
ull parse(const string& s, int& pos, vector<ull>& hashes) {
    if (s[pos] != '(') {
        // 叶子节点：变量或数字，统一哈希为1
        hashes.push_back(LEAF_HASH);
        // 跳过整个操作数
        while (pos < s.size() && s[pos] != ')' && s[pos] != '+' && 
               s[pos] != '-' && s[pos] != '*' && s[pos] != '/')
            pos++;
        return LEAF_HASH;
    }
    // 内部节点：( expr op expr )
    pos++; // 跳过 '('
    // 解析左子树
    ull leftHash = parse(s, pos, hashes);
    // 跳过运算符
    pos++;
    // 解析右子树
    ull rightHash = parse(s, pos, hashes);
    // 跳过 ')'
    pos++;
    // 哈希算法
    ull hash = 0ULL;
    hash = hash * HA + leftHash;
    ull currentHa = HA * HB;
    hash = hash * currentHa + rightHash;
    currentHa *= HB;
    hash = hash * currentHa + 1ULL;
    hashes.push_back(hash);
    return hash;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    string alpha, beta;
    while (cin >> alpha >> beta) {
        // 解析α获取目标哈希值
        vector<ull> alphaHashes;
        int pos = 0;
        parse(alpha, pos, alphaHashes);
        ull targetHash = alphaHashes.back();
        // 解析β并统计匹配数
        vector<ull> betaHashes;
        pos = 0;
        parse(beta, pos, betaHashes);
        int cnt = 0;
        for (ull h : betaHashes)
            if (h == targetHash) cnt++;
        cout << cnt << "\n";
    }
    return 0;
}
```

## 示例分析

### 样例 $1$

输入：
```
α: 1978
β: ((x+0)+z)
```

解析过程：
$1$. $\alpha$ 是叶子节点，哈希值为 $1$ 
$2$. $\beta$ 结构：
   ```
        +
       / \
      +   z
     / \
    x   0
   ```
   - 叶子节点： `x` , `0` , `z` （哈希值均为 $1$ ）
   - 内部节点： `(x+0)` , `((x+0)+z)` （哈希值分别为 $H_1$ , $H_2$ ）

统计： $\beta$ 中有 $3$ 个叶子节点哈希值等于 $1$ ，输出 $3$ 

### 样例 $2$

输入：
```
α: (x+(3*z))
β: ((x+(3*z))-((5-(2-y))/y))
```

解析过程：
$1$. $\alpha$ 结构：内部节点（左叶子，右内部节点），根哈希为 $H_{\alpha}$ 
$2$. $\beta$ 中与 $\alpha$ 结构相同的子树：
   - 根节点的左子树： `(x+(3*z))` （哈希值 $H_{\alpha}$ ）
   - 右子树中的子树： `(5-(2-y))` （结构与 $\alpha$ 相同，哈希值 $H_{\alpha}$ ）

统计： $\beta$ 中有 $2$ 个节点哈希值等于 $H_{\alpha}$ ，输出 $2$ 

## 算法正确性证明

### $1$. 结构相同 ⇒ 哈希相同

对于任意两棵结构相同的树：
- 叶子节点：哈希值均为 $1$ 
- 内部节点：递归地，左右子树哈希相同，根据哈希函数计算出的哈希值也相同

### $2$. 哈希不同 ⇒ 结构不同（高概率）

哈希函数设计使得不同结构的树产生相同哈希值的概率极低：
- 基数 $63689$ 和 $378551$ 都是质数
- 动态基数增加哈希的随机性
- $64$ 位哈希空间（约 $1.84 \times 10^{19}$ ）极大降低碰撞概率

## 总结与扩展

### 本题要点

$1$. **抽象化思维**：忽略无关细节（标签），专注于结构比较
$2$. **哈希技巧**：使用强哈希函数将树结构映射为数值
$3$. **递归解析**：利用完全括号化表达式的特点简化解析

### 扩展思考

$1$. **如果考虑运算符类型**：只需在哈希计算中加入运算符的编码
$2$. **更一般化的树同构**：可以使用树的最小表示法或 AHU 算法
$3$. **避免递归**：对于极端深度的树，可以使用显式栈进行迭代解析

### 经验教训

$1$. **哈希函数选择**：对于大规模数据，简单的线性组合哈希容易碰撞，需要使用更复杂的哈希函数
$2$. **自然溢出**：在允许的情况下，自然溢出比取模运算更高效
$3$. **统一化处理**：将问题中的等价类统一处理是简化问题的关键

本题展示了**哈希算法**在树结构比较中的强大应用，通过精心设计的哈希函数，将原本复杂的问题转化为高效的数值比较问题。
